    E4 管道：运行时和实时事件通道¶

    1. 目的¶

    E4 使边缘运行时和产品窗口边界硬件变得可观察 无需物理相机、条形码或触发硬件即可就绪：

    • WebSocket 运行时通道推送临时检查/设备/上传 通知仪表板，将轮询 REST 预览替换为 实时更新路径，而 REST 仍然是事实来源（ADR-006，设计 15.5/15.6）。
    • 与硬件无关的触发器/条形码/身份接缝提供了 window_strategy: identity 来自经过验证的产品窗口边界 产品身份源，具有用于开发的确定性模拟源 和验收测试。仅时间后备仍然是一种开发模式。
    • 多个检查实例按清单共享只读模型权重 身份，因此每个实例管道不会重新加载相同的工件 （ADR-013 第 3 阶段）。

    2. 范围和非目标¶

    范围内¶

    • 具有 per-(source_id, channel) 单调性的内存运行时事件总线 序列、有界缓冲和缓慢的消费者断开连接。
    • WS /api/v1/ws/runtime 发出设计的经过身份验证的端点 15.6 inspection.started、inspection.completed 的信封、 device.status_changed和upload.changed。
    • 前端接线，以便实时视图刷新事件并协调 在重新连接/序列间隙上休息（设计 16 规则 3）。
    • TriggerSource 协议加上确定性 MockTriggerSource 将经过验证的产品身份注入现有的身份密封窗口 路径；模拟源仅供开发/测试。
    • 由跨实例共享的清单校验和作为键控的模型权重缓存。

    超出范围¶

    • 供应商相机 SDK、真实条形码解码和物理光电眼/PLC 触发器（硬件决策、E6 接受）。
    • 中央 WebSocket (/api/v1/ws/organization) 和 Redis 发布/订阅。
    • 持久的事件重播：总线的设计是短暂的（REST 是权威的）。
    • WebRTC/MJPEG全帧预览；仪表板继续使用 像素的有界 JPEG 预览。
    • 通过 WebSocket 暂停/恢复或相机重新连接命令（REST 命令 保留，设计 15.5）。

    3. 安全不变量¶

    在每个 E4 变更和测试中，以下不变量是强制性的：

    1. WebSocket事件只是暂时的通知； API从不依赖 用于检查执行、耐久性或同步的总线，以及 重新连接的客户端必须先刷新 REST 状态，然后才能信任推送的数据。
    2. 事件发布永远不会阻止检查、持久化或上传 工作人员：总线是非阻塞的，缓冲区是有限的，消费者速度很慢 是断开连接而不是限制发布者。
    3. WebSocket 身份验证使用与 休息；跨源浏览器套接字使用短暂的一次性票据 通过经过身份验证的 REST 发出并作为协商的子协议发送。 令牌和票证永远不会出现在 URL 查询日志中，并且未经身份验证， 已过期，或者在发送任何事件之前重播的票证被拒绝。
    4. 每个(source_id, channel)序列是单调的；差距总是意味着 事件丢失，客户端必须重新获取 REST。重新连接保留 连续性且不表示间隙（设计 14.4.1）。
    5. 仅当每个框架都属于一个产品窗口时，产品窗口才可以释放OK 经验证的身份；身份缺失、身份转换或已确认 多产品框架未能按 NG 关闭窗口（PR-015 F1，不变）。 身份接缝仅提供经过验证的身份；模拟来源是 仅用于开发/测试，切勿将硬件歪曲为生产数据。
    6. 共享模型权重由不可变的清单校验和作为密钥；仅 相同的工件被重用，并且缓存从不共享可变的 实例之间的推理状态。
    7. 仅时间窗口回退显然仍然是一种开发模式，并且是 从未声称为生产产品边界。

    4. 生产启用前所需的决策¶

    • WebSocket代理/防火墙支持和空闲超时配置（设计15.8 开放式问题）。
    • 选定的触发/条形码硬件、信号定时和身份相关性 每个站点的 window_strategy: identity 规则。
    • 已部署硬件上的每个实例模型共享策略（内存预算、 热身行为）。

    5. 交付管道¶

    每个门都可以独立审查。

    E4a：WebSocket 运行时通道¶

    实施

    • 添加一个分配单调序列号的RuntimeEventBus（内存中） 每个 (source_id, channel)，保持有界的每个连接缓冲区，并且 断开落后的消费者而不是阻止发布者。
    • 添加使用现有查看器承载进行身份验证的WS /api/v1/ws/runtime 非浏览器/同源客户端的令牌或会话 cookie，加上 通过经过身份验证的 REST 颁发的短期、一次性票据 (POST /api/v1/ws/runtime/ticket) 并按协商发送 Sec-WebSocket-Protocol 跨域浏览器套接字的值；发出 设计 15.6 信封（event_id、type、schema_version、occurred_at、 source_id、sequence、correlation_id、data）。票已消耗 在接受过程中以原子方式进行，很快就会过期，并且永远不会出现在 URL 中。
    • 发布来自真实运行时转换的事件：检查开始/完成 来自检查循环（包括默认的每帧模式，该模式会发出 在推理之前开始，在持久之后完成匹配 持久性），暂停/恢复和存储故障导致的设备状态变化 转换，并从调度程序工作人员上传更改。
    • 将仪表板实时视图连接到事件源；重新连接或按顺序 间隙 UI 重新获取 REST 状态（现有 ReconnectingWebSocket 合同）。
    • 公开通道计数器（活动连接、按类型发布的事件、 通过经过身份验证的缓慢消费者断开连接、交付失败） GET /api/v1/ws/runtime/stats 端点，以便操作员可以区分 来自失败事件源的空闲仪表板。

    退出标准

    • 测试证明：未经身份验证的套接字被拒绝；信封上装有 具有单调每个源序列的记录字段；有界缓冲区 断开慢速消费者的连接而不阻止发布者（包括 跨线程发布，绝不能在事件循环中引发 QueueFull）； 事件是从实际检查完成时发出的（时间窗口和 默认每帧模式）、暂停/恢复和上传调度程序转换； 门票是一次性的，过期/重播的门票将在任何之前被拒绝 事件已发送；通道计数器是可观察的和确定性的。
    • 前端测试证明了键入事件的实时视图更新以及 在序列间隙后重新获取 REST，不需要预览轮询 为了正确性，WebSocket URL 保留 /api/v1 前缀，以及 跨源连接通过 REST 颁发的票证进行身份验证，无需任何 URL 中的凭据。

    E4b：触发器/条形码/身份接缝¶

    实施

    • 定义一个发出确定性的TriggerSource协议 TriggerEvents（产品标识、可选条形码、时间 单调时钟）和一个由配置驱动的 MockTriggerSource 开发和测试。
    • 将触发身份与捕获的帧相关联，以便现有的 window_strategy: identity 窗口管理器接收 product_identity 每 框架；身份密封窗口保留其故障关闭语义。
    • 保持模拟源的门控，这样它们就永远不会伪装成生产硬件。

    退出标准

    • 测试证明模拟触发器产生确定性身份/条形码 顺序以及身份密封窗口打开、密封、过渡和失败 完全按照现有 PR-015 窗口合同的要求关闭。
    • 测试证明由模拟身份提供的窗口每释放一个 OK 身份并在丢失/转换身份时作为 NG 中止，没有任何 伪造证据。

    E4c：共享模型权重缓存¶

    实施

    • 为加载的 YOLO 权重添加一个进程范围的缓存，该权重由清单键入 校验和；引用同一工件的多个实例共享一个模型。
    • 确保缓存是只读的（没有可变的推理状态）并且 不同的工件永远不会合并。

    退出标准

    • 测试证明两个实例具有相同的清单校验和加载模型 一次和具有不同清单的实例分别加载；一个 缓存未命中/驱逐路径被覆盖，并且不共享可变状态。

    6. 强制测试矩阵¶

    面积 所需案例
    WebSocket 授权拒绝（承载/会话/票证）；信封字段；单调的每源序列；有界缓冲区 + 慢速消费者断开连接，无需发布者阻塞（包括跨线程 QueueFull）；一次性/过期门票被拒绝；间隙语义
    事件来源 检查开始+完成（时间窗口和默认每帧模式）；暂停/恢复设备状态；从调度程序上传更改
    身份缝 模拟触发确定性序列；身份窗口打开/密封/转换/失败关闭；每个身份一个 OK；没有捏造证据
    共享权重 相同清单重用（一次加载）；不同的表现是分开的；只读共享
    前端 事件驱动的实时刷新；间隙/重新连接时的 REST 重新获取
    可观察性 可观察的 WebSocket 连接/事件计数；没有 URL 标记

    7. 合并和释放门¶

    • 通过类型化接口进行重点更改，并且没有非结构化字典 公共边界。
    • 对每个更改的安全不变量进行回归测试。
    • 通过强制性质量命令：ruff check/format、mypy、pytest、 mkdocs build --strict、pnpm -r build/lint/test、边缘网络 e2e。
    • 审查 WebSocket 事件从不阻止检查或上传的证据，以及 模拟触发源不能伪装成生产硬件。
