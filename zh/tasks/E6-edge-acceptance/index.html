    E6 管道：边缘验收¶

    1. 目的¶

    E6 为特定客户建立边缘运行时的测量适应性 生产线、型号/规则发布、相机设置和操作程序。里程碑 E1-E4 合并。 E5 在开放 PR #24 中实现，未合并。 E6是 Edge 交付工作和最后一个 Edge 之后的验收门 中央工作开始前的生产候选门。满 在当前环境下无法完成验收，因为它需要 真实的客户站点、选定的硬件和看不见的客户数据。 E6是 因此分为两个阶段：

    • E6-prep：不需要真实环境并且可以构建的可交付成果， 已测试，现已合并。这些是验收测试矩阵（第 6 节）、 本地自动化运行程序（E6b）、验收报告模板（E6c）和 现场执行计划及其运行手册/清单更新 (E6d)。
    • 现场验收：执行验收的单独门控阶段 矩阵、弹性和浸泡证据以及真实硬件和看不见的指标 客户数据 (E6d)。

    如果没有真实的硬件、未见过的客户数据以及 执行现场恢复并浸泡证据。没有伪造的通过结果 曾经记录过：缺失的真实环境输入被报告为NOT_EXECUTED， 从来不作为通行证。本文档是 E6 的真实来源，并取代任何 非正式验收索赔。

    2. 范围和非目标¶

    范围内¶

    • E6a：验收测试矩阵（第 6 节），涵盖行为、弹性、 性能和稳定性断言，并对内容进行诚实分类 每个项目都需要。
    • E6b：scripts/edge-acceptance-run.py，本地自动化运行器 执行每个本地可自动化的矩阵项并发出机器可读的 证据明显；现场项目作为 NOT_EXECUTED 发出 记录所需的环境。
    • E6c：边缘验收报告模板 docs/design/28-edge-acceptance-report.md 包含版本/环境、矩阵 结果、指标、证据链接、偏差、风险和签核字段。
    • E6d：Runbook 15: Edge Acceptance Execution中的现场验收执行计划（门控阶段， 此处记录但未在此环境中执行）。

    超出范围¶

    • 进行现场验收、获取客户数据或生成最终结果 指标：基于硬件和看不见的客户数据（E6d）。
    • 中央服务器（摄取 API、PostgreSQL、对象存储、手动审核）： 在边缘门通过之前，未实施并故意超出范围。
    • 声称通用的准确性保证或采用未经测量的指标 证据：仅包含分子、分母和置信度的测量结果 报告治疗情况（设计 22.7，合同 10）。
    • 使用验收数据进行模型训练、阈值调整或规则选择 （设计 26.4）。

    3. 安全不变量¶

    在每个 E6 更改和测试中，以下不变量是强制性的：

    1. 当检验证据不完整、无效或 无法验证；不完整的证据映射到NG或采用的 根据政策的不确定/手动路径（设计 11、22.6）。
    2. 缺少真实环境输入（硬件、看不见的客户数据、中央 server) 被报告为 NOT_EXECUTED 以及所需的环境 记录，从来不作为通行证，也不作为OK。
    3. 从未声称 100% 准确；仅测量回忆和 报告假阴性结果（设计 22.7，合同 10）。
    4. 验收数据从不用于训练、阈值调整、检查点 选择，或验收运行前的规则选择（设计26.4）。
    5. 原始人工智能决策在人工审核过程中保持不变； 更正结果单独存储，绝不会覆盖原始决定 （设计 24，合同 10 §5）。
    6. 证据是不可变的或受校验和保护并通过 检查标识符（设计 26.6）。
    7. 在代表性恢复完成之前，备份才被视为可操作。 成功了（设计20.10）。
    8. 现场执行绝不会删除或更改证据、待上传或 可追溯性所需的数据库记录（设计 20.11）。

    4. 现场验收前所需的决定¶

    以下决定仍然悬而未决，并记录在接受中 报告直至客户和供应商同意为止。它们不是在这里发明的 （设计22.13、26.11）：

    • 客户 TLS 终止选择：边缘服务本地 TLS 与现有的 工厂反向代理、证书来源和轮换所有者（设计 20.6，合同 08)。
    • 与备份目标、计划、保留和恢复 RPO/RTO 达成一致 客户；确切的频率是接受决定（设计20.10）。
    • 硬件设备映射：GigE Vision / GenICam相机系列，GenTL生产商， NIC/交换机路径和可选的巨型帧配置，或 USB UVC 驱动程序和 设备路径；加上 GPU 设备和硬件/软件触发接口 客户现场要求（设计 20.2、20.13）。
    • 接受阈值：主要 NG 召回目标、允许的漏报和 升级/重新测试政策、误报和人工审核预期， 以及UNCERTAIN和的统计置信方法和处理 不确定的基本事实（设计 26.3）。
    • 条形码标准以及对不可读和未知代码的预期处理 （设计 22.13、26.11）。
    • 传送带速度、预期吞吐量、延迟预算、占空比和 长时间运行的测试持续时间（设计 22.9、26.11）。
    • 事实真相所有者、裁决者、证人、签名者和重新测试 责任（设计 26.3、26.11）。

    5. 交付管道¶

    每个门都可以独立审查。

    E6a：验收测试矩阵¶

    完整的强制矩阵位于第 6 节。它是 E6 必须展示的真相、什么是本地可自动化的以及什么是 由硬件、客户数据或中央服务器控制。

    退出标准

    • 设计 26.5 和 22.8 所需的每个场景都带有分类 以及本地跑步者报道答案；没有需要的场景是默默的 当需要真实环境时自动本地化。

    E6b：本地自动化运行器¶

    实施

    • scripts/edge-acceptance-run.py 锁定应用程序、产品型号、 组件模型、规则和配置工件通过提供 --artifact，加上通过提供的验收清单 --acceptance-manifest，执行前。缺少必需的工件使得 运行不完整且非零，而不是成功。
    • 运行程序为每个可运行对象执行显式的目标 pytest 断言 行为矩阵行，记录其证据清单中的每个矩阵行，以及 记录每个执行行的断言和锁定工件校验和。
    • 对于每个矩阵项目，发出机器可读的证据清单条目 包含：矩阵ID、场景、状态、不需要时所需的环境 已执行、已执行断言、证据链接、时间戳和工件 校验和。
    • 切勿为所需环境不可用的项目发出 PASS 或 不支持本地执行；将其记录为 NOT_EXECUTED 或 INCOMPLETE，缺少输入或限制（硬件、客户数据、 中央服务器或不受支持的本地功能）。
    • 场景将本地可自动化的行为断言与 门控接受度量，记录执行的行为断言和 接受项本身为NOT_EXECUTED。

    退出标准

    • 运行程序针对当前存储库完成，无需外部 硬件、客户数据或中央服务，并记录每个矩阵行。 硬件/客户/中央项目和不可用或不受支持的本地项目 是 NOT_EXECUTED 或 INCOMPLETE，而不是 PASS。
    • 测试涵盖跑步者的明显排放；输入清单模式并 版本化。

    E6c：边缘验收报告模板¶

    实施

    • 添加 docs/design/28-edge-acceptance-report.md 以及以下字段：
    • 发布和环境：应用程序、模型、规则和配置 版本和校验和、硬件、摄像头、网络和设备 ID；
    • 矩阵结果：每个矩阵 ID 一行，带有状态和证据链接；
    • 指标：NG召回率、假阴性率、假阳性率、 每个组件召回、每个产品召回、产品检测成功、 ROI 生成成功、条码读取成功、平均和 P95 延迟、 吞吐量、按连接性分段的上传延迟、审核率和 稳定性，每个都有分子、分母和置信度处理 （设计26.7，合同10）；
    • 证据链接、偏差、残余风险以及角色和签名 残余风险批准（设计 26.8 步骤 10）。
    • 任何没有客户数据的指标都记录为 NOT_MEASURED，而不是记录为 零、占位符或通行证。

    退出标准

    • MkDocs严格通过新的设计文档；模板是 从运行手册/清单更新和此任务交叉引用。

    E6d：现场验收执行计划¶

    这是门控阶段；它无法在当前环境中运行。的 程序遵循设计 26.8：

    1. 批准验收协议、领域、角色、目标设定方法以及 停止条件；将第 4 节的决定记录为已解决或明确记录 打开。
    2. 验证相机安装、对焦、曝光、照明、边缘硬件、时间 同步、磁盘容量和网络设置；记录设备 映射。
    3. 锁定应用程序/模型/规则/配置工件并对其进行校验和 验收清单。
    4. 运行校准和烟雾案例，而不使用验收结果进行调整 锁定的候选人。
    5. 在见证下执行随机或生产代表性案件， 记录所有证据。
    6. 练习离线、恢复、重启和持续时间（浸泡）场景。
    7. 核对产品数量、重复和缺失检查、介质、日志、 并上传收据。
    8. 只审理预先宣判的未决案件，不改变原案 记录。
    9. 生成分段指标并将其与联合批准的指标进行比较 协议。
    10. 记录批准、限制批准、补救/重新测试或拒绝 签名和剩余风险。

    如果发现释放阻塞问题，则保留运行；修复创造了 新的候选版本和受控的重新运行，并且历史故障不是 被覆盖（设计26.8）。

    退出标准

    • Runbook 15: Edge Acceptance Execution 和 edge acceptance report template 可以从该计划中执行；没有E6-prep门被E6d阻挡，并且E6是 直到 E6d 出示已执行的现场证据后才宣布完成。

    6. 强制测试矩阵¶

    列语义：分类是验收运行最严格的环境 需要 (automated-local、hardware-required、customer-data-required、 central-required）。当运行程序执行时，本地运行程序覆盖率为 yes 矩阵行的显式目标 pytest 断言或 Docker 重启检查； 证据清单记录了确切的断言，因此跳过或失败 断言永远不会产生PASS。否则它是 no 并且跑步者发出 NOT_EXECUTED 具有所需的环境。断电，真正的条码解码， 真实相机断开连接、GPU/加速器故障、长时间浸泡以及任何 客户数据场景永远不会automated-local。

    身份证 场景 所需的断言/行为 分类 本地跑者报道 笔记
    E6-A1 产品类型（每种适用） 正确的产品映射、适用的版本化规则、组件级结果；按类型分段的指标 需要客户数据 没有 指标和验收证据需要看不见的客户数据
    E6-A2 每个缺失的组件 NG或采用不确定/手动路径，纠正缺失原因和证据 需要客户数据 没有 在客户队伍中上演案例；阶段性缺陷与自然发生的缺陷分别报告 (22.10)
    E6-A3 缺少手册 缺失手册原因及溯源 需要客户数据 没有 文件存在情况 (26.5)
    E6-A4 条码故障 错误、未知或不可读的产品映射下没有未经验证的 OK 所需硬件 没有 需要真正的条形码解码（22.5）；本地模拟不是验收证据
    E6-A5 产品定位转变 可用的 ROI 或明确的 NG/不确定/错误；没有固定坐标假设 需要客户数据 没有 需要在批准的操作范围内进行看不见的捕获
    E6-A6 正常生产变化 代表领域的分段质量和延迟结果 需要客户数据 没有 代表性生产流程
    E6-A7 连续OK产品 每件产品一次正确检验；没有重复或帧混合 需要客户数据 没有 操作流程指标需要客户生产序列
    E6-A8 连续NG产品 每件产品一次正确检验并说明理由；持续审核并上传 需要客户数据 没有 操作流程指标需要客户生产序列
    E6-A9 混合产品类型 每个物理产品的正确版本规则 需要客户数据 没有 需要客户混合产品生产序列
    E6-A10 没有产品 明确无产品处理或不打开窗口；从来都不是捏造的好吧 自动化本地 是的 确定性无产品框架 (22.6)
    E6-A11 多种产品 窗口完整性：明确的 NG 或错误，而不是混合证据 自动化本地 是的 多产品夹具 (22.6)
    E6-A12 离线操作 地方检查、证据和持久的队列在没有中央的情况下继续进行自动化本地 是的 中央独立（ADR-001，22.8）
    E6-A13 网络中断 地方决定继续进行；队列仍然存在；无数据丢失 自动化本地 是的 阻塞端点模拟
    E6-A14 反复网络断开（抖动） 无中心往返；队列仍然存在；抖动回退和断路器限制流量；无数据丢失或重复上传；积压排水 自动化本地 是的 振荡连接 (22.8)
    E6-A15 中央停电 带抖动的退避；没有决策障碍 自动化本地 是的 边缘行为；一旦存在中央，就需要端到端的中央对账
    E6-A16 重复上传幂等性 每个幂等密钥进行一次集中检查和一致收据 中央要求 没有 针对接收器的边缘重放是本地执行的；验证中央收据需要尚未实现的中央服务器
    E6-A17 应用程序重启 不得捏造或重复；显式处理的不完整窗口；状态恢复 自动化本地 是的 在捕获、决策和上传状态期间重新启动
    E6-A18 断电 数据库和队列恢复；不明确的窗口未标记为“OK”；无证据丢失 所需硬件 没有 在选定状态下杀死主机/进程；需要硬件环境(22.8)
    E6-A19 磁盘已满/压力 警报、安全清理、在失去可追溯性之前暂停； NG 证据依然存在 自动化本地 是的 配额或已填满的测试量 (22.8)

    7. 强制性证据要求¶

    每个执行的测试都会保留（设计 26.6，合同 10 §6）：

    • 检查结果和原因代码。
    • 原始和选定的图像证据，加上注释/ROI 证据 配置。
    • 事实真相和裁决来源。
    • 应用程序、模型、规则、产品配置和审查策略版本 和校验和。
    • 源和接收时间戳以及设备标识符。
    • 条形码和产品映射结果。
    • 相关结构化日志、运行状况事件和阶段时间安排。
    • 上传任务和中央收据/校验和，其中同步在范围内。
    • 审阅者结果，其中人工验证是程序的一部分。

    证据是不可变的或受校验和保护并通过检查链接 标识符。 NOT_EXECUTED条目记录所需的环境而不是 证据。报告的指标包括分子、分母、排除和 不确定的计数、有意义的置信区间以及细分 发布版本（设计26.7）。

    8. 合并和释放门¶

    • 通过类型化接口和类型化、版本化的 Pydantic 进行重点更改 体现出来。
    • 对每个更改的安全不变量进行回归测试。
    • 通过强制性质量命令：ruff check、ruff format --check、 mypy、pytest、mkdocs build --strict、pnpm -r build/lint/test 和 边缘网络 e2e。
    • 现场有证据后才出具边缘验收报告；一个 模板或仅准备状态永远不会被视为已接受。
    • 在代表性恢复完成之前，备份不被视为可操作 成功了（设计20.10）。
