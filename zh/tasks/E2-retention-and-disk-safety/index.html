    E2 管道：保留和磁盘安全¶

    1. 目的¶

    在不削弱边缘保留和磁盘安全里程碑的情况下 边缘优先、故障安全检查合同。这条管道为当地提供了证据 删除受控、可审计、收据门控且在磁盘压力下安全。

    默认的生产安全配置是不删除。清理可以运行 仅在配置批准的保留策略后。缺少政策价值， 未知的上传状态、缺少收据、缺少存储测量，或者 完整性错误必须保护证据而不是删除证据。

    2. 范围和非目标¶

    范围内¶

    • 持久媒体保留状态和清理审核字段。
    • 具有进程间租约的收据门控保留清理工作人员 击剑令牌。
    • 警告、严重和停止存储压力状态。
    • 启动完整性扫描和隔离/故障报告。
    • 类型化 Edge API、生成的 OpenAPI/TypeScript 合约、仪表板状态、 上述的操作指标、运行手册和故障注入测试。

    超出范围¶

    • 中央摄取、中央对象存储、中央手动审查和远程 包分发。
    • 客户特定的保留期限、合法保留政策、安全擦除 方法、站点磁盘大小和线路控制集成。这些都是需要的 可以在生产中启用删除或停止模式之前的输入。
    • 带宽限制、断路和可恢复媒体上传 (E3)。

    3. 安全不变量¶

    在每个 E2 变更和测试中，以下不变量是强制性的：

    1. 如果任何所需的上传任务被执行，清理工作人员绝不能删除媒体 PENDING、IN_PROGRESS、RETRY_WAIT、PERMANENT_FAILURE、CANCELLED 或 否则缺少经过验证的收据。
    2. 媒体收据仅在包含预期幂等性时才被验证 密钥、对象身份、校验和、字节大小和中心对象标识符。
    3. 清理绝不能删除受配置保留、接受的媒体 锁、人工审查锁、完整性错误、生命周期未知或未过期 保留期限。
    4. 清理必须将工件永久标记为在租约/围栏下删除 取消链接之前的令牌。它可能仅在之后标记工件 PURGED 预期文件不存在；失败的取消链接必须保持可重试且可观察。
    5. 过时的清理工作人员不得覆盖新租约的结果 持有者。租约到期必须使放弃的删除声明可恢复。
    6. 磁盘压力清理可能会优先考虑符合条件的数据，但绝不能删除 待上传 NG 证据以继续静默检查。
    7. 在停止压力下，如果不能持久地进行完整的可审计检查 书面的，运行时必须停止接受新产品或做出结果 故障安全。它绝不能返回未记录的OK。
    8. 完整性扫描失败、只读存储、磁盘满写入、损坏 数据库状态，缺少强制证据必然会产生显式错误 状态/警报。它们不得被视为健康的存储。
    9. SQLite元数据并不授权删除任意文件系统 路径。每个取消链接都必须限制在配置的输出根和 工件的可信检查包。
    10. 保留仅限于本地，并且不得要求中央可达 检查时间。中央不可用可以保护证据并可能增加 队列；当保留保留时，它不得阻止本地持久检查。

    4. 生产启用前所需的决策¶

    E2 可能会在禁用删除的情况下实施，但这些决定已发布 用于在客户站点启用清理或存储停止行为的拦截器：

    • 每个KEY_FRAME、ANNOTATED_FRAME的保留期限和配额， PRODUCT_ROI、NG_CLIP、ROLLING_VIDEO、日志和元数据。
    • 磁盘卷容量、索引节点容量、每日媒体量、最大停机时间、 所需的保护储备和警告/严重/停止阈值。
    • NG 媒体、滚动/完整视频和选定的 OK 媒体是否为强制。
    • 法律、接受和人工审查保留行为；清除审计保留； 静态加密、备份和安全删除义务。
    • 停止模式线路行为：暂停/触发拒绝、操作员确认、 恢复权限和上游设备信号。
    • 真正的集中收据部署和媒体绑定保证。测试水槽或 未部署的中央端点没有删除数据的生产授权。

    5. 交付管道¶

    每个门都可以独立审查。稍后的门不得开始，直到所有 其前身通过的接受标准。

    E2a：持久保留状态和资格¶

    实施

    • 在0006_upload_task_size之后添加迁移，用于保留和删除 协调领域。这至少包括有效的 retention_eligible_at，保留状态，删除声明/租赁/防护字段， 删除时间戳、清除时间戳/原因和上次删除错误。
    • 仅在外部可见元数据的情况下扩展类型化域/API 媒体模型 是必需的。重新生成 OpenAPI 和 TypeScript 类型以进行公共更改。
    • 添加存储库方法来计算收据门控资格，原子声明 有界清理批次，完成清除，并记录可重试删除 失败。所有比较和设置转换都需要当前的防护令牌。
    • 定义事实来源：文件系统保存媒体字节； SQLite 持有 元数据和删除状态。 PURGED 行仍然是审计逻辑删除；是的 未随文件一起删除。

    退出标准

    • 新的和迁移的 SQLite 数据库成功打开并保留所有 现有发件箱/媒体数据。
    • 没有经过验证的未过期收据SYNCED，资格不会退回任何物品 检查、已过的保留期限和允许的生命周期。
    • 资格不包括所有待处理、重试、进行中、失败、取消、 持有、锁定、未知、损坏或已清除的项目。
    • 两个并发存储库实例不能声明相同的媒体；陈旧的 声明不能将较新的声明标记为已清除或失败。
    • 公共架构更改已提交 OpenAPI 并生成 TypeScript 工件和合同漂移测试都通过了。

    E2b：清理工作人员和审核删除¶

    实施

    • 添加一个受监督的进程内清理工作人员，与上传分开 调度程序，具有进程级生命周期和进程间 SQLite 租约。
    • 首先声明，然后解析并重新验证可信媒体路径，取消链接， 验证缺席情况，并使用时间戳/原因/回收字节最终确定 PURGED。
    • 将丢失的文件视为完整性错误，而不是成功的保留删除。
    • 记录删除失败，释放/恢复过期的声明，暴露工人 运行状况和清理指标，并发出没有路径的稳定事件/警报， 凭证或日志中的图像字节。
    • 保持清理禁用状态，除非保留策略明确有效并启用。

    退出标准

    • 符合条件的上传工件将被删除一次；它的行变成 可审核的PURGED逻辑删除和媒体服务返回410 MEDIA_PURGED。
    • 删除前丢失的文件会导致完整性警报/故障，但不会 谎称清除成功。
    • 权限错误、只读文件系统、取消链接失败、之后进程崩溃 声明，并在取消链接后/最终确定前崩溃恢复而不删除 第二个文件或丢失审核跟踪。
    • 并发工作人员和工作人员重新启动演示了租约恢复和 击剑；没有测试可能只依赖于进程内锁。
    • 即使在警告下，禁用或不完整的策略也会产生零取消链接调用 或临界磁盘压力。

    E2c：存储压力和故障安全运行时行为¶

    实施

    • 添加存储卷、警告/严重/停止阈值的类型化配置， 清理间隔/批次/租赁，并启用保留策略。验证严格 排序：stop < critical < warning，有效的百分比/字节/索引节点范围， 并且没有破坏性的默认值。
    • 测量实际持久输出卷上的可用字节和索引节点。发布 具有观察值、阈值、时间戳、清理的稳定存储状态 通过设备状态保持健康和稳定的警报代码。
    • 发出警告时，请求符合条件的清理和警报。临界时，仅抑制 明确可选的捕获；元数据和所需的 NG 证据保留 受保护。停止时，强制耐用时暂停/拒绝新产品摄入 无法保证持久性。
    • 将强制输出/持久性故障转换为可控制的存储故障 检查入场。飞行前检查还不够；写入时间 ENOSPC、EROFS 和 I/O 故障也必须是故障安全的。
    • 删除仪表板拥有的固定磁盘阈值；渲染服务器提供的策略 相反，状态和警报。

    退出标准

    • 边界测试证明了警告、严重和停止时的准确转换行为 字节和索引节点的阈值，包括恢复/滞后策略。
    • 警告仅加速符合条件的清理。关键保留所需 NG 证据并仅禁用配置的可选捕获。停止阻止新的 检查是否产生未记录的OK。
    • 模拟ENOSPC、EROFS、写入失败、数据库写入失败结果 处于显式存储/未就绪状态或故障安全检查结果；不 异常路径发出业务OK。
    • 完整或只读磁盘无法使服务进行广告 inspection_ready=true 当强制持久化不可用时。
    • API、仪表板和日志显示一种一致的服务器权威状态。

    E2d：启动完整性、恢复和运营验收¶

    实施

    • 扩展启动协调以识别丢失的引用文件， 文件大小错误、校验和不匹配（全面扫描或显式配置 有界采样）、不安全路径、孤立的最终捆绑包/媒体以及废弃的 删除声明。
    • 定义并实施持久的完整性故障/隔离状态。不 默默地重新导入、覆盖或删除不明确的证据。
    • 在声明存储就绪之前运行适当的 SQLite 完整性检查。 数据库损坏必须进入存储未就绪模式并需要记录 恢复而不是自动替换。
    • 更新低磁盘、上传积压、数据库恢复和同步 包含 E2 警报代码、分类、清理限制、安全恢复的操作手册 检查和证据保存要求。

    退出标准

    • 启动故障注入测试涵盖过时的暂存、放弃的删除声明、 文件丢失、大小不匹配、校验和不匹配、孤立包、不安全路径、 数据库损坏信号，并在清理期间重新启动。
    • 当所需的证据不能持久时，不允许完整性错误OK 记录；不明确的媒体会被隔离/保护，永远不会被悄悄删除。
    • 受控离线浸泡测试运行并发检查持久性， 上传重试、清理、API 读取和重新启动，无需重复上传任务， 过早删除、SQLite 锁定失败或无法审核的检查结果。
    • 运行手册仅使用记录的状态/警报即可执行，并且不会告诉 操作员手动删除受保护的证据。

    6. 强制测试矩阵¶

    如果没有对每一行进行自动化测试，则不会接受该实现。

    面积 所需案例
    资格 没有收据；收据格式错误；没有中央对象 ID 的媒体； PENDING； IN_PROGRESS； RETRY_WAIT；永久性故障；取消;握住;未过期；已验证收据已过期
    租赁/围栏 并发工人；陈旧的租赁完成；索赔后崩溃；租约到期/收回；重复的清理调用
    文件系统 丢失文件；遍历/绝对/符号链接转义；尺寸错误；校验和不匹配；没有权限;只读文件系统； ENOSPC；取消链接崩溃边界
    压力 警告/严重/停止转换；字节和索引节点阈值；恢复;可选媒体抑制；强制 NG 保存；新品停止入场
    和解 分期残留物；孤儿最终捆绑包；数据库/介质不匹配；陈旧的删除状态； SQLite 信号损坏；重启恢复
    合同/用户界面 架构默认值； OpenAPI/TypeScript 漂移；已验证状态； PURGED媒体410；服务器权威仪表板警报
    浸泡 并发检查、上传、清理、仪表板读取、重启和长时间离线积压

    7. 合并和释放门¶

    代码合并门¶

    每个 E2 拉取请求必须具有：

    • 通过测试升级和降级行为进行集中迁移。
    • 类型化接口；没有使用非结构化字典作为保留域 界面。
    • 对每个更改的安全不变量进行回归测试。
    • 公共架构更改时的当前 OpenAPI/TypeScript 工件。
    • 通过强制性质量命令和相关故障注入测试。
    • 审查证据表明更改不能删除待定、未经验证、保留或 未过期的证据。

    E2完成门¶

    仅当所有 E2a-E2d 退出标准均通过且所有 以下是正确的：

    1. 任何自动化测试都不会导致受保护的证据被删除。
    2. 未经批准的政策，清理仍处于禁用状态且非破坏性。
    3. 收据门控删除、删除审计、租约隔离和重启恢复 针对 SQLite 和文件系统进行了演示。
    4. 磁盘压力和实际写入失败导致可见的故障安全模式， 绝不是未记录的OK。
    5. 启动完整性故障是可见的、受保护的并且可以通过以下方式恢复： 形成文件的程序。
    6. API/仪表板状态、日志、指标和运行手册在存储模式上达成一致。
    7. 第 4 节中的客户/站点决策应在之前记录并批准 在生产中启用删除或停止模式。
