    PR-008 Review: FastAPI Local API, SQLite Index, Runtime Hardening, and Test Coverage¶

    更正 (AUDIT-001)。 PR 中的“100% 测试覆盖率”声明 描述没有被复制。测量边缘 Python 语句覆盖率 合并结果约为 99.5% (pytest-cov)；未覆盖的线条 是查看者会话/无令牌分支、派生图像和统计信息 后备、验证空工作分支和无法访问的 IntegrityError 处理程序。将覆盖率数字视为过时的测量工件，而不是 保证，并在提出索赔时记录准确的命令/输出。

    范围¶

    dev -> main PR #8 (feat(edge): FastAPI local API, SQLite index, runtime hardening, and test coverage) 的代码审查。 PR 连线边缘 仪表板到真实后端（assemblyvision serve、/api/v1），添加 SQLite 具有 Alembic 迁移和幂等 CLI 输出协调的索引，适用 PR-003 运行时强化，并扩展了 Python 覆盖范围。

    本文件记录了调查结果、建议的解决方案和验收标准 对于合并之前必须修复的项目以及非阻塞后续操作 工作。

    Merge Decision¶

    在下面的 F1-F14 解决之前不要合并。 GitHub CI、CodeQL 和本地质量门都通过了，但有几个关键的 当前测试套件不涵盖缺陷和合同违规行为。

    C1-C4 是有条件的生产持久性要求，而不是阻碍 显式限制的只读 M1 索引。如果此 PR 被阻止，他们就会成为阻碍者 被描述或用作权威的生产持久/上传子系统。

    解决状态¶

    本次审查中的所有发现均已在 dev 上得到修复和验证：

    • F1-F14（阻塞）已解决。每个提交都进行了回归测试；的 全套通行证和边缘 Python 覆盖率通过以下方式测量和记录 pytest-cov（合并结果的语句覆盖率约为 99.5%；请参阅 上面的更正说明）。
    • C1-C4（条件生产持久性）针对 M1：SQLite 是 记录为具有重建等效测试的可重建读取投影， 迁移头验证、重复子项拒绝和隔离 崩溃左侧暂存包。
    • P2 项目已解决：未知 /api 路径返回问题 404，请求 ID 传播，媒体流受到有效的 416 问题的限制， verify --expected 禁用文件名回退并拒绝重复 身份、推理元数据按每个阶段的可追溯性、规则进行分类 身份无法使用不同的内容重新激活，并且快速入门/ 上下文文档与实现的 M1 边界相匹配。
    • 剩余路线图范围（上传队列调度程序、WebSocket 通道、摄像头/ 条形码适配器、时间聚合、Docker 打包、权威 SQLite 持久化/发件箱）被记录为下一个里程碑，并且不 阻止此 PR。

    立即封锁结果¶

    F1。在暂存路径下发布的媒体记录，后来更名为“离开”¶

    问题： OutputWriter.save 将媒体写入随机 .staging-... 目录，然后将该目录重命名为检查 ID，但是 persisted relative_path 源自暂存目录名称，并且是 重命名后就再也没有更新过。每一条媒体记录均由硬核制作 因此，作者指出了一条不再存在的路径。

    地点： - apps/edge-service/src/assemblyvision_edge/output/writer.py:114（暂存目录） - apps/edge-service/src/assemblyvision_edge/output/writer.py:130（重命名） - apps/edge-service/src/assemblyvision_edge/output/writer.py:151 (relative = f"{inspection_dir.name}/{name}")

    影响： assemblyvision inspect之后，最终文件存在于 <output>/<inspection_id>/key_frame.jpg同时记录引用 <output>/.staging-.../key_frame.jpg。协调导入无效路径 GET /api/v1/media/{id}/content 为每个生成的图像返回 404。 本地重现：持久路径不存在，而最终文件存在。

    测试间隙： apps/edge-service/tests/test_output_writer.py:60-78 和 apps/edge-service/tests/test_output_writer_extended.py断言物理 文件和校验和，但从未解析 output_root / media.relative_path。

    建议的解决方案： 从稳定版构建最终的 relative_path 文件仍写入暂存目录下时检查 ID。通行证 最终相对目录名单独到_save_image；不要重写 出版后的记录，因为这需要重写 原子目录重命名后的inspection.json。添加一个往返测试 通过存储库和媒体保存媒体、协调和提供内容 端点。

    验收标准： - media.relative_path 解析为 output_root 下的现有文件 writer.save制作的各种媒体。 - 测试验证保存后是否存在 output_root / media["relative_path"] reconcile_output_root 之后。 - API 测试验证 GET /api/v1/media/{id}/content 返回 a 的字节 新鲜生产的检验。

    F2。媒体内容端点允许目录遍历和绝对路径¶

    问题： relative_path 是从 inspection.json 导入的，没有 验证并通过加入 settings.output_root / media.relative_path 提供服务 无需解决和检查遏制。一个 inspection.json 包含 ../secret.txt 或在协调过程中接受绝对路径及其 内容在媒体根之外提供。调用者控制的 MIME 类型可以 还会导致提供活动的浏览器内容。

    Location: - packages/python/domain/src/assemblyvision_domain/models.py:136-145 - apps/edge-service/src/assemblyvision_edge/persistence/reconcile.py:30-40 - apps/edge-service/src/assemblyvision_edge/api/routers/media.py:49-60

    Violation: docs/design/12-local-storage-and-retention.md:32 (paths are generated by trusted code and cannot contain caller-supplied traversal segments), docs/design/14-data-model-and-database.md:429,511-515 (paths must be relative to the configured media root), docs/contracts/05-data-api-and-versioning-contracts.md:75-82 (API must not expose filesystem data).

    Proposed solution: - Reject absolute and traversal paths at import time (reconciliation and any future ingestion path). - Resolve every served path and require candidate.is_relative_to(output_root.resolve()) before reading. - Do not trust the persisted MIME type; use a serve-time allowlist.

    Acceptance criteria: - Reconciliation skips (and logs) any media record whose path is absolute or escapes output_root; the inspection record is not partially imported. - GET /api/v1/media/{id}/content returns 404 for any non-contained path. - Tests with crafted reconciled metadata prove ../, absolute paths, and symlink escapes cannot be read. - Response Content-Type is derived from a media-kind/extension allowlist, or a validated persisted value; arbitrary persisted MIME values are rejected.

    F3。未经身份验证的带有通配符 CORS 的本地 API 会暴露特权操作¶

    Problem: No route has an authentication or authorization dependency, and the app enables allow_origins=["*"] with all methods and headers. Any process or browser able to reach the host can pause/resume inspection, reconnect the camera, retry uploads, and read history, configuration, logs, and media. The wildcard CORS lets arbitrary websites issue cross-origin requests to the local API. paused_by is therefore hardcoded to "operator", creating false attribution.

    Location: - apps/edge-service/src/assemblyvision_edge/api/app.py:81-90 (CORS) - apps/edge-service/src/assemblyvision_edge/api/app.py:95-107 (no auth deps) - apps/edge-service/src/assemblyvision_edge/api/routers/inspection.py:48-81 - apps/edge-service/src/assemblyvision_edge/api/routers/camera.py:23-29 - apps/edge-service/src/assemblyvision_edge/api/routers/uploads.py:53-64 - apps/edge-service/src/assemblyvision_edge/api/state.py:60-64

    Violation: docs/design/15-rest-api-and-events.md:13-18 (mutating routes require operator/edge_admin; read-only health is deliberately limited; do not treat localhost as authentication), docs/design/16-edge-dashboard.md:137-139, docs/contracts/08-security-permissions-and-audit.md:11-16.

    Proposed solution: - Adopt and document an offline-capable edge session/principal design defining credential issuance, validation, expiry, CSRF protection, and viewer/operator/ edge-admin authorization. Enforce it on every route except /health/live. - For read-only M1, remove unsupported mutation routes and their UI controls rather than exposing unauthenticated placeholders. If mutations remain, they require the documented operator/admin role and actor attribution. - Disable CORS by default (same-origin static deployment) and configure an explicit development-origin allowlist (or an anchored localhost regex) instead of *. - Record the acting principal (real user or session) in paused_by and audit mutations.

    Acceptance criteria: - The selected edge-session contract is recorded in the relevant design/ADR; loopback binding and CORS are not treated as authentication. - Every read route except the deliberately minimal /health/live returns 401/403 without the defined viewer credential. - Unsupported M1 mutations return 404/405 and have no corresponding UI control; any retained mutation returns 401/403 without its required role. - A browser-origin test proves that an unapproved origin cannot read or mutate the API (preflight/actual request rejected). - For retained mutations, actor fields reflect the authenticated principal and direct authorization tests cover every exposed command.

    F4。暂停会改变演示状态，但不会停止检查工作¶

    Problem: EdgeRuntime.pause only sets booleans and metadata. Nothing in the pipeline or any inspection entry point reads runtime.paused, so inspection work can continue while the UI shows a prominent "No new product windows will be opened" banner.

    Location: - apps/edge-service/src/assemblyvision_edge/api/state.py:60-70 - apps/edge-service/src/assemblyvision_edge/api/routers/inspection.py:48-80 - apps/edge-web/src/pages/LiveInspection.vue:125-136

    Violation: docs/design/16-edge-dashboard.md:112-116 (pause stops opening new product windows; the API owns the active-window behavior).

    Proposed solution: Route pause/resume through an inspection coordinator that owns admission of new product windows; detector/pipeline classes should not own operational pause state. The coordinator must finish or abort an active window according to an explicit policy, and resume must evaluate a typed readiness snapshot. For this read-only M1, the smaller valid alternative is to remove or disable the mutation endpoints and hide the controls until such a coordinator exists.

    Acceptance criteria: - For the M1 removal option, API tests assert pause/resume return 404/405 and UI tests assert that no control or effectiveness claim is rendered. - For the coordinator option, integration tests prove paused admission rejection and the configured active-window finish/abort policy, including conservative NG persistence for an aborted window when applicable. - For the coordinator option, resume returns 409 PRECONDITION_FAILED unless camera, model, rule, database, and disk preconditions pass, and the UI does not optimistically render READY before confirmation.

    F5。记录的 serve 快速入门提供模拟支持的仪表板¶

    Problem: VITE_API_BASE_URL is embedded at build time. The quickstart runs pnpm --filter edge-web build without setting it, so the bundle selects MockApiClient and the dashboard served by FastAPI shows seeded mock data instead of the reconciled real inspections.

    Location: - QUICKSTART.md:152-162 - apps/edge-web/src/services/client.ts:14-18

    Contradicts: QUICKSTART.md:147-150 and docs/ai/context.md:276-297.

    Proposed solution: Introduce an explicit build/runtime data mode such as VITE_API_MODE=mock|http. In HTTP mode, an omitted base URL means same-origin /api/v1; in mock mode the deterministic demo remains available. Build the served production bundle in HTTP mode. Add a browser-to-FastAPI integration test that proves real data renders when the built bundle is served by assemblyvision serve.

    Acceptance criteria: - Following the quickstart end to end shows real inspections in history, detail, media, and statistics, and shows backend-derived configuration/logs. - A separate HTTP integration fixture with a barcode value proves traceability rendering; the default static-MVP quickstart is not required to fabricate an SN that its CLI does not produce. - A test asserts the served bundle talks to the same-origin API. - The mock remains available only when an explicit mock mode is selected; an absent URL alone does not silently select mock in a production build.

    额外的阻塞发现¶

    F6。实模式将模拟检测结果与真实设备控制相结合¶

    Problem: The current inspection, confirm, next, and manual actions always run against a private MockApiClient, while pause/resume, status, logs, history, and runtime state use the configured real client. The mock inspection ID is then used to request real media; on failure the UI silently substitutes a synthetic camera frame.

    Location: - apps/edge-web/src/services/inspectionService.ts:27-51 - apps/edge-web/src/pages/LiveInspection.vue:46-56

    F8。规则、组件配置和清单集在启动时不会进行交叉验证¶

    Problem: Detector construction validates only config.components ⊆ manifest.class_names. If the rule requires a component that is present in the manifest but missing from config.components, the pipeline is reported as built and the detector later raises KeyError on every inspection.

    Location: - apps/edge-service/src/assemblyvision_edge/api/state.py:210-230 - apps/edge-service/src/assemblyvision_edge/detection/component_detector.py:101-104

    F10。 SQLite 默认值和不可变检查语义不符合约定¶

    Problem: The repository does not enable WAL or foreign keys, so ON DELETE CASCADE is inert. upsert_inspection can overwrite device_id, completed_at, and decision and deletes/replaces all evidence and media, while the denormalized filter columns are not updated, leaving list filters inconsistent with detail.

    条件生产-持久性发现¶

    C1-C4是权威生产持久性的有效要求 上传子系统。如果 API、快速入门、 上下文文档明确地将 SQLite 标记为 CLI 的可重建投影 捆绑，并且不声明事务发件箱/恢复准备就绪。

    C1。已完成的检查不会作为一个持久单元提交到数据库¶

    问题： assemblyvision inspect 发布媒体/JSON 并报告 OK 立即；仅当 API 稍后启动和扫描时才会填充 SQLite，并且 协调不会创建上传任务。启动前崩溃留下已完成的 结果在操作数据库和队列之外，并且 /api/v1/uploads 仍然存在 空用于正常检查。

    地点： - apps/edge-service/src/assemblyvision_edge/pipeline.py:235-278 - apps/edge-service/src/assemblyvision_edge/output/writer.py:96-135 - apps/edge-service/src/assemblyvision_edge/cli.py:150-164 - apps/edge-service/src/assemblyvision_edge/persistence/reconcile.py:30-42

    建议的解决方案： 保持当前 CLI JSON 包作为权威 static-MVP 结果并显式地将 SQLite 视为可重建的读取投影。 当权威的 SQLite 持久化/上传进入范围时，替换仅启动 与应用程序服务协调，在持久介质之后 发布并在发布完成之前，自动插入 检查、证据、媒体元数据和所需的上传发件箱任务合二为一 交易。

    M1 的验收标准： - 文档将 SQLite 标识为可重建的读索引，而不是 权威的完成/发件箱商店。 - 从有效的 CLI 包中删除并重建索引会产生等效的结果 无需更改捆绑包即可读取结果。

    生产持久性激活前的验收标准： - 完成的检查始终具有匹配的数据库行和所需的上传 OK/completion 之前的任务发布给操作消费者。 - 每个原子持久性步骤的崩溃测试都确定性地恢复（没有 已完成检查，但没有其所需的上传任务）。

    C2。架构无法强制同步身份或恢复上传租约¶

    问题： 架构允许重复的 (device_id, device_sequence)， 重复的 (device_id, idempotency_key)、重复的媒体路径和重复 每次检查的部件代码。 upload_tasks 和 UploadTask 没有租约 所有者/过期，因此过时的 IN_PROGRESS 工作在崩溃后无法恢复。

    建议的解决方案： 在可重建的M1索引中，拒绝重复的规范 儿童在和解过程中认同并测试拒绝。在 SQLite 之前 变得权威，添加记录的数据库唯一性约束。如果 修订版 0001 尚未部署在一次性开发数据之外 直接纠正；否则添加向前的 Alembic 修订版。添加上传 实现调度程序时的幂等性约束和租约字段。

    上传调度程序激活之前的接受标准： - UNIQUE(device_id, idempotency_key) 和租赁所有者/到期字段是 强制执行。 - 过时的IN_PROGRESS任务是可检测到的，并在之后转移到可重试状态 租约到期。

    问题： device_sequence 在每次进程重新启动后都会在 1 处重新启动，而 省略的设备 ID 会重新生成，从而产生重复的序列号 架构允许。管道创建 ProductResolution 没有 product_version_id，并且架构没有必需的产品配置 版本列，因此集中同步无法删除重复或重播 检查其精确配置。

    建议的解决方案： 对于静态 CLI MVP，记录其顺序不是 同步身份。在持久/同步操作之前，需要一个 稳定配置的设备身份、持久化和事务性分配 每个设备的序列号，并将产品配置版本存储在 每次检查。

    C4。启动协调不执行所需的完整性或恢复工作¶

    问题： 现有数据库行被跳过，以及它们的介质存在、大小、 校验和和生命周期从不检查。过时的 IN_PROGRESS 任务， 中断的检查、孤立/暂存文件和数据库完整性都不是 恢复了。缺少的 AVAILABLE 媒体将保持广告状态，直到发出请求为止 失败。
