    PR-008 评论：FastAPI 本地 API、SQLite 索引、运行时强化和测试覆盖率¶

    更正 (AUDIT-001)。 PR 中的“100% 测试覆盖率”声明 描述没有被复制。测量边缘 Python 语句覆盖率 合并结果约为 99.5% (pytest-cov)；未覆盖的线条 是查看者会话/无令牌分支、派生图像和统计信息 后备、验证空工作分支和无法访问的 IntegrityError 处理程序。将覆盖率数字视为过时的测量工件，而不是 保证，并在提出索赔时记录准确的命令/输出。

    范围¶

    dev -> main PR #8 (feat(edge): FastAPI local API, SQLite index, runtime hardening, and test coverage) 的代码审查。 PR 连线边缘 仪表板到真实后端（assemblyvision serve、/api/v1），添加 SQLite 具有 Alembic 迁移和幂等 CLI 输出协调的索引，适用 PR-003 运行时强化，并扩展了 Python 覆盖范围。

    本文件记录了调查结果、建议的解决方案和验收标准 对于合并之前必须修复的项目以及非阻塞后续操作 工作。

    合并决策¶

    在下面的 F1-F14 解决之前不要合并。 GitHub CI、CodeQL 和本地质量门都通过了，但有几个关键的 当前测试套件不涵盖缺陷和合同违规行为。

    C1-C4 是有条件的生产持久性要求，而不是阻碍 显式限制的只读 M1 索引。如果此 PR 被阻止，他们就会成为阻碍者 被描述或用作权威的生产持久/上传子系统。

    解决状态¶

    本次审查中的所有发现均已在 dev 上得到修复和验证：

    • F1-F14（阻塞）已解决。每个提交都进行了回归测试；的 全套通行证和边缘 Python 覆盖率通过以下方式测量和记录 pytest-cov（合并结果的语句覆盖率约为 99.5%；请参阅 上面的更正说明）。
    • C1-C4（条件生产持久性）针对 M1：SQLite 是 记录为具有重建等效测试的可重建读取投影， 迁移头验证、重复子项拒绝和隔离 崩溃左侧暂存包。
    • P2 项目已解决：未知 /api 路径返回问题 404，请求 ID 传播，媒体流受到有效的 416 问题的限制， verify --expected 禁用文件名回退并拒绝重复 身份、推理元数据按每个阶段的可追溯性、规则进行分类 身份无法使用不同的内容重新激活，并且快速入门/ 上下文文档与实现的 M1 边界相匹配。
    • 剩余路线图范围（上传队列调度程序、WebSocket 通道、摄像头/ 条形码适配器、时间聚合、Docker 打包、权威 SQLite 持久化/发件箱）被记录为下一个里程碑，并且不 阻止此 PR。

    立即封锁结果¶

    F1。在暂存路径下发布的媒体记录，后来更名为“离开”¶

    问题： OutputWriter.save 将媒体写入随机 .staging-... 目录，然后将该目录重命名为检查 ID，但是 persisted relative_path 源自暂存目录名称，并且是 重命名后就再也没有更新过。每一条媒体记录均由硬核制作 因此，作者指出了一条不再存在的路径。

    地点： - apps/edge-service/src/assemblyvision_edge/output/writer.py:114（暂存目录） - apps/edge-service/src/assemblyvision_edge/output/writer.py:130（重命名） - apps/edge-service/src/assemblyvision_edge/output/writer.py:151 (relative = f"{inspection_dir.name}/{name}")

    影响： assemblyvision inspect之后，最终文件存在于 <output>/<inspection_id>/key_frame.jpg同时记录引用 <output>/.staging-.../key_frame.jpg。协调导入无效路径 GET /api/v1/media/{id}/content 为每个生成的图像返回 404。 本地重现：持久路径不存在，而最终文件存在。

    测试间隙： apps/edge-service/tests/test_output_writer.py:60-78 和 apps/edge-service/tests/test_output_writer_extended.py断言物理 文件和校验和，但从未解析 output_root / media.relative_path。

    建议的解决方案： 从稳定版构建最终的 relative_path 文件仍写入暂存目录下时检查 ID。通行证 最终相对目录名单独到_save_image；不要重写 出版后的记录，因为这需要重写 原子目录重命名后的inspection.json。添加一个往返测试 通过存储库和媒体保存媒体、协调和提供内容 端点。

    验收标准： - media.relative_path 解析为 output_root 下的现有文件 writer.save制作的各种媒体。 - 测试验证保存后是否存在 output_root / media["relative_path"] reconcile_output_root 之后。 - API 测试验证 GET /api/v1/media/{id}/content 返回 a 的字节 新鲜生产的检验。

    F2。媒体内容端点允许目录遍历和绝对路径¶

    问题： relative_path 是从 inspection.json 导入的，没有 验证并通过加入 settings.output_root / media.relative_path 提供服务 无需解决和检查遏制。一个 inspection.json 包含 ../secret.txt 或在协调过程中接受绝对路径及其 内容在媒体根之外提供。调用者控制的 MIME 类型可以 还会导致提供活动的浏览器内容。

    地点： - packages/python/domain/src/assemblyvision_domain/models.py:136-145 - apps/edge-service/src/assemblyvision_edge/persistence/reconcile.py:30-40 - apps/edge-service/src/assemblyvision_edge/api/routers/media.py:49-60

    违规： docs/design/12-local-storage-and-retention.md:32 （路径是 由可信代码生成，不能包含调用者提供的遍历 段），docs/design/14-data-model-and-database.md:429,511-515（路径必须 相对于配置的媒体根），docs/contracts/05-data-api-and-versioning-contracts.md:75-82（API 不得公开文件系统数据）。

    建议的解决方案： - 在导入时拒绝绝对路径和遍历路径（协调和任何 未来的摄取路径）。 - 解析每个服务路径并要求 candidate.is_relative_to(output_root.resolve()) 阅读之前。 - 不要信任持久化的 MIME 类型；使用服务时间白名单。

    验收标准： - 协调会跳过（并记录）任何路径为绝对路径或 转义output_root；检验记录未部分导入。 - GET /api/v1/media/{id}/content 对于任何非包含路径返回 404。 - 使用精心设计的协调元数据进行测试，证明 ../、绝对路径和 无法读取符号链接转义。 - 响应Content-Type源自媒体种类/扩展允许列表，或者 经验证的持续价值；任意保留的 MIME 值都会被拒绝。

    F3。未经身份验证的带有通配符 CORS 的本地 API 会暴露特权操作¶

    问题： 没有路由具有身份验证或授权依赖性，并且 应用程序对所有方法和标头启用 allow_origins=["*"]。任何过程或 能够到达主机的浏览器可以暂停/恢复检查、重新连接 摄像头、重试上传以及读取历史记录、配置、日志和媒体。的 通配符 CORS 可以让任意网站向本地发出跨域请求 API。因此 paused_by 被硬编码为 "operator"，创建 false 归因。

    地点： - apps/edge-service/src/assemblyvision_edge/api/app.py:81-90 (CORS) - apps/edge-service/src/assemblyvision_edge/api/app.py:95-107（无授权部门） - apps/edge-service/src/assemblyvision_edge/api/routers/inspection.py:48-81 - apps/edge-service/src/assemblyvision_edge/api/routers/camera.py:23-29 - apps/edge-service/src/assemblyvision_edge/api/routers/uploads.py:53-64 - apps/edge-service/src/assemblyvision_edge/api/state.py:60-64

    违规： docs/design/15-rest-api-and-events.md:13-18 （改变路由 需要 operator/edge_admin；只读健康状况被故意限制；做 不将 localhost 视为身份验证），docs/design/16-edge-dashboard.md:137-139， docs/contracts/08-security-permissions-and-audit.md:11-16。

    建议的解决方案： - 采用并记录具有离线功能的边缘会话/主要设计定义 凭证颁发、验证、过期、CSRF 保护和查看者/操作者/ 边缘管理员授权。在除 /health/live 之外的所有路由上强制执行。 - 对于只读 M1，删除不支持的突变路线及其 UI 控件 而不是暴露未经身份验证的占位符。如果突变仍然存在，它们 需要记录的操作员/管理员角色和参与者属性。 - 默认禁用CORS（同源静态部署）并配置 明确的开发来源允许列表（或锚定的本地主机正则表达式） *。 - 在paused_by中记录代理主体（真实用户或会话）并进行审计 突变。

    验收标准： - 所选的边缘会话合同记录在相关设计/ADR 中； 环回绑定和 CORS 不被视为身份验证。 - 除了故意最小的 /health/live 返回之外的每个读取路由 401/403 没有定义的查看者凭据。 - 不支持的M1突变返回404/405并且没有相应的UI控件； 任何保留的突变都会返回 401/403，而没有其所需的作用。 - 浏览器源测试证明未经批准的源无法读取或变异 API（预检/实际请求被拒绝）。 - 对于保留的突变，参与者字段反映了经过身份验证的主体和 直接授权测试涵盖每个公开的命令。

    F4。暂停会改变演示状态，但不会停止检查工作¶

    问题： EdgeRuntime.pause 只设置布尔值和元数据。里面什么也没有 管道或任何检查入口点读取runtime.paused，因此检查 当用户界面显示突出的“不会有新产品窗口”时，工作可以继续进行 打开”的横幅。

    地点： - apps/edge-service/src/assemblyvision_edge/api/state.py:60-70 - apps/edge-service/src/assemblyvision_edge/api/routers/inspection.py:48-80 - apps/edge-web/src/pages/LiveInspection.vue:125-136

    违规： docs/design/16-edge-dashboard.md:112-116（暂停停止打开 新产品橱窗； API 拥有活动窗口行为）。

    持久/同步操作之前的验收标准： - 每个设备在重新启动后序列号都是唯一的。 - 每次持续检查都会记录其产品配置版本。 - 数据库拒绝重复的设备序列。

    C4。启动协调不执行所需的完整性或恢复工作¶

    问题： 现有数据库行被跳过，以及它们的介质存在、大小、 校验和和生命周期从不检查。过时的 IN_PROGRESS 任务， 中断的检查、孤立/暂存文件和数据库完整性都不是 恢复了。缺少的 AVAILABLE 媒体将保持广告状态，直到发出请求为止 失败。

    地点： - apps/edge-service/src/assemblyvision_edge/api/app.py:55-70 - apps/edge-service/src/assemblyvision_edge/persistence/reconcile.py:20-42

    违规： docs/design/12-local-storage-and-retention.md:108-112， docs/design/14-data-model-and-database.md:539-543, docs/contracts/04-edge-storage-upload-contracts.md:90-99。

    建议的解决方案： 对于 M1，验证迁移成功和可重建性 读取索引，并且不声称完全恢复。在权威坚持之前 激活，实施显式启动恢复阶段（数据库完整性， 中断检查、暂存/孤立文件、引用媒体存在/大小、 有界校验和验证、过期上传租约）并输入 无法恢复的损坏时的存储未就绪模式。

    权威持久性激活之前的接受标准： - 启动检测并报告引用的媒体丢失或损坏。 - 过时的IN_PROGRESS任务恢复到可重试状态。 - 不可恢复的数据库损坏将服务设置为存储未就绪，并且 永远不会在损坏的证据上初始化新的数据库。

    非阻塞 P2 结果¶

    以下项目不是合并阻止程序，但应在下一个项目中进行跟踪 里程碑：

    • 未知 /api/v1 路由返回 index.html 并带有 200。 apps/edge-service/src/assemblyvision_edge/api/app.py:130-143 应用 SPA 回退到 /api 之下； test_api_extended.py:111-116 处的测试编码 它。返回标准 API 404 问题。 解决方案： 切勿在 /api 下应用 SPA 后备。

    • 历史游标/过滤器不实现记录的合同。 apps/edge-service/src/assemblyvision_edge/api/routers/inspections.py:17-38。 游标未绑定到归一化过滤器集，无效游标变为500， 无效的决策/时间戳被接受为字符串，并且超出范围限制 默默重置。 解决方案： 验证边界处的类型化枚举/日期时间/范围，绑定 过滤不透明光标中的指纹，将失败映射到 400 INVALID_FILTER。

    • 上传重试会忽略资格、幂等性、原因和状态元数据。 apps/edge-service/src/assemblyvision_edge/api/routers/uploads.py:53-64; repository.retry_upload 接受任何状态，忽略 Idempotency-Key 和 原因，并且不更新 updated_at/next_attempt_at。 解决方案： 因为调度程序超出了 M1 范围，所以删除/禁用 目前突变端点和 UI 操作。激活后，保留密钥/原因， 仅允许符合条件的状态，返回 409 TASK_ACTIVE，并更新转换 时间戳。

    • 媒体“流式传输”加载整个文件并发出无效的空 416。 apps/edge-service/src/assemblyvision_edge/api/routers/media.py:58-81。 解决方案： 流式传输有界块并提出问题响应 Content-Range 保留。

    • 记录的过滤器被省略而不是拒绝/实施媒体 种类、上传状态/种类和日志级别/组件/时间/光标。 解决方案： 实施类型化、索引过滤器或停止声明设计 15.3 一致性。

    • 未处理的 500 响应不携带/传播请求 ID。 apps/edge-service/src/assemblyvision_edge/api/app.py:41-49,121-127。 解决方案：为每个请求生成/验证一个请求 ID 并将其包含在 每个问题和响应标题。

    • 推理来源仍然是未类型化且不完整的。 packages/python/domain/src/assemblyvision_domain/models.py:263， pipeline.py:280-289：inference_metadata是dict[str, object]并且记录 仅设置，而不是模型名称/版本、每次推理时间戳或阶段 延迟。在声明完整的推理可追溯性之前需要 (docs/contracts/03-ai-rule-and-safety-contracts.md:30-43)。

    • 未解决的 PR-003 验证差距： verify --expected 仍然启用文件名 回退（cli.py:173-180），验证将身份折叠为基本名称 （verify.py:191-212）。请参阅docs/reviews/PR-003-review.md:114-137。

    • 规则版本哈希不会强制跨版本的语义不变性。 接受不同内容的相同 rule_id/rule_version （rules/rule_engine.py:85-93）。需要安装规则注册表或冲突 拒绝。

    • 崩溃遗留的暂存包将被忽略并且永远不会被协调。 output/writer.py:114-134；进程内失败干净的暂存，但进程 终止绕过处理程序。初创公司应该隔离/验证过时的 .staging-* 目录。

    • 文档夸大了并与实施相矛盾： QUICKSTART.md:202-216 和 docs/ai/context.md:256-264,289-297,316-334。 需要与功能性阻断剂一起进行纠正（例如“切换到 FastAPI 不需要 UI 更改”是不准确的；暂停/恢复描述为 实施时它不管理管道执行）。
