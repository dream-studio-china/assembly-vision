    PR-014 评论：相机帧源、多实例边缘和 Web 开发测试工具¶

    范围¶

    针对 main 对 feat/camera-frame-sources 进行代码审查（PR #14）。的 审查涵盖 ADR-013 相机源和多实例运行时行为， ADR-014 基于文件的门控开发工具、API/OpenAPI/客户端合约、 以及新的开发人员工具视图。

    审查的相关要求：

    • docs/design/07-camera-and-image-acquisition.md
    • docs/design/decisions/ADR-013-camera-frame-sources-and-multi-instance.md
    • docs/design/decisions/ADR-014-web-dev-test-harness.md
    • docs/contracts/03-ai-rule-and-safety-contracts.md
    • docs/contracts/05-data-api-and-versioning-contracts.md
    • docs/contracts/06-testing-quality-and-ci-contracts.md
    • docs/contracts/08-security-permissions-and-audit.md

    合并决策¶

    在 F1-F9 解决之前不要合并。

    该实现建立了有用的源代码和测试工具接缝，并且 现有的重点测试通过。然而，电流捕获循环可以默默地 失去检验证据，暂停不停止检验，几个来源 失败违反了非致命/故障安全生命周期和公共开发 API 合约不能由提交的 OpenAPI 和生成的客户端来表示。

    F10-F12是非阻塞后续工作，但应该在之前解决 开发人员工具的使用超出了受控的本地开发范围。

    解决状态¶

    本次审查 (F1-F14) 中的所有发现均已在 feat/camera-frame-sources 由四个并行执行代理组成，然后是 合同再生和完整的质量门。每个修复都会带来回归 在修复之前失败并在修复之后通过的测试：

    • F1 - 有界的每个实例检查队列；溢出被记录 （frames_dropped/degraded、FRAME_OVERFLOW警报）而不是无声的损失； 预览仍然提供最新捕获的帧。
    • F2 - 根据记录检查暂停和排出过时帧的循环门 暂停/恢复时溢出；多实例设备状态报告PAUSED和 inspection_ready=false。
    • F3 - 缺少文件夹源引发 FrameStreamError；源头建设 失败被捕获为 AssemblyVisionError 并注册 CAMERA_UNAVAILABLE 不中止健康实例。
    • F4 - HTTP 图像传输与解码失败是分开的（解码 故障源）； PyAV 打开/解码/转换异常是 包装为 FrameStreamError；捕获循环有一个最终的 标记实例已断开连接的意外异常处理程序。
    • F5 - 图像主体流入带有早期 413 的有界缓冲区； 解码限制（_MAX_IMAGE_PIXELS、_MAX_IMAGE_DIMENSION）拒绝 减压炸弹为400 INVALID_IMAGE。
    • F6 - step 有界 (le=100)；总解码帧和解码 挂钟预算停止迭代并在视频摘要上设置 truncated。
    • F7 - 持久的开发检查被更新到 SQLite 投影中 立即可见，无需重启； persist=false 不导入任何内容。
    • F8 - 开发启用门在查看者身份验证之前运行：禁用 即使未经身份验证，端点也会返回 404 DEV_TOOLS_DISABLED；已启用 端点为未经身份验证的调用者保留 401。
    • F9 - generate-edge-openapi.py 现在声明所需的二进制请求 两个开发操作的主体和 400/404/413/503 问题响应； 重新生成 OpenAPI 和 TypeScript 类型；漂移测试已更新。
    • F10 - DevToolsView 上传按单调请求 ID 排序，因此 过时的响应无法覆盖当前结果或清除 busy。
    • F11 - HTTP 客户端发送 Blob 自己的媒体类型 （application/octet-stream 后备）而不是制作 jpeg/mp4。
    • F12 - VideoFrameInspectResult 使用规范的 BusinessResult / InternalDecision 枚举； TS 联合和运行时验证强制执行 OK|NG / OK|NG|UNCERTAIN。
    • F13（执行期间添加） - 多实例 inspection_state 否 当启用的实例运行状况良好时，报告 faulted=true 的时间更长，并且 显示最新的每个实例结果。
    • F14（在执行期间添加） - 重新连接策略 maximum_delay_ms < initial_delay_ms 被拒绝为 ConfigError。

    阻塞结果¶

    F1。最新的车架更换默默地丢弃了检查证据¶

    严重性： P0 / 高

    地点：

    • apps/edge-service/src/assemblyvision_edge/camera_manager.py:101-105
    • apps/edge-service/src/assemblyvision_edge/api/state.py:204-214

    CameraSourceManager仅保留一帧。检查循环显示 推理完成后的槽并仅检测到其序列已更改。 当捕获速度快于推理速度时，所有中间帧都会被覆盖 没有记录、背压信号或降级/NG 结果。例如，一个 25 FPS 源和 500 毫秒推理可以为每个帧丢弃大约 12 帧 完成检查。这与 ADR-013 明确的当前 MVP 相冲突 对每个捕获的帧进行一次检查的语义并设计 07 的规则 捕获失败和丢失证据不能被默默地跳过。

    解决方案： 保留一帧缓存专门用于预览。启用饲料 从有界的每个实例队列进行检查循环。将队列饱和度定义为 明确的、可观察的条件：应用捕获反压或标记 根据记录，受影响的检查路径已降级/出现故障 政策。不要用后面的帧替换排队的检查帧。

    验收标准：

    • 比阻塞测试管道更快地发出编号帧的源 要么导致按顺序检查每个接受的帧，要么产生 记录的溢出状态和指标/原因代码。
    • 预览端点仍然返回最近捕获的帧，同时 检查队列是独立消耗的。
    • 回归测试在当前实现上失败，并在之后通过 实现了队列/溢出行为。

    F2。暂停叶子启用多实例检查循环运行¶

    严重性： P0 / 高

    地点：

    • apps/edge-service/src/assemblyvision_edge/api/state.py:204-214
    • apps/edge-service/src/assemblyvision_edge/api/state.py:216-226
    • apps/edge-service/src/assemblyvision_edge/api/state.py:267-307

    pause() 仅更新状态字段。 _inspection_loop()从不阅读 self.paused，因此它继续调用inspect_frame()并保留结果。 多实例设备状态路径也会忽略暂停并可以报告 READY 和inspection_ready=true。因此，操作员可以被告知检查是 当流程仍在发出物理检查决策时暂停。

    解决方案： 在出队/处理之前暂停时对每个检查循环进行门控 新工作。在多实例模式下，报告 PAUSED inspection_ready=false 暂停时。保持预览/相机健康（如果有） 是有意为之，但要在状态和文档中明确区分。

    验收标准：

    • 启动启用的实例并验证检查是否发生；暂停并验证 不会再发生对 inspect_frame() 或持久记录的调用。
    • 暂停时，设备状态为 PAUSED，inspection_ready 为 false，并且 警报包括NOT_READY。
    • 恢复仅对随后接受的帧重新启动处理，并且不会 不将跳过/不明确的队列内容视为积极证据。

    F3。错误的文件夹源配置可能会在启动时中止所有实例¶

    严重性： P0 / 高

    地点：

    • packages/python/vision-core/src/assemblyvision_vision/sources/folder_source.py:35-37
    • apps/edge-service/src/assemblyvision_edge/api/state.py:168-178

    当目录丢失时 FolderSource 会引发 ImageReadError，但是 load_instances() 仅捕获围绕源构建的 FrameStreamError。 ImageReadError 转义，阻止 self.instances 和相机管理器 停止安装，并阻止健康配置的实例启动。 这违反了 ADR-013 所要求的非致命每实例源故障。

    解决方案： 将每个 FrameSource 的构造错误标准化为 FrameStreamError，或者在实例中捕获常见的AssemblyVisionError 边界并为该实例安装失败的源状态。不要抓住 任意编程错误。

    验收标准：

    • 配置 1 个缺失文件夹实例和 1 个有效循环文件夹实例。
    • 启动成功；有效实例生成预览帧并可以检查 当启用时。
    • 无效实例的状态存在稳定的不可用错误 代码，并且不能选择它作为可用的检查管道。

    F4。 HTTP 损坏的图像和 PyAV 失败不遵守帧错误契约¶

    严重性： P0 / 高

    地点：

    • packages/python/vision-core/src/assemblyvision_vision/sources/http_image_source.py:79-91
    • packages/python/vision-core/src/assemblyvision_vision/sources/http_image_source.py:96-106
    • packages/python/vision-core/src/assemblyvision_vision/sources/rtsp_source.py:113-137
    • apps/edge-service/src/assemblyvision_edge/camera_manager.py:54-75
    • apps/edge-service/src/assemblyvision_edge/camera_manager.py:98-115

    HttpImageSource._fetch() 映射传输错误和损坏的图像字节 到 FrameStreamError，然后 frames() 重试这两种情况。腐败的回应 因此被默默地跳过，这违反了 ADR-013/design 07 的要求 解码失败会浮现出来，而不是作为缺乏证据而消失。

    RTSPFrameSource 不翻译 av.open() 中的异常， container.decode()，或将 to_image() 转换为 FrameStreamError。在启动时 普通 PyAV 异常转义 CameraSourceManager.start() 并可以中止 其他情况。在捕获期间，它逃脱线程而不是跟随 定义源错误/重新连接策略。

    解决方案： 拆分可恢复传输与无效/解码断开连接 数据。仅重试已记录的具有有限退避的传输失败；传播 损坏图像/解码失败为 FrameStreamError，因此管理器将其标记为 实例失败。在适配器处包装 PyAV 打开/解码/转换异常 边界为 FrameStreamError，并在中添加最终的意外异常处理程序 在终止线程之前记录相机错误的管理器。

    验收标准：

    • HTTP 服务器返回有效字节、损坏字节、然后返回有效字节 对损坏的字节进行源故障；它不能像没有一样发出最终帧 失败发生了。
    • 模拟 PyAV 在打开和解码时失败，留下健康的同级实例 运行并公开 CAMERA_UNAVAILABLE 或 CAMERA_STREAM_ERROR 失败的实例。
    • 没有适配器异常转义 CameraSourceManager.start() 或离开 管理器在失败后报告流已连接。

    F5。图像上传完全缓冲和解码，没有像素限制¶

    严重性： P0 / 高

    地点：

    • apps/edge-service/src/assemblyvision_edge/api/routers/dev.py:61-76

    仅在 await request.body() 缓冲后才检查 20 MB 图像限制 完整的有效负载。没有 Content-Length 的分块请求可以消耗 在被拒绝之前任意更多的边缘进程内存。另外，还有一个压缩包 低于 20 MB 的图像可以扩展到 convert("RGB") 处的无界像素缓冲区。 显式启用的开发端点的经过身份验证的用户可能会耗尽 记忆并扰乱局部检查。

    解决方案： 在计数时将请求块流式传输到有界缓冲区中 字节，就像视频路由已经做的那样。转换前，强制执行最大 宽度、高度和总像素；处理枕头减压炸弹警告和 错误为 INVALID_IMAGE。明确选择限制并将其记录在 20 MB 线路大小限制。

    验收标准：

    • 超过限制的分块 ASGI 请求被 413 PAYLOAD_TOO_LARGE 拒绝 在累积超过配置限制的主体之前。
    • 超出解码像素限制的小型压缩装置返回 400 INVALID_IMAGE 并且不调用管道。
    • 字节和像素限制内的有效图像产生相同的结果 InspectionRecord 行为与以前一样。

    F6。视频采样限制检查帧但不解码工作¶

    严重性： P1/高

    地点：

    • apps/edge-service/src/assemblyvision_edge/api/routers/dev.py:94
    • apps/edge-service/src/assemblyvision_edge/api/routers/dev.py:141-152

    step 没有最大值。每个跳帧都被完全解码 VideoFrameSource 在计算模条件之前。与一个大 step，路由可以检查一帧，然后解码剩余的 100 MB 视频搜索下一个选定的帧。广告上的最多三十个 帧仅限制推理调用，而不限制解码器 CPU 时间或已用请求 时间。

    分辨率： 独立绑定step和总解码帧，并添加一个 挂钟解码预算。如果编解码器支持允许，首选基于搜索的采样； 否则，当解码帧或时间达到时，返回有界问题响应 预算达到。在 ADR-014/API 文档中记录所选策略。

    验收标准：

    • 具有许多帧和非常大的 step 的假源在解码时停止 帧/时间预算而不是迭代完整的源。
    • 太大的 step 会被请求验证拒绝。
    • 响应清楚地表明结果是完整的还是被停止的 记录资源限制；这并不意味着所有视频帧都是 分析了。

    F7。在流程重新启动之前，持续的开发人员检查不可见¶

    严重性： P1/高

    地点：

    • apps/edge-service/src/assemblyvision_edge/api/routers/dev.py:86-87
    • apps/edge-service/src/assemblyvision_edge/api/app.py:81-85

    持久帧路径仅写入输出包。调节进口 仅在应用程序启动期间捆绑，因此不存在返回的检查 从历史记录和检查详细信息端点直到服务重新启动。这个 与 ADR-014 所声明的行为相矛盾，即持久结果出现在仪表板中 历史。

    解决方案： 成功发布原子包后，导入/更新插入 在返回 200 之前通过相同的存储库协调路径进行记录。 保留输出包作为当前 M1 读取的真实来源 投影，并定义一个故障安全响应（如果发布成功但 投影无法更新。

    验收标准：

    • 将持久帧发布到实时应用程序，然后立即请求它 无需重启即可检查详细信息和历史记录；两者都返回记录。
    • persist=false 不创建捆绑或投影条目。
    • 重新启动后的协调仍然是幂等的并且不会重复 立即导入记录。

    F8。禁用的开发端点在其所需的 404 门之前返回 401¶

    严重性： P1 / 中

    地点：

    • apps/edge-service/src/assemblyvision_edge/api/app.py:135-147
    • apps/edge-service/src/assemblyvision_edge/api/routers/dev.py:39-50

    所有路由器之前都会收到应用程序级 require_viewer 依赖项 开发路由器的依赖项运行。配置了 API 令牌并 enable_web_test=false，未经身份验证的请求会收到401 UNAUTHENTICATED，而不是ADR-014所需的404 DEV_TOOLS_DISABLED。 因此，禁用的表面是可区分的，并且明确的 不满足默认禁用的合同。目前的测试包括路由器 隔离并且不执行这种依赖顺序。

    解决方案： 在查看器之前通过启用门路由开发请求 身份验证，同时在该功能启用时保留查看者身份验证 已启用。这可以是应用程序级别的条件依赖性或小的 专用路由器包含路径；不要削弱已启用端点的身份验证。

    验收标准：

    • 在具有配置令牌和 Web 测试的完整 create_app() 实例中 禁用、经过身份验证和未经身份验证的开发请求都会返回 404 DEV_TOOLS_DISABLED。
    • 启用 Web 测试后，未经身份验证的请求将返回标准 401 有效的承载/会话身份验证可以调用端点。

    F9。 OpenAPI 和生成的 TypeScript 未描述附带的开发 API¶

    严重性： P1/高

    地点：

    • OpenAPI 回归测试断言媒体模式和问题响应； 现有的 OpenAPI 偏差检查通过。

    F10。开发人员工具页面允许过时的并发结果覆盖当前上传的结果¶

    严重性： P2 / 中

    地点：

    • apps/edge-web/src/pages/DevToolsView.vue:31-62

    选择图片A启动请求A；选择图像 B 重置 UI 并开始 请求 B。如果 A 在 B 之后完成，则预览时会覆盖结果 仍然显示 B。A 的 finally 也会清除 busy，同时 B 保持活动状态。这个 可以显示不同图像的决定并允许重复提交。

    解决方案：中止之前的请求或者使用单调递增 仅请求 ID 并应用 record、videoResult、error 和 busy 更改 对于当前的请求。

    验收标准： 延迟承诺组件测试启动两次上传， 解决了第二个之后的第一个结果，并证明只剩下第二个结果 而 busy 保持 true 直到第二个稳定。

    F11。客户端内容类型是为非 JPEG/非 MP4 上传而设计的¶

    严重性： P2 / 中

    地点：

    • apps/edge-web/src/pages/DevToolsView.vue:96-104
    • packages/typescript/api-client/src/edge/HttpApiClient.ts:215-242

    UI 接受所有浏览器图像/视频媒体，但 HTTP 客户端标记每个 图片 image/jpeg 和每个视频 video/mp4。 PNG、HEIC、WebM、MOV 和 AVI 因此，有效负载会被错误地呈现给代理和未来的媒体验证器。

    解决方案： 可用时发送 Blob.type 并使用 application/octet-stream 仅作为后备。缩小文件选择器类型或 扩展记录的 API 媒体类型以完全匹配解码器 支持。

    验收标准： 使用 PNG 和 WebM/QuickTime File 进行客户端测试 对象验证传出 Content-Type 保留每个文件的 MIME 类型， OpenAPI 指出了支持的集合。

    F12。视频决策字段被弱化为任意字符串¶

    严重性： P2 / 中

    地点：

    • apps/edge-service/src/assemblyvision_edge/api/schemas.py:77-93

    F13。多实例巡检状态老报故障¶

    严重性： P1 / 中

    地点： apps/edge-service/src/assemblyvision_edge/api/state.py:324-334

    在多实例模式下 self.pipeline 始终是 None，因此 即使已启用实例，inspection_state() 也会报告 faulted=true 检查后，没有显示每个实例的最后结果。

    F14。重新连接退避允许低于初始延迟的最大延迟¶

    严重性： P1 / 中

    地点： apps/edge-service/src/assemblyvision_edge/config.py:521-542
