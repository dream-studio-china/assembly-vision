    AUDIT-001：系统和文档一致性审核¶

    范围¶

    Read-only audit of the AssemblyVision repository (edge runtime, persistence, API, frontend, training, scripts, and documentation), performed 2026-08-08. This verification update was performed against the current worktree on 2026-08-09. No production code was changed by this update.

    方法¶

    • Reviewed the governing safety, storage, data/API, security, and model-release contracts; design 11, 14, and 19; and ADR-011 and ADR-012.
    • Inspected each cited current implementation and its related tests.
    • A finding is retained only where the current code demonstrates the stated behavior or where the current documents demonstrably conflict. A struck item is not an open finding; its original evidence is stale, false, or based on an unsupported requirement.

    解决状态¶

    All HIGH findings and reproduced MED findings, the rule-engine and manifest defects, the API/frontend hardening items, and the documentation alignment items are closed as of 2026-08-09. Each closure is recorded in Section 8 with the commit and the verification that satisfied its acceptance criteria. The only remaining work is the authoritative persistence schema (4.4), which is explicitly deferred until the upload scheduler is built; the M1 boundary document now names it as future work.

    The shared closure gate for every behavioral change is:

    uv run ruff check .
uv run ruff format --check .
uv run mypy .
uv run pytest

    Documentation-only changes must also pass uv run mkdocs build --strict when the documentation environment is installed. A finding closes only when its specific acceptance criteria and the applicable shared gate pass in CI.

    总体判断¶

    No evidence in this review contradicts the prior conclusion that the current single-frame pipeline fails closed for ordinary invalid pipeline states. The highest concrete risks are dataset-label fabrication, unusable published training datasets, and a documented training command that can select the wrong Ultralytics run directory. Several lower-severity robustness and contract gaps remain. The M1 SQLite database is a rebuildable read projection, not the contract-required authoritative inspection/outbox store; future scheduler and authoritative-persistence work must not treat its current schema as fulfilling that production contract.

    3. 高发现¶

    H1。丢失的标签文件伪造了真实情况¶

    • Status: CLOSED (3ce3147).
    • Evidence: Both adapters use [] when <image-stem>.txt is absent (adapt-roboflow-dataset.py:191, adapt-xanylabeling.py:231). The result is interpreted as an explicit negative or an expected missing-component test sample. This contradicts design 19.17.3, which requires explicit empty label files and image/label pairing.
    • Required change: Reject every missing label file in every supported split. Do not add an adapter opt-in unless its semantics, provenance, and downstream validation behavior are designed and documented; the minimal safe fix is rejection. Also reject duplicate image stems within a split before output writing, and normalize Roboflow's valid split to val if it is supported.
    • Acceptance: Add parameterized tests for both adapters proving that a missing train, validation, or test label raises ValueError, leaves no output or staging directory, and does not write test-expected.json. Add tests for an explicit empty label (accepted), same-stem collision (rejected), and the documented valid layout (accepted only when normalized to val).

    H2。发布的 data.yaml 引用已删除的暂存目录¶

    • 状态： 关闭 (7af307b)。
    • 证据： 两个适配器和 prepare_components.py:181-189 序列化 从其暂存输出派生的绝对路径，然后自动重命名 暂存目录。因此，发布的 YAML 指向不存在的 目录。
    • 需要更改： 编写相对于数据集 YAML 的可移植路径（对于 例如 images/train 和 images/val)，或仅写入最终绝对路径 出版后。在适配器、准备、 和合成发电机。
    • 验收： 对于每个适配器和组件准备，创建一个数据集， 发布它，解析它的data.yaml，根据以下内容解析train和val 选择约定，并断言最终输出下两个目录都存在 root 并包含预期的图像。断言序列化值不包含 .staging-。

    H3。相对--out-weights可以选择错误的Ultralytics运行路径¶

    • 状态： 关闭 (fcfcf7c)。
    • 证据： cli.py:226,313 通过了潜在的亲属 weights_path.parent / ".train-runs"； train.py:71-77 然后假设 固定返回路径。这与记录的相对路径命令不同 并且可能与 Ultralytics 对相关项目的处理发生冲突。
    • 需要更改： 在调用 Ultralytics 之前解析项目目录。 从解析的项目目录中导出返回的权重路径，验证 它存在并且是 place_weights 之前的常规文件，并提出明确的 否则训练错误。
    • 接受： 使用相对路径对产品和组件 CLI 路径进行单元测试 --out-weights，使用 train_detector/YOLO 进行模拟，并断言该项目是 绝对并且选择了预期的 best.pt。添加回归测试 丢失返回的神器。运行一个记录的相对路径烟雾命令 仅当其受控训练装置可用时才进行 CI。

    H4。 context.md 表示 PR #11 已开放¶

    • 状态： ~~无效/过时的审计证据~~。
    • 原因： docs/ai/context.md:24,31,40 现在声明 PR #11 已合并， 没有开放的 PR，并且 dev 与 main 同步。没有变化 此项目需要。

    4. 医学研究结果¶

    4.1 再现健壮性和并发性缺陷¶

    身份证 现状和证据 需要改变 严格验收
    M1 已关闭 (7d987e7)。 media_path_is_safe 仅捕获 OSError (reconcile.py:37-42)； Path.resolve() 可以为嵌入的 NUL 引发 ValueError。因此，启动扫描会中止，而不是跳过格式错误的包。 将路径构建/解析期间引发的 ValueError 视为格式错误的媒体并跳过该记录。隔离单个包中的错误。 包含 NUL 字节媒体路径的协调测试会导入有效的同级包，跳过格式错误的包，返回正确的导入计数，并发出警告而不引发警告。
    M2 已关闭 (5f70071)。 register_rule_identity 是选择然后插入，没有 IntegrityError 翻译或重试 (repository.py:688-715)。 在 unique-race 中，重新读取新事务中存储的哈希值：相等时成功返回，不同时引发 RepositoryError。翻译意外的数据库错误。 基于屏障的多线程测试同时注册相同的身份/散列，没有原始的 IntegrityError；并发的不同哈希确定性地引发 RepositoryError 并保持原始哈希不变。
    M3 已关闭 (84e5fd5)。 EdgeRepository.open() 始终为同一新路径（repository.py:155-167、migrate.py:17-29）调用进程不安全的 Alembic 运行器。 使用进程间锁序列化首次打开迁移，或者在创建引擎之前显式拒绝并发首次打开。在 M1 边界文档中定义行为。 打开同一个新数据库的多进程测试无需 Alembic KeyError 即可完成，完全保留头部修订版本，启用所需的 SQLite 编译指示，并且两个存储库都可以执行读/写投影操作。

    4.2 规则引擎故障安全差距¶

    • 状态： 关闭 (653a850)。
    • 证据： _spatial_violation不拒绝非有限比率或 中心（rule_engine.py:110-123）；与 NaN 的比较是错误的。另外， PRESENT 证据在没有可用框架、置信度或 支撑框架（147-168）。这违反了合同03.5的禁令 OK来自不完整的结果数据/没有可用的框架和设计11.2的证据 要求。
    • 需要更改： 明确拒绝非有限几何。礼物之前 组件可以满足一个要求，需要usable_frame_count >= 1，a 有限best_confidence，非空支撑框架列表，并且一致 检测/支持帧计数。决定并记录是否每个 当没有声明空间约束时，检测需要几何形状。
    • 接受： 表驱动测试注入 NaN、inf、零可用帧、 缺乏/非有限置信度，并将支持 ID 清空为其他有效的 ID 证据。每个案例都会返回带有稳定原因码的业务NG；没有测试 可以从不完整的证据中获得OK。现有有效证据仍须 返回OK。

    4.3 明显的验证差距¶

    • 状态： 关闭 (16448b5)。
    • 证据： runtime在探测器构造之前不受约束； verify_manifest_artifact 仅拒绝前导斜杠/反斜杠并允许 遍历或类似 URI 的工件路径； verify_model_class_map 假设 连续的映射键并且可能泄漏KeyError。
    • 需要更改： 清单中需要 runtime == "ultralytics" 加载边界、拒绝非文件 URI 方案、解析工件并 需要包含在模型束根以下（这允许 记录了 models/manifests 和同级 models/weights 布局），以及 将格式错误/不连续的类映射转换为 ConfigError。
    • 接受： 测试拒绝 runtime="other"，逃离模型的路径 路径解析器、符号链接接受的包、编码或方案 URI 形式 escape，以及与 ConfigError 不连续的 {1: "component"} 映射。一个 有效的相对工件，包括记录的同级权重，以及 连续映射继续加载并进行校验和验证。

    4.4 持久化和契约边界¶

    • 状态： 部分。 M1 边界已记录 (5488804)；的 权威模式、产品配置版本和并发 等内容更新插入行为仍然是上传的未来工作 调度程序。并不是说 M1 已经实现了生产发件箱。
    • 证据： 当前的投影模式缺乏唯一性约束， 产品配置列，并上传设计14指定的租约和 合同 04/05。 pipeline.py:303-305 创建一个 ProductResolution 没有 product_version_id。 upsert_inspection 仍然是先检查后插入，尽管 其外部 IntegrityError 翻译可防止原始 SQLAlchemy 泄漏。
    • 需要更改： 首先更新设计 14 以区分 M1 可重建 来自未来权威商店的投影。在任何上传调度程序之前 或多写入器部署，为权威添加 Alembic 迁移 模式，保留一个非空的受控产品配置版本，并制作 等内容并发检查更新插入幂等返回unchanged。
    • 接受： 边界文件指出投影的非权威性 限制。权威商店测试验证所有合同 04/05 约束， 租赁字段、产品版本追溯、并发等内容 更新插入返回unchanged；不同的内容必须在没有突变的情况下失败。
