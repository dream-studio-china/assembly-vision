    PR-003 后续审查¶

    范围¶

    本文件记录了可操作的 P1 和 P2 发现后剩余的 P0 修复已提交为 677c094、c23d831 和 1618efb。

    解决状态¶

    本文档中的所有 P1 和 P2 发现均已得到解决和验证：

    • P1：明显的完整内容不变性，Roboflow 源标签严格 验证，需要图像/标签与记录的选择配对，明确 产品数据集的背景底片和源相关 验证身份。
    • P2：捆绑原子证据输出，规则版本标识绑定到 内容、过时输出安全数据集改编/准备文件 清单和组件准备重用已验证的产品清单 以及运行时恰好一种产品选择策略。

    P1 调查结果¶

    模型明显的不变性不完整¶

    training/src/assemblyvision_training/artifact.py 允许现有清单 当语义版本和第一个工件校验和匹配时被覆盖。 替换仍然可以更改任务、类顺序、输入大小、工件 URI、 出处或其他决策关键元数据，同时保留相同的模型 版本标识。

    在接受之前要求规范的不可变清单内容匹配 幂等发布。返回现有清单而不重写它 它匹配；否则拒绝发布并要求新版本。添加测试 在改变班级顺序、任务和输入大小的同时保留相同的权重。

    相关参考：docs/contracts/08-security-permissions-and-audit.md、 docs/contracts/10-model-rule-release-and-acceptance.md，以及 docs/design/19-training-and-evaluation.md。

    运行时推理不应用声明的模型设置¶

    apps/edge-service/src/assemblyvision_edge/detection/product_detector.py 和 component_detector.py 在没有清单输入大小的情况下调用 Ultralytics 或 配置 IoU 和置信度设置。因此，运行时取决于库 默认值而不是声明的发布配置。特别是，默认 NMS 可以在精确计数规则之前抑制重叠的产品或组件 跑。

    显式传递经过验证的 imgsz、iou、置信度和设备参数。 将有效值保留为推理元数据并添加适配器测试 断言确切的模型调用参数。

    相关参考：docs/contracts/03-ai-rule-and-safety-contracts.md和 docs/design/08-product-detection-and-roi.md。

    组件配置、规则和清单集未进行交叉验证¶

    apps/edge-service/src/assemblyvision_edge/cli.py 验证配置 组件对照清单，但不验证每条所需的规则 针对运行时设置的组件。规则和清单中存在的类 但缺席 config.components 到达 ComponentDetector.detect() 并在访问其时引发 KeyError 阈值。

    在启动时验证兼容的组件集并防止检查准备就绪 对于任何不匹配。为规则中的每个不匹配方向添加测试， 组件配置和清单。

    相关参考：docs/contracts/03-ai-rule-and-safety-contracts.md和 docs/contracts/05-data-api-and-versioning-contracts.md。

    Pipeline 不验证检测来源¶

    apps/edge-service/src/assemblyvision_edge/pipeline.py 不验证 产品和组件检测属于当前框架、加载的模型、 或证据聚合之前的预期坐标空间。目前的 测试套件在成功的管道测试中接受随机、不相关的帧 ID。

    验证帧 ID、模型版本 ID、图像尺寸和 ROI/全帧 协调管道边界处的元数据。任何不匹配都必须使 检查为NG，并且不得转换为当前框架证据。

    相关参考：docs/contracts/03-ai-rule-and-safety-contracts.md和 docs/design/09-component-detection.md。

    Roboflow 适配器默默地丢弃无效的源注释¶

    scripts/adapt-roboflow-dataset.py 跳过一些无效的类 ID 并允许 从类名列表末尾开始索引的负 ID。它不验证 字段计数、有限坐标、正框尺寸或图像边界。一个 删除的测试注释可以转换为制造的缺失组件 基本事实。

    解析每个源标签行一次并需要正好五个有限域，一个 非负范围内类 ID 和帧内正区域框。拒绝 当任何源注释无效时，在写入输出之前进行整个适应。

    相关参考：docs/design/19-training-and-evaluation.md和 docs/design/22-testing-and-quality-assurance.md。

    缺失的标签仍然被视为隐含的否定¶

    training/src/assemblyvision_training/dataset.py 仅在图像出现以下情况时发出警告 没有匹配的标签文件。因此，训练可以治疗意外未配对的情况 产品图片作为底片。

    默认情况下需要图像/标签基本名称配对。故意负面图像 必须有明确的空标签文件。如果遗留数据需要缺失标签， 提供有意选择加入模式并将其记录在数据集清单中。

    相关参考：docs/design/19-training-and-evaluation.md和 docs/design/25-roadmap.md。

    产品检测器培训消除了明确的背景底片¶

    scripts/adapt-roboflow-dataset.py 排除所有没有产品包装盒的图像 来自 dataset_product，包括明确的空标签传送带/背景 图像。这消除了有用的产品检测器底片。

    在具有空产品的产品数据集中保留显式的空标签图像 标签文件。拒绝包含组件标签但缺少所需的图像 独立的产品盒，而不是将它们与背景混为一谈。

    相关参考：docs/design/19-training-and-evaluation.md和 docs/design/22-testing-and-quality-assurance.md。

    预期标签验证仍然接受意外的文件名标签文件¶

    apps/edge-service/src/assemblyvision_edge/cli.py 调用 run_verify() 即使提供了 --expected，文件名后备也会启用。额外的过时文件 以 ok、ng 或 missing 命名的系统会默默分配预期标签，并且 包含在指标中。

    通过filename_fallback=args.expected is None。当预期清单是 提供，要求其条目与 输入文件，将丢失和意外的文件报告为验证差距。

    相关参考文献：docs/design/22-testing-and-quality-assurance.md。

    验证仅通过基本名称识别样本¶

    apps/edge-service/src/assemblyvision_edge/verify.py 使用 path.name 作为 预期结果键。不同文件夹提供的同名图像共享 一个标签，seen 集会折叠它们，同时指标对两行进行计数。

    使用清单相对路径或不可变的示例 ID。拒绝重复工作 身份，并且每个预期条目都需要一个输入。

    相关参考：docs/design/19-training-and-evaluation.md和 docs/design/22-testing-and-quality-assurance.md。

    P2 调查结果¶

    检查证据输出不具有束原子或断电持久性¶

    apps/edge-service/src/assemblyvision_edge/output/writer.py 写入媒体并 JSON独立在最终检查目录中。失败可以离开 部分可见证据；重试可以将替换的媒体与旧的 JSON 结合起来 记录。单个文件和目录不会进行 fsync。

    在同级暂存目录中构建每个检查，刷新并同步所有文件 和目录，然后自动发布完整的目录。拒绝写入 到已发布的检查 ID 并添加注入的写入失败和 重新启动恢复测试。

    相关参考文献：docs/design/06-ai-detection-pipeline.md和 docs/design/23-observability-and-support.md。

    规则版本标识不与规则内容绑定¶

    rule_version_id() 在 apps/edge-service/src/assemblyvision_edge/rules/rule_engine.py 仅限哈希值 rule_id 和 rule_version。组件要求、门的变化， 空间限制或兼容模型可以保留相同的持久 UUID。

    保留记录的规范规则校验和，或派生版本 来自规范规则内容的身份。拒绝重复使用相同的规则 ID/版本 具有不同的内容。

    相关参考：docs/contracts/05-data-api-and-versioning-contracts.md 和docs/design/11-rule-engine.md。

    数据集调整和准备可以保留陈旧的输出¶

    scripts/adapt-roboflow-dataset.py 和 training/src/assemblyvision_training/prepare_components.py 直接写入 现有的输出目录。使用更少的样本、不同的来源重新运行 数据，或者跳过样本的检测器将旧文件留在新数据集中。

    拒绝非空目标或将完整的新数据集写入暂存 目录、验证它并自动发布它。记录一个文件清单 数据集成员资格和沿袭是可审计的。

    相关参考：docs/design/19-training-and-evaluation.md和 docs/design/25-roadmap.md。

    组件数据集准备不共享生产选择策略¶

    training/src/assemblyvision_training/prepare_components.py 加载未经验证的 权重，使用固定置信度设置，并选择最大的产品框 当检测到多个产品时。这可以根据不同的标签裁剪标签 来自运行时管道的对象。

    需要经过验证的产品清单并重用运行时产品检测器 选择策略，包括单一产品处理和清单派生 推理设置。失败或产生明确的排除清单 不明确的样本。

    相关参考：docs/design/19-training-and-evaluation.md、 docs/design/08-product-detection-and-roi.md和ADR-004。
