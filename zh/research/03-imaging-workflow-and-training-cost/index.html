    研究3：固定线路巡检的成像工作流程、数据实践和培训成本¶

    状态：AssemblyVision 项目的研究综合（固定 4MP 工业相机、固定照明、大型部件的存在检查、300-800 个图像目标）。 编译日期：2026-08-04 诚实惯例：照明/相机指南引用自已发表的工程参考文献（康耐视、维基百科/MV 文献）。 无法固定到可引用来源的培训时间和标签时间数字明确标记为“从业者估计”。成本数字在很大程度上取决于本地硬件，并且是范围，而不是保证。

    1. 目的¶

    本文档提供了 AssemblyVision (a) 固定线检测的成像规范和最佳实践，(b) 标准数据工作流程（收集 SOP、标签标准、分割、质量门），以及 (c) 有关培训成本、数据集大小和常见故障的从业者证据 - 以及直接映射到 AssemblyVision 设计集的实用检查表。

    2. 固定线路检测的成像规范和最佳实践¶

    2.1 照明是主导因素¶

    供应商与工程界的共识是明确的：“照明不佳是机器视觉性能不佳的最常见原因。即使是复杂的相机和软件也无法弥补照明不足。”良好的照明可以最大限度地提高感兴趣特征的对比度，并最大限度地减少其他地方的对比度，并且它必须一致，以便正常零件变化不会改变图像对比度（https://www.cognex.com/en/tools-and-resources/resource-center/machine-vision/the-importance-of-lighting）。

    2.2 照明系列（以及何时使用它们）¶

    类型 几何 最适合 AssemblyVision 注释
    戒指/低角度戒指 透镜周围的圆形LED 平坦、哑光部件上的均匀明场；一般存在检查 从上方观察哑光塑料/金属组件的良好默认设置
    酒吧灯 线性 LED 灯带 更大的面积、更宽的视场或高部件的角度照明 考虑填充 4MP 框架的大型产品
    圆顶（漫射）照明 环上的漫射器，“阴天”光 弯曲或闪亮的表面；抑制反射 如果产品具有光泽表面或可见反射，则为首选
    同轴（轴向）照明 光通过分束器沿光轴注入 平坦的镜面表面；阅读低对比度功能 平面部件面的有力候选者；如果对齐漂移，可能会引入镜面反射热点
    背光 目标后面的漫射光 轮廓、边缘/计数、尺寸检查 不适用于位于背景可见的传送带上的产品，除非生产线允许使用背板
    暗视野/低角度 浅角度的侧面光线 表面纹理、划痕、压花、高度变化 对于平坦表面上的划痕/压花检测非常有用
    明场/全照明 来自上方的光线反射到相机中 扁平件；平面特征上的高对比度 最常见的默认
    多光谱/红外 特定颜色或红外 LED 抑制繁忙的背景或色彩噪声；在具有挑战性的环境光下工作 如果可见光反射不可避免，则可能有后退方案

    来源：https://www.cognex.com/en/tools-and-resources/resource-center/machine-vision/the-importance-of-lighting； https://en.wikipedia.org/wiki/Machine_vision（设备和成像部分）。

    2.3 滤光片和眩光控制¶

    • 偏振滤光片（相机侧和/或光侧）“可以消除反射到相机中的光产生的眩光”-金属或闪亮塑料上镜面反射的标准修复（https://www.cognex.com/en/tools-and-resources/resource-center/machine-vision/the-importance-of-lighting）。
    • 彩色/红外/紫外线滤镜可以提高对比度或阻挡不需要的环境光。在受控站中，排除环境光的外壳通常比依赖过滤器更简单。
    • 工程指南中将玻璃和反射表面称为“受控照明很重要，因为反射可能看起来与真实缺陷相似”的情况 (https://blog.roboflow.com/surface-defects/)。

    2.4 曝光、光圈、景深和运动¶

    • 运动模糊规则： 图像必须冻结产品。对于移动传送带，曝光时间必须足够短，以使曝光期间的物体位移仅为像素的一小部分（或使用频闪/全局快门相机）。工业相机通常对移动部件使用全局快门（维基百科的机器视觉设备部分列出了同步曝光（“适合移动过程”）作为关键区别：https://en.wikipedia.org/wiki/Machine_vision）。
    • 光圈和景深： 选择光圈（光圈值），以便整个产品高度范围都处于焦点；较小的光圈会增加景深，但会减少光线，需要更多的照明或更长的曝光时间（这有模糊的风险）。有一个经典的贸易三角：曝光时间/光圈/照明强度。
    • ISO/增益： 保持模拟增益/ISO 较低，以最大限度地减少噪音；添加光而不是增益。 （一般成像工程实践；不依赖于单个引用 - 视为来自上述相同 MV 文献的标准知识。）
    • 过度曝光/泛光：镜面高光会使传感器饱和并冲掉特征边缘。直方图检查（例如，最大平均亮度限制）属于质量门（AssemblyVision 已在 [docs/design/06-ai-detection-pipeline.md](../design/06-ai-detection-pipeline.md) 中指定最小/最大平均亮度和拉普拉斯方差）。

    2.5 相机安装、角度和平稳性¶

    • 固定、隔振安装。 工程指南的环境部分将振动、温度变化和污染物标记为破坏视觉系统的首要环境风险 (https://www.cognex.com/en/tools-and-resources/resource-center/machine-vision-considerations-implementation)。
    • 角度： 单个固定角度是正确的设计（AssemblyVision [docs/design/19-training-and-evaluation.md](../design/19-training-and-evaluation.md) 指出约 45 度的角度变化是需要重新验证的域变化）。近乎垂直的自上而下视图最大限度地减少了透视失真并使 ROI 坐标稳定。
    • 视野： 设置 FOV，以便产品占据框架的一致部分（AssemblyVision 的 stage-1 最小框面积比在 [docs/design/08-product-detection-and-roi.md](../design/08-product-detection-and-roi.md) 中为 0.15）；验证生产捕获的实际位置带和剪辑范围。
    • 稳定性/触发： 硬件光电眼或 PLC 触发优于时间窗口（根据 [docs/design/07-camera-and-image-acquisition.md](../design/07-camera-and-image-acquisition.md)）；确保产品静止或在传送周期中的确定点进行曝光选通，以便每个帧都具有可比性。

    2.6 AssemblyVision 成像检查表（直接应用）¶

    1. 针对特定产品材料使用圆顶或同轴漫射装置；首先将测试环/明场作为基线（康耐视指南：“没有一种适合所有应用的最佳照明设置”）。
    2. 将工作站封闭或遮挡环境光；验证整个班次的一致性。
    3. 如果任何组件面是镜面的，请添加偏振。
    4. 将曝光设置为定格运动（全局快门/频闪）；目标低 ISO/增益；调整全高度景深的光圈。 5、相机安装牢固；记录应用的设置和序列号（按照[docs/design/07-camera-and-image-acquisition.md](../design/07-camera-and-image-acquisition.md)）。
    5. 从真实的制作捕获中校准帧质量门（模糊、亮度、眩光），包括空的、模糊的、黑暗的、明亮的和反射的场景（根据 [docs/design/07-camera-and-image-acquisition.md](../design/07-camera-and-image-acquisition.md) 第 7.9 节）。
    6. 在最终确定阈值之前收集正常班次的校准和漂移数据。

    3. 标准工作流程和程序¶

    3.1 数据采集SOP（Ultralytics+Roboflow+AssemblyVision的综合）¶

    Ultralytics 的官方指南强调 “数据的质量直接决定模型性能” 并涵盖类定义、来源和偏差避免 (https://docs.ultralytics.com/guides/data-collection-and-annotation/)。 Roboflow 的工业演练添加了特定领域的覆盖规则 (https://blog.roboflow.com/surface-defects/)。

    推荐标准操作流程：

    1. 定义版本化类本体（产品 + 所需组件），包含包含/排除规则和歧义策略（AssemblyVision [docs/design/19-training-and-evaluation.md](../design/19-training-and-evaluation.md) 第 19.5 节）。
    2. 使用生产相机/光学器件/安装/照明收集，而不是手机或其他相机。应保留固定角度设置以供训练和部署。
    3. 覆盖范围必须包括： 所有产品/组件；跨批次/日期的真正合格产品；为每个缺失的组件物理构建 NG 产品（不要通过数字擦除来合成所有 NG - 阴影、包装变形和显示的背景有所不同）；空帧；部分条目；模糊;反思；曝光变化；遮挡（AssemblyVision [docs/design/19-training-and-evaluation.md](../design/19-training-and-evaluation.md) 第 19.4 节；https://blog.roboflow.com/surface-defects/ 中的相同覆盖主题）。
    4. 包括负片/背景图像 - “正常图像也很重要。它们教导模型普通颗粒、颜色变化和无害的表面图案不应总是被归类为缺陷”(https://blog.roboflow.com/surface-defects/)。
    5. 每张图像的出处： 场地/生产线/相机/设置、捕获会话、产品实例、故意缺陷场景和相机/照明修订（AssemblyVision [docs/design/19-training-and-evaluation.md](../design/19-training-and-evaluation.md) 第 19.3 节）。

    3.2 标签标准和工具¶

    • 注解规则：一致的类名；可见特征周围的紧密框（“包含大部分法线表面的大框会使模型更难学习”）；注释每个实例；决定并记录相关/重叠的案例；所有 NG 和不明确标签的第二位审阅者（https://blog.roboflow.com/surface-defects/；AssemblyVision [docs/design/19-training-and-evaluation.md](../design/19-training-and-evaluation.md) 第 19.5 节）。
    • 注释类型/格式：用于检测的边界框； COCO/VOC/YOLO 格式； YOLO 格式已标准化 (https://docs.ultralytics.com/guides/data-collection-and-annotation/)。
    • 工具：
    • CVAT - 开源、团队工作流程、自动分段：https://github.com/cvat-ai/cvat
    • Label Studio - 开源、多任务标签：https://github.com/HumanSignal/label-studio
    • LabelImg - 经典的轻量级边界框工具：https://github.com/HumanSignal/labelImg
    • Roboflow Annotate - 托管、模型辅助标记、数据集版本控制、导出到 YOLO/COCO：https://blog.roboflow.com/missing-item-inspection/ 和 https://blog.roboflow.com/roboflow-train-3-0/
    • Ultralytics 注释编辑器（平台） - SAM 支持的智能注释，原生 YOLO 格式：https://docs.ultralytics.com/guides/data-collection-and-annotation/
    • 标记效率策略：明确的指南、预注释工具、主动学习（首先标记信息最丰富的样本）、批量处理相似图像、定期质量检查（https://docs.ultralytics.com/guides/data-collection-and-annotation/）。

    3.3 数据集组织和训练/验证/测试分割¶

    • 对每个数据集进行版本控制（校验和、注释哈希、本体版本）并将原始数据视为不可变（AssemblyVision [docs/design/19-training-and-evaluation.md](../design/19-training-and-evaluation.md) 第 19.3/19.5 节）。
    • 泄漏安全拆分是最重要的拆分规则： 按物理产品实例拆分，最好按捕获会话/批次/日期拆分； 永远不要随机分割相邻的视频帧，因为几乎相同的帧会泄漏并导致指标膨胀（AssemblyVision [docs/design/19-training-and-evaluation.md](../design/19-training-and-evaluation.md) 第 19.6 节）。计划开始：2015 年 70 月 15 日，按分组实例进行训练/验证/内部测试，并完全保留客户验收集。
    • 运行泄漏检查： 精确的 SHA-256 重复项、感知哈希最近邻、组 ID 重叠、派生文件沿袭（AssemblyVision 第 19.6.3 节）。

    3.4 质量门¶

    • 推理时的帧级门：模糊（拉普拉斯方差）、亮度范围、损坏、帧年龄；被拒绝的帧没有提供任何积极的证据（AssemblyVision [docs/design/06-ai-detection-pipeline.md](../design/06-ai-detection-pipeline.md) 和 [docs/design/07-camera-and-image-acquisition.md](../design/07-camera-and-image-acquisition.md)）。
    • 数据集级门：自动检查无效框、未知类、重复项；第二审稿人抽样；注释者间协议（https://docs.ultralytics.com/guides/data-collection-and-annotation/）。
    • 模型级门：评估精度、召回率、mAP、混淆矩阵、误报/阴性、小缺陷性能以及对正常图像的预测； “对于关键类别，召回可能比使用非常高的置信度阈值更重要”（https://blog.roboflow.com/surface-defects/）。

    4. 培训费用和从业人员经验¶

    4.1 人们实际需要多少图像？¶

    公共指导故意广泛，因为它取决于任务难度：

    • 非常简单的单类检测（固定对象的存在/计数）： Roboflow 的缺失项目教程建议 从一个对象类的 25-50 个图像开始 (https://blog.roboflow.com/missing-item-inspection/)。
    • 开始实验的一般指导：“每个类几百个带注释的对象足以开始尝试迁移学习，但为了获得可靠的实际性能，Ultralytics 建议每个类至少 1,500 个图像和 10,000 个标记实例”(https://docs.ultralytics.com/guides/data-collection-and-annotation/)。
    • AssemblyVision 自己的目标： 每个组件类约 300-800 个产品图像（一类）和约 300-500 个标记实例以及物理构建的缺失组件场景（根据 [docs/design/19-training-and-evaluation.md](../design/19-training-and-evaluation.md)）。这介于“启动时的几百个”和“可靠性为 1,500 / 10,000”的指导之间。考虑到固定站、单一产品类型和大型组件，较低的结果是合理的，但必须根据经验进行验证——“可靠的现实世界”指导来自供应商对不同定制数据集的概括。

    4.2 训练时间和计算¶

    • Ultralytics 参考时间表： 从 300 epoch 左右开始；如果早期过度拟合则减少，如果没有过度拟合则延长至 600-1200+；使用早期停止（耐心）、预训练权重（迁移学习）、混合精度 (AMP) 和子集训练进行迭代 (https://docs.ultralytics.com/guides/model-training-tips/)。
    • 托管训练： Roboflow Train 默认为 100 个 epoch，支持从 COCO 检查点进行训练，NAS 自动训练 10-100 个候选模型（https://blog.roboflow.com/roboflow-train-3-0/）。 Roboflow 的 PCB 演练报告称，对于分叉数据集“训练需要几个小时”(https://blog.roboflow.com/pcb-defect-detection/)。
    • 从业者的估计（明确标记，不是来自单个可引用的基准）：
    • 单个现代消费者/数据中心 GPU 上的 数百个图像 上的纳米/小型 YOLO 通常在 分钟到约 1 小时内收敛，持续 100-300 个周期。 Roboflow 的“几个小时”是托管管道的安全规划数字。
    • 在从业者论坛中，对于经验丰富的注释者来说，边界框的标记时间通常约为每个实例 1-3 秒（每个图像需要几分钟，有多个实例）。 这是一个估计值；根据您自己的数据进行测量。
    • 对于 AssemblyVision 规模（几百个图像，3-5 个类），总的人工标记工作实际上约为小时到 1-2 人天，并且云 GPU 上的计算成本很小（对于小型模型最多需要数十个 GPU 小时）。将这些视为计划范围，而不是承诺。

    4.3 常见故障和提示（引用的从业者材料的综合）¶

    1. 照明不佳/不一致是第一大故障（康耐视：“照明不佳是机器视觉性能不佳的最常见原因” - https://www.cognex.com/en/tools-and-resources/resource-center/machine-vision/the-importance-of-lighting）。
    2. 视频帧中的数据泄漏会夸大验证指标并误导阈值选择（AssemblyVision 第 19.6 节；这是整个社区众所周知的陷阱）。
    3. 真实的 NG 示例太少 - 合成数字擦除不会再现阴影/背景变化（AssemblyVision 第 19.4 节）。
    4. 注释者之间和跨天的标签漂移/不一致的框；修复冻结本体版本、示例、审查抽样和裁决（AssemblyVision 第 19.5 节；https://docs.ultralytics.com/guides/data-collection-and-annotation/）。
    5. 过度信任 mAP - 选择验证时召回的阈值并在冻结阈值下进行评估（https://blog.roboflow.com/surface-defects/；AssemblyVision 第 19.9 节）。
    6. 集成失败是真正的杀手 - 约 77% 的制造视觉试点因集成而停滞，而不是模型质量 (https://blog.roboflow.com/scale-a-computer-vision-pilot-to-products/)。 AssemblyVision 的设计（本地优先、离线功能、人工审查、证据持久性）旨在解决这一问题。
    7. 过于激进地开始增强可能会扭曲薄特征（例如，剪切扭曲划痕/裂纹 - https://blog.roboflow.com/flanges-uality-inspection/）。将增强限制在物理上合理的变化范围内（AssemblyVision 第 19.7 节）。
    8. 置信度分类（通过/审核/失败范围）减少错误的自动决策，并将审核流反馈到训练中 - 直接适用于 AssemblyVision 的低置信度 UNCERTAIN 处理（https://blog.roboflow.com/flanges-uality-inspection/；AssemblyVision BR-006）。

    4.4 迭代周期¶

    从业者材料一致地描述了短、反馈驱动的周期：在默认设置下运行第一个模型，检查误报/阴性，添加信息最丰富的错误分类/不确定图像，重新标记，重新训练（https://blog.roboflow.com/surface-defects/；https://blog.roboflow.com/flanges-uality-inspection/）。主动学习循环（上传低置信度预测以供审查和再培训）是一种标准生产模式，符合 AssemblyVision 的人机交互和生产监控要求（[docs/design/19-training-and-evaluation.md](../design/19-training-and-evaluation.md) 第 19.14 节）。

    5. AssemblyVision 实用清单¶

    5.1 成像站清单（数据收集前）¶

    • [ ] 选择圆顶或同轴漫射照明并制作原型；环/明场基线测试
    • [ ] 偏振器可用/已针对镜面组件面进行测试
    • [ ] 排除环境光（外壳/护罩）
    • [ ] 全局快门/频闪配置设置；在最大传送带速度下验证运动模糊
    • [ ] 孔径/自由度覆盖整个产品高度范围；增益/ISO 保持较低水平
    • [ ] 相机牢固安装；应用的设置+串行记录（根据[docs/design/07-camera-and-image-acquisition.md](../design/07-camera-and-image-acquisition.md)）
    • [ ] 根据真实捕获校准帧质量门（模糊、亮度、眩光）
    • [ ] 触发（光电眼/PLC）去抖动和产品窗口边界验证
    • [ ] FOV/位置带根据阶段 1 最小框面积和 ROI 边距进行验证

    5.2 数据收集清单¶

    • [ ] 使用精确的生产相机/光学器件/灯光/软件进行收集
    • [ ] 涵盖所有产品、所有组件，跨批次/日期真正OK
    • [ ] 为每个缺失的组件和缺失的手册物理构建 NG 案例
    • [ ] 包括空帧、部分条目、模糊、反射、曝光变化、遮挡
    • [ ] 记录每张图像的出处（站点、线路、摄像机、会话、产品实例、场景）
    • [ ] 目标：~300-800 张产品图片； ~300-500 个实例/组件；每个缺失场景启动约 100 个产品实例（AssemblyVision 第 19.2 节）
    • [ ] 冻结带有校验和的数据集版本和本体版本

    5.3 注释清单¶

    • [ ] 锁定、版本化的类本体，具有包含/排除和歧义规则
    • [ ] 一致的紧密盒子；每个实例都带有注释；记录连接/重叠规则
    • [ ] 自动检查（无效框、未知类、重复项）
    • [ ] 所有 NG 和不明确标签的第二位审稿人；裁决日志
    • [ ] 跟踪每类计数、产品实例、会话、批次（仅帧计数就夸大了多样性）

    5.4 拆分和评估清单¶

    • [ ] 按产品实例/会话/批次/日期进行防泄漏分组（绝不随机帧分割）
    • [ ] 2015 年 70 月 15 日计划按分组实例划分；客户验收集完全保留
    • [ ] 运行 SHA-256 + 感知哈希 + 组 ID 泄漏检查
    • [ ] 报告 NG 召回、FN/FP 率、每个组件召回、产品检测和 ROI 成功、延迟 (AssemblyVision QA-012)
    • [ ] 选择验证阈值，漏检 NG 成本更高；测试/验收前冻结

    5.5 培训和成本规划清单¶

    • [ ] 从 COCO 预训练的权重开始；约 300 个周期默认提前停止
    • [ ] 预算计算：数百个图像的小型模型在几分钟到几小时内收敛（每个 Roboflow 的托管管道“几个小时”）
    • [ ] 预算标签：AssemblyVision 规模的小时数为 1-2 人天（估计 - 当地测量）
    • [ ] 在完整运行之前运行子集训练（例如 10% 分数）以实现快速迭代 (Ultralytics)
    • [ ] 跟踪运行出处：源版本、容器摘要、种子、数据集版本、超参数、工件校验和（AssemblyVision 第 19.8 节）

    6. 开放式问题和需要验证¶

    • 在承诺标签预算之前，测量实际组件的实际标签率（每盒秒数）；公布/估计的费率差异很大。
    • 确认300-800张产品图片是否足以对实际产品进行第一阶段产品检测；与 Ultralytics 在固定单一产品站上的“每类约 1,500 个图像/10,000 个实例”可靠性指南进行比较。
    • 在真实零件上选择照明解决方案并进行原型设计（圆顶、同轴、环形+偏振）；没有供应商来源可以选择它来完成特定的产品。
    • 根据实际传送带速度和产品停留时间验证运动模糊和曝光要求；确定是否需要频闪/全局快门配置。
    • 在最终确定产品窗口策略之前确认触发器可用性（光电眼/PLC/条形码定时）和稳定性。
    • 确定从设计默认值中选择的质量门阈值（拉普拉斯方差、亮度）对于真实相机和照明是否正确。
    • 建立客户接受样本量和二项式置信界限，以进行 NG 召回，观察到的遗漏为零或很少（根据 [docs/design/19-training-and-evaluation.md](../design/19-training-and-evaluation.md) 第 19.13 节）。
    • 在团队实际训练硬件上验证 GPU/CPU 训练时间；此数据集大小的云 GPU 小时成本预计会很小，但此处未进行测量。
