    08 — 相机源和视觉核心¶

    图像采集、ROI 引擎和模型清单如何工作 packages/python/vision-core (assemblyvision_vision)，以及如何添加新的 相机来源。

    FrameSource协议¶

    每个采集源都实现此协议 (sources/frame_source.py):

    class FrameSource(Protocol):
    def open(self) -> CameraCapabilities: ...
    def configure(self, settings: CameraSettings) -> AppliedSettings: ...
    def frames(self, stop: Event) -> Iterator[CapturedFrame]: ...
    def close(self) -> None: ...

    CapturedFrame（冻结数据类，eq=False）： monotonic_ts_ns（整数）、wall_clock_utc（日期时间）、sequence（整数）、 pixel_format (str)、status (str)、image (PIL RGB)，以及可选 product_identity和multi_product（由身份相关器标记）。

    故障安全规则：读取/解码失败引发 FrameStreamError — 帧 永远不会默默地跳过（ADR-013）。原始缓冲区永远不会默默无闻 重新解释；不支持的格式在检查前失败。

    实施来源¶

    来源 班级 配置字段 笔记
    文件夹 FolderSource path、loop、fps 确定性排序迭代；支持 .jpg .jpeg .png .bmp .tif .tiff .webp
    视频 VideoFrameSource path、fps、loop OpenCV VideoCapture，寻找 0 进行循环
    opencv 设备 OpenCVCameraSource device（索引或/dev/videoN）、fps、width、height、reconnect 有界指数退避重新连接（ReconnectPolicy 250 ms → 10 s）；还有虚拟摄像机（v4l2loopback、OBS）
    rtsp RTSPFrameSource url (rtsp:///rtsps://)、fps、reconnect PyAV 主要 (rtsp_transport=tcp)，OpenCV 后备
    http 图像 HttpImageSource url (http(s)://)、fps、timeout_seconds httpx 轮询；重试瞬时传输失败，无法解码的内容导致源故障
    吉格视觉 GigEVisionFrameSource serial、gentl_producer、trigger_mode、pixel_format、exposure_us、gain_db、packet_size、fps、width、height、reconnect GenICam/GenTL 通过 Harvester + 供应商 .cti；串行绑定（从不 IP）；仅 Mono8/RGB8/BGR8 确定性转换；通过回读验证节点映射配置；仅限 Linux/Windows（macOS gige extra 解析为空）

    惰性后端助手（_opencv.py、_av.py、_harvester.py）提高明确 当可选时询问匹配 vision-core[extra] 时出错 缺少依赖性。

    工厂¶

    sources/factory.py — SourceType = Literal["folder", "video", "opencv-device", "rtsp", "http-image", "gige-vision"]； build_frame_source(config: FrameSourceConfig) -> FrameSource 验证 每个源类型所需的字段并构造源。工厂是 从 assemblyvision_edge.config._parse_camera_source 调用（边缘配置） 和实例管道构建。

    添加新的相机源¶

    1. 创建实现FrameSource协议的sources/your_source.py。
    2. open() 返回 CameraCapabilities （源暗淡、fps、像素格式、 序列号/型号/固件/GenTL 生产者（如果有）。
    3. frames(stop) 产生带有单调 + UTC 时间戳的 CapturedFrame， 序列、暗淡、像素格式、状态、PIL RGB 图像；提高 FrameStreamError 解码失败（从不跳过）。
    4. 实现有界重新连接（参见ReconnectPolicy） sources/reconnect.py）。
    5. 如果供应商 SDK 是可选的，则通过 _your_backend.py 延迟加载它 helper 并在 pyproject.toml 中添加 vision-core[your-extra] 额外内容 （镜像_harvester.py）。 2.注册源类型：
    6. sources/factory.py：添加到SourceType，扩展build_frame_source， 并验证必需的 FrameSourceConfig 字段。
    7. assemblyvision_edge/config.py _SOURCE_TYPES + _parse_camera_source 验证以便 YAML 配置接受它。 3.连线管道：边CameraSourceManager只需要一个FrameSource — 没有其他运行时变化。
    8. 在现有的packages/python/vision-core/tests/中添加测试 模式：通过注入假后端 monkeypatch.setattr(_your_backend, "_module", FakeModule)（没有真正的 需要硬件），并断言重新连接、停止语义、解码失败 故障安全和工厂验证。
    9. 更新文档：设计 07，ADR-013 式决策（如果更改） 建筑学和本手册。

    投资回报率引擎¶

    roi/roi_engine.py：

    • ROIConfig（冻结数据类）：margin_x_ratio=0.05， margin_y_ratio=0.05、min_area_pixels=250_000、 min_expanded_area_retained=0.90，normalize_perspective=False。 构造函数因无效边距/区域/保留而引发 ROIGenerationError 或 normalize_perspective=True （不受 MVP 支持）。
    • ROIEngine.generate(frame, frame_id, product_box) -> GeneratedROI： 按边距扩展 → 裁剪到框架 → 拒绝 (ROI_INVALID) 剪切区域 < min_area_pixels 或 retained_fraction < min_expanded_area_retained → 裁剪 → 构建 ROIResult transform_full_to_roi（仅翻译）。

    roi/geometry.py（纯，无 I/O）— Box（xyxy + 区域）、expand、clip、 retained_fraction、translation_transform、inverse_transform、 apply_transform。这与使用的转换代码相同 training/prepare_components.py 因此数据集准备和运行时推理共享 精确的坐标语义。

    模型清单 (manifests.py)¶

    • load_model_manifest(path) -> ModelManifest：JSON → Pydantic (extra="forbid")，需要runtime == "ultralytics"，否则ConfigError。
    • verify_manifest_artifact(manifest, manifest_path) -> Path：解决 仅第一个工件； URI 必须是相对的（没有前导 /，没有 :// 方案，无驱动段）；解析的路径必须保留在模型内 捆绑根（清单目录的父目录，符号链接安全）；文件必须存在； size_bytes 和 SHA-256 必须匹配 — 否则 ConfigError。这允许 记录的 models/manifests + 同级 models/weights 布局。
    • verify_model_class_map(names, manifest)：Ultralytics model.names 必须 连续的 0..n-1 且在顺序上完全等于 class_names。
    • model_version_label(task, semver): product-yolo-<semver> / component-yolo-<semver>； manifest_model_version(manifest) 推导出 用于 pipeline.yaml model_version 声明的规范标签。

    添加新的组件类（无需更改代码）¶

    新的组件类是配置数据，而不是代码：

    1. 组件检测器必须经过培训（参见 09-training-and-datasets.md）及其清单 class_names 已更新。 2.pipeline.yaml→component_detection.components.<code>: {observation_threshold: <t>}。
    2. product-rule.yaml → 添加<code>: {expected_count: 1} required_components，并确保清单标签位于 compatible_component_model_versions。
    3. 验证：管道加载拒绝从任一管道中丢失的组件 配置或清单；在加载时检查规则/组件兼容性。
