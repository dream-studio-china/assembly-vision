    07 — 数据库和持久性¶

    SQLite 如何存储、迁移、存储库、上传发件箱和保留 工人的工作，以及如何扩展它们。

    架构（SQLite、WAL 模式、外键打开）¶

    apps/edge-service/src/assemblyvision_edge/persistence/ schema.py中定义的表：

    表 目的 重点栏目
    inspections 每次检查的不可变投影 inspection_id、device_id、device_sequence、生命周期、时间戳、条形码/产品解析、内部/业务决策、模型/规则版本 + 校验和、原因 JSON、延迟、synchronization_status
    component_evidence 每个组件的汇总证据 inspection_id FK、component_code、状态、置信度/计数、原因 JSON
    media 媒体元数据（磁盘上的字节） media_id、inspection_id FK、kind、relative_path、mime、size_bytes、checksum_sha256、生命周期 + 保留字段 (E2)、保留/声明/租赁/屏蔽/清除列、integrity_status
    upload_tasks 耐用的发件箱 upload_task_id、device_id、inspection_id、kind、object_id、payload_hash、idempotency_key、status、checksum_sha256、attempt_count、next_attempt_at、last_error_code、时间戳、lease_owner、lease_expires_at
    device_events 仅附加事件 发生时间、严重程度、代码、详细信息 JSON、上传状态
    active_packages 安装/激活的模型/规则包 版本 ID、清单 JSON、路径、校验和、状态
    rule_identities 持久规则身份注册 (rule_id, rule_version) 唯一，content_sha256 — 重用具有不同内容的身份无法加载 (CONFIG_INVALID)
    review_records 仅附加人工评论（迁移 0008） review_id、inspection_id FK、处置、原因/注释/审阅者、原始决策快照、组件更正 JSON、supersedes_review_id

    索引（最小值，合同 05 §4）：条形码、检验时间戳、决定、 产品类型、设备 ID、型号版本、上传状态 — 以及 设计14.5中的操作索引（例如upload_tasks(state, next_attempt_at)）。

    迁移（蒸馏器）¶

    • 迁移位于apps/edge-service/migrations/中；头部修订链 在 review_records 迁移 (0008) 处结束。
    • persistence/migrate.py 在每个打开的数据库上运行迁移 进程+进程间（flock）序列化和修订验证； 荣誉AV_EDGE_ROOT。

    添加迁移 — 模板¶

    cd apps/edge-service
uv run alembic revision -m "add your_table"   # or write it manually following the chain

    迁移文件（现有文件的框架）：

    """add your_table

Revision ID: <head+1>
Revises: <current head>
Create Date: ...
"""
from alembic import op
import sqlalchemy as sa

revision = "<head+1>"
down_revision = "<current head>"


def upgrade() -> None:
    op.create_table(
        "your_table",
        sa.Column("id", sa.String(length=36), primary_key=True),

        # ... define all columns; text CHECKs for enum-like strings where used

    规则： - 每次架构更改都是一次迁移；生产模式永远不会被编辑 手动。编写经过测试的升级/降级（该套件具有迁移测试 打开新的+迁移的数据库）。 - 更新persistence/schema.py表定义以匹配。 - 如果新数据通过 API 公开，请更新 schemas/OpenAPI/TS 和 contract.test.ts 模式断言。 - 新查询路径所需的索引（合同 05 §4 + 设计 14.5）。

    存储库模式（persistence/repository.py、EdgeRepository）¶

    • 通过 EdgeRepository.open(path) 打开（运行迁移 + PRAGMA quick_check，因损坏而关闭失败）。
    • 原子投影 + 发件箱：persist_inspection_and_enqueue_uploads(record, retention=...) 更新插入检查、证据、媒体行和队列 每个工件中的一个 INSPECTION 任务 + 一个 MEDIA 任务 ** 在单个任务中 事务**（SQLite BEGIN；短写事务）。
    • CAS 状态转换 + 防护：终端/重试更新需要 匹配 lease_owner 令牌和预期的当前状态，例如 mark_upload_succeeded(task_id, lease_owner, receipt) 返回数字 已更改的行数（0 = 过时的所有者 → 被拒绝）；另外还取得了成功 需要与任务的不可变性相匹配的持久验证收据 字段（幂等键、对象、种类、大小、校验和）。
    • 立即交易序列化：submit_review解析 supersedes_review_id 在 BEGIN IMMEDIATE 下链接所以并发 提交链呈线性（不会丢失更新）。
    • 启动协调（persistence/reconcile.py）：导入CLI inspection.json 幂等地捆绑，隔离陈旧的暂存和 格式错误/不安全的包，运行 scan_storage_integrity （有界采样的存在/大小/校验和），以及 media_path_is_safe 拒绝遍历/符号链接转义。

    上传发件箱 + 调度程序 (upload/scheduler.py)¶

    • UploadScheduler 清空发件箱：立即领取到期任务 每个任务租约下的交易 + 隔离令牌； MEDIA 任务变成 仅在其检查任务持有经验证的成功收据后到期 （元数据始终先于媒体）。
    • 故障分类：传输错误和408/429/5xx→全抖动 遵循Retry-After的指数退避；当地证据丢失/损坏 和服务器 409 冲突 → PERMANENT_FAILURE 与本地证据 保存下来。
    • 验证收据：仅当有界打字收据时，2xx 才是成功 回显有效负载的幂等键、对象、种类、大小和校验和 已发送；媒体收据还需要一个中央对象 ID。
    • 接收器：HttpUploadSink（HTTPS POST 到{base_url}/inspection-uploads； dev HTTP 仅环回）和 DirectoryUploadSink （本地/dev，幂等 键）。没有配置目的地 → 工作人员保持禁用状态并执行任务 在 /api/v1/uploads 中保持可见。
    • 同一模块中的 E3 附加功能：令牌桶带宽限制器、电路 断路器（连续可重试故障→打开→半开探头），以及 POST /api/v1/uploads/{id}/retry 后面的手动重试路径。

    保留人员（retention/worker.py、policy.py、storage.py）¶

    • 资格：检查SYNCED（每项任务收据均已验证）+媒体 带有中央对象 ID 的收据 + 保留期限已过 + 否 保持/故障/清除/删除状态。
    • RetentionCleanupWorker：在进程间 SQLite 下声明候选者 租赁时每件物品都有围栏；重新验证完整谓词 破坏性 I/O 之前；通过 O_NOFOLLOW 目录取消链接 文件描述符（并发符号链接交换不能删除外部文件 检查包）；丢失文件 → 完整性错误，绝不错误 清洗；失败取消链接可重试和可观察。
    • 没有经过批准、启用的策略 (AV_EDGE_RETENTION_ENABLED=true + AV_EDGE_RETENTION_DURATIONS)，worker执行零文件系统 突变。
    • observe_storage 计算 PressureMode (NORMAL/WARNING/CRITICAL/STOP) 来自空闲字节 + inode 与严格排序的阈值 (stop < critical < warning); storage_write_fault 锁存器并且仅 通过 probe_persistence 清除（探测文件 + fsync + BEGIN IMMEDIATE 写）。
