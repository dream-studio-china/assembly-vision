    05 — 边缘服务内部结构¶

    运行时的实际工作原理（逐个功能）。所有路径相对于 apps/edge-service/src/assemblyvision_edge/。

    图像如何成为检查记录（inspect）¶

    1. cli._run_inspect → _open_durable_rule_registry(output) 打开 EdgeRepository.open(output / "edge.sqlite3")（持久规则身份 注册表，与serve共享；如果无法打开则失败关闭）。
    2. _build_pipeline 加载配置+规则+清单和验证： validate_model_version_declaration （声明 model_version 必须等于 清单标签）和 validate_rule_component_compatibility （每个 配置中存在规则所需的组件；组件清单版本 位于 compatible_component_model_versions 中； barcode_required 规则 需要启用+必需的 identity.barcode 配置）。探测器已建成 来自清单。
    3. 对于每个(source, path)：pipeline.inspect_image(source, path, writer)。

    InspectionPipeline._inspect_impl (pipeline.py:536) — 核心流程：

    1. 生成inspection_id、frame_id、started_at（UTC）。 2._detect_frame(frame, frame_id)：
    2. product_detector.detect(frame, frame_id)； DetectionError → 附加其 reason_code（例如INFERENCE_ERROR）；没有选择 → NO_PRODUCT。
    3. 出处检查_validate_product_provenance：detection.frame_id == frame_id、model_version_id == manifest.model_version_id和盒子 尺寸与框架匹配 — 任何不匹配 → INFERENCE_ERROR。
    4. roi_engine.generate(frame, frame_id, product_box)；失败 → ROI_INVALID；成功设置门 roi_valid=True。
    5. component_detector.detect(roi_image, frame_id, required_components, transform_full_to_roi, frame_size)。
    6. 组件出处检查：转换必须是纯翻译， 每个观察 frame_id/model_version_id 必须匹配，roi_bbox size == ROI 大小，full_frame_bbox size == 帧大小，以及 apply_transform(roi_box, inverse) == full_frame_box之内 _COORD_TOLERANCE = 1e-6 — 否则观察值下降 + INFERENCE_ERROR。 3._build_evidence(observations, gates, frame_readable, frame_id)： 每个所需组件→ PRESENT（命中），MISSING（有效推论，无 点击数、COMPONENT_MISSING 政策原因）或 UNCERTAIN (COMPONENT_UNVERIFIABLE) 当推理无效时。 4、身份：identity_verified = identity.verified if identity else not rule.barcode_required；未经验证的身份添加 PRODUCT_IDENTITY_UNVERIFIED。
    7. rule_engine.evaluate(context, rule) — 任何提出的 RuleEvaluationError → 额外原因RULE_EVALUATION_ERROR， decided=None。
    8. 失败关闭合并：final_reasons = decided.reasons ∪ extra_reasons； internal = NG if final_reasons else OK； business_result = NG if internal != OK else OK。任何额外原因（读取错误、检测失败、 出处不匹配、未经验证的身份、规则评估错误）强制 NG。
    9. 收集推理元数据（模型、版本、输入大小、延迟、设备、 阈值），构建 InspectionRecord （aggregation_policy_version="single-frame-mvp-1" 对于单帧）， 注释框架（产品框绿色，组件框红色），然后 writer.save(...)。

    OutputWriter.save (output/writer.py:96) — 原子发布： 暂存目录 .staging-<inspection_id>-<uuid> → 写入 key_frame.jpg (KEY_FRAME), product_roi.jpg (PRODUCT_ROI), annotated_frame.jpg (ANNOTATED_FRAME) 通过 temp+fsync+rename (JPEG q90) → 写入 inspection.json (record.model_dump(mode="json"), 缩进 2, sort_keys) → fsync dir → 将 staging 重命名为 <output>/<inspection_id>/ → fsync 父级。 record.media 准确反映了所写内容。重新发布相同内容 检查 ID → OutputError。在临界/停止磁盘压力下，仅OK 样品抑制可选介质； NG 证据和元数据始终存在。

    serve 如何运行实时检查¶

    组合根api/app.py:create_app(settings)： - runtime = EdgeRuntime(settings)；生命周期：打开存储库→创建 RuntimeEventBus(source_id=device_id) → reconcile_output_root + scan_storage_integrity → runtime.load_config(repository)（多实例 load_edge_config，回退到传统的单一管道）→ 可选地启动 UploadScheduler + RetentionCleanupWorker。

    EdgeRuntime.load_instances (api/state.py:170): - 加载边缘配置；每个实例与共享的构建管道 ModelRegistry； device_id = uuid5(_INSTANCE_NAMESPACE, instance_id) 除非配置；构建 IdentityCorrelator(MockTriggerSource(...)) 时 存在 trigger: 块；每个相机build_frame_source(...)（失败 实例是非致命的）；带有 inspection.enabled and pipeline 的实例 订阅有界队列（最大大小 8）并启动守护进程 _inspection_loop。

    捕获线程 (camera_manager.py): source.open() → _capture_loop 迭代 source.frames(stop) → _publish_frame：存储 state.last_frame （预览内存）和inspection_queue.put_nowait(frame)；在queue.Full上 递增 frames_dropped 并设置 degraded=True （显式溢出， 从来没有沉默的损失）。

    _inspection_loop (api/state.py:268) 每次迭代： 1.如果暂停→清空队列，睡眠。 2. refresh_storage() — 锁存器storage_write_fault出现故障。 3. 如果写入错误 → probe_persistence() 仅当发生写入错误时才清除锁存器 SQLite 探针写入和探针文件写入+fsync 均成功。 4. 如果堵塞(write_fault or integrity_fault or mode == "STOP") → 排水， 没有摄入。 5. optional = _optional_capture_suppressed()（紧急/停止模式）。 6.next_frame(instance_id)： - None→window_manager.expire(now)；过期窗口 → inspect_window → _persist_projection。 - 框架→correlator.annotate(frame)印记product_identity；然后 - 颞分支：pipeline.frame_observations(frame) → window_manager.feed(observation, frame.monotonic_ts_ns/1e9) （采集时间单调时钟）；新窗口 → 发布 inspection.started；关闭窗口 → inspect_window → _persist_projection。 - 单帧分支：发布 inspection.started （之前 推理）→ 解析条形码身份（如果启用）→ pipeline.inspect_frame(frame, writer, inspection_id=..., identity=...) → _persist_projection。 7. 关机 → window_manager.force_close() → 中断窗口关闭为 NG 与 INSPECTION_INTERRUPTED （部分证据从未重建）。

    _persist_projection (api/state.py:464): repository.persist_inspection_and_enqueue_uploads(record, retention=...) — 不可变投影的原子更新插入 + 一项 INSPECTION 任务 + 一项 MEDIA 单个事务中每个工件的任务。故障→锁存 storage_write_fault，未发布 inspection.completed 事件。 成功 → 发布 inspection.completed {inspection_id, instance_id, business_result, internal_decision}。

    配置加载和验证门¶

    config.py： - load_pipeline_config → _parse_pipeline_doc：未知的顶级键 被拒绝； product_detection键{model_version, confidence_threshold (default 0.7), iou_threshold (default 0.5)}； component_detection键 {model_version, iou_threshold, components} 与每个组件 observation_threshold（默认0.5）；至少一个组件； roi已建成 进入 ROIConfig （无效几何 → ConfigError）； normalize_perspective=True 被拒绝； identity.barcode {enabled, required, allowed_symbologies, mapping_file} 带有 用于平面精确条形码→产品的重复键拒绝 YAML 加载器 地图。 - load_rule_definition → RuleDefinition.model_validate → _register_rule_identity：进程本地注册表键控 (rule_id, rule_version) 反对规范 JSON 的 SHA-256；重新加载 相同身份不同内容→ConfigError；然后是耐用的 回调到 SQLite rule_identities（如果不匹配则为 RepositoryError）。 - load_edge_config：每个实例的门 - 唯一的instance_id； device_id 解析为 UUID；相机源类型特定的必填字段； fps > 0； reconnect.maximum_delay_ms >= initial_delay_ms； gige-vision 需要 serial + gentl_producer;时间：medium_confidence严格< high_confidence，observation_threshold <= medium_confidence， identity.barcode 被临时拒绝，启用临时检查 需要window_strategy: identity； trigger仅接受 source: mock。 - _build_instance_pipeline 添加 validate_temporal_against_rule（每个规则需要恰好一个策略 组件）。

    规则引擎¶

    rules/rule_engine.py： - rule_version_id(rule) = uuid5(NAMESPACE, canonical JSON) — 任何内容 变化产生新的身份。 - RuleEngine.evaluate(context, rule)（静态，确定性）签入 订单、累积原因（任意原因→NG）： 1. schema_version != 1 → CONFIG_INVALID。 2. 清空required_components→CONFIG_INVALID。 3. component_model_version not in compatible_component_model_versions → VERSION_INCOMPATIBLE。 4. barcode_required and not product_identity_verified → PRODUCT_IDENTITY_UNVERIFIED。 5. 强制登机口：context.gates.get(gate) is not expected → GATE_FAILED:<gate>。 6. 每个组件：缺少证据 → COMPONENT_UNVERIFIABLE:<key>； 状态 != PRESENT → COMPONENT_MISSING|UNCERTAIN|UNVERIFIABLE:<key>; 现有证据不完整 (usable_frame_count < 1, best_confidence is None，非有限置信度，或无支持 帧 ID) → COMPONENT_UNVERIFIABLE; detection_count != expected_count → COMPONENT_COUNT_INVALID; _spatial_violation （缺失/非有限/超出范围面积比或中心外侧 allowed_zone)→COMPONENT_SPATIAL_INVALID。 - InspectionDecision 携带排序的 missing_components， low_confidence_components，排序reason_codes。

    颞窗¶

    temporal/window_manager.py — ProductWindowManager.feed(observation, now_monotonic)： - 过时的水印：早于截止时间的帧将被丢弃（计数），甚至 窗口关闭后（延迟排队的到期前帧无法打开新的 窗口）。 - multi_product → 关闭活动窗口作为完整性违规 (MULTIPLE_PRODUCTS)。 - 身份策略：无活动窗口+无身份→丢弃；被隔离 身份→掉落；主动+身份无→关闭IDENTITY_MISSING;活跃的 + 不同身份 → 关闭IDENTITY_TRANSITION + 打开新的；一样 身份→饲料。 - 间隙：now - last_frame_at >= maximum_window_ms→关闭GAP，打开新的。 - 最长持续时间：身份策略以 MAX_DURATION 结束 (WINDOW_MAX_DURATION_EXCEEDED) 具有身份隔离；时间策略 关闭并打开新的。 - expire(now) 在空闲时像 GAP 一样关闭活动窗口。 - force_close()（关闭）→ INTERRUPTED + INSPECTION_INTERRUPTED， 帧已清除。

    temporal/aggregator.py — TemporalAggregator.aggregate(frames, required_components)： - 配置时通过frame_id进行重复数据删除；只保留可用的机会。 - 每个组件_resolve_component：机会<minimum_valid_frames → UNVERIFIABLE (INSUFFICIENT_VALID_FRAMES);没有政策 → UNVERIFIABLE (COMPONENT_POLICY_MISSING);没有点击 → MISSING (COMPONENT_MISSING);任意命中 ≥ high_confidence → PRESENT；中等 策略要求 medium_hits 不同的帧序列 require_adjacent_hits 尊重 max_frame_gap → 其他 UNCERTAIN。 - _present: detection_count = 每单帧最大检测数 或以上count_threshold（至少政策medium_confidence） - a 低置信度命中不能夸大准确计数。 - temporal_policy_version(config) = 规范策略的 SHA-256 文档，保留为 aggregation_policy_version。

    探测器和模型注册表¶

    • ProductDetector.from_manifest需要task == PRODUCT_DETECTION并且 包含 product 的类名； ComponentDetector.from_manifest 需要 class_names 中的每个配置组件。两者都打电话 verify_manifest_artifact（大小 + SHA-256，包内的相对 URI root）和 verify_model_class_map （连续 0..n-1 匹配 明显的顺序）。推理imgsz = (input_height, input_width)。
    • ComponentDetector.detect 过滤规则所需的代码和每个组件 observation_threshold，通过以下方式映射 roi_bbox → full_frame_bbox 逆平移变换。
    • ModelRegistry (detection/registry.py): 键"{artifact_sha256}:{device or 'default'}";第一次加载获胜，每个句柄共享推理锁 （超解预测器保持可变状态；不同的工件/设备 从不分享）。

    持久性/上传/保留（另见 07）¶

    • persist_inspection_and_enqueue_uploads — 一笔交易：不可变 检查+证据+媒体+发件箱任务。
    • UploadScheduler——根据租约+围栏令牌索取到期任务； MEDIA 仅在其检查任务有经过验证的收据后才应完成任务； 瞬态故障→全抖动退避遵守Retry-After；失踪/ 证据损坏和服务器冲突 → 永久性故障； 2xx 计数 仅具有匹配的打印收据。
    • RetentionCleanupWorker — 收据门控资格，通过隔离删除 O_NOFOLLOW dir 文件描述符；丢失文件是完整性错误； 没有批准的启用策略的零删除。
