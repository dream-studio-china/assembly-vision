    03 — CLI 参考¶

    assemblyvision 和 av-train 命令的真实行为，具有精确的 标志、输出格式和退出代码。显示的所有输出都是命令的内容 实际打印（来自 cli.py、verify.py、backup.py 及其测试）。

    assemblyvision (top level)¶

    usage: assemblyvision [-h] [--version] {inspect,verify,serve,backup,restore} ...
    • 版本：assemblyvision --version→assemblyvision 0.1.0。
    • 需要一个子命令 - 运行裸 assemblyvision 会退出 2。
    • 作为 assemblyvision 控制台脚本或 python -m assemblyvision_edge 调用。
    • 退出代码约定：argparse 误用 → 2；配置/验证 失败 → 2;下面的每个命令代码。

    assemblyvision inspect¶

    usage: assemblyvision inspect <paths...> --config <pipeline.yaml>
       --rule <rule.yaml> --output <dir> [--device-id <uuid>] [-q]
    旗帜 默认 意义
    paths（位置，必需） — 图像或文件夹（按 .jpg .jpeg .png .bmp .tif .tiff .webp 的确定性排序顺序扫描的文件夹）
    --config（必填） — 管道配置文件
    --rule（必填） — 产品规则定义文件
    --output（必填） — 输出目录
    --device-id 随机 uuid4() 稳定的设备UUID
    -q / --quiet 关闭 抑制信息日志（保留每个图像的标准输出行）

    行为： - 在<output>/edge.sqlite3处打开持久规则注册表（与 serve);验证清单、模型版本声明，以及 处理任何图像之前的规则/组件兼容性。 - 写入<output>/<inspection_id>/inspection.json、key_frame.jpg、 annotated_frame.jpg、product_roi.jpg。

    真实的标准输出（每个图像一个制表符分隔行）：

    /tmp/av-e2e/test/ok_000.png        OK   -                                          1f4b5c8e-0000-4000-8000-0000000000aa
/tmp/av-e2e/test/ng_missing_000.png NG   COMPONENT_MISSING:chip                     1f4b5c8e-0000-4000-8000-0000000000ab

    stderr 摘要（INFO 级别；用 -q 抑制）：

    INFO ...: summary: 6 OK, 6 NG, 0 errors

    退出代码：0 当error_count == 0时（NG结果不影响退出 代码——只有错误才会发生）； 1 当任何图像出现错误时； 2 开启 配置/注册表错误。

    assemblyvision verify¶

    usage: assemblyvision verify <paths...> --config <pipeline.yaml>
       --rule <rule.yaml> [--expected <test-expected.json>]
       --output <dir> [--device-id <uuid>] [-q]
    旗帜 默认 意义
    --expected 文件名后备 ​​ 预期标签 JSON {"img.png": {"ok": true, "present": [...], "missing": [...]}};提供它禁用文件名回退
    （其他标志） 与inspect 相同

    文件名后备：基本名称标记 — ng/missing → NG，ok → OK， 否则未标记。

    可评估性门：当记录没有任何记录时，该记录是不可评分的（计为failed） 证据，包含 IMAGE_READ_ERROR / INFERENCE_ERROR / ROI_INVALID / RULE_EVALUATION_ERROR / CONFIG_INVALID / VERSION_INCOMPATIBLE 在其 原因代码，或有任何UNCERTAIN证据。重复的样本身份 被拒绝。

    真正的标准输出：

    ng_missing_001.png      expected=NG      predicted=NG      match    COMPONENT_MISSING:chip
ok_001.png              expected=OK      predicted=OK      match    -

=== Verification report ===
total            : 12
expected OK      : 6
expected NG      : 6
unlabeled        : 0
failed           : 0
unmatched expect.: 0
matched          : 12/12
NG recall        : 1.000 (6/6)
false negatives  : 0  (FN rate 0.000)
false positives  : 0  (FP rate 0.000)

    对于差距，报告附加了DANGER: verification did not cover the full expected set (...)；对于假阴性，它会附加 DANGER: NG predicted as OK (false negatives): 后接一个 每个 FN 的 - <image> 行。

    退出代码：0仅当false_negative == 0时且无间隙； 1 当 存在假阴性或差距； 2 配置错误。

    assemblyvision serve¶

    usage: assemblyvision serve --output <dir> [--db <file>] [--config <file>]
       [--rule <file>] [--static <dir>] [--host 127.0.0.1] [--port 8000]
       [--device-id <uuid>] [--api-token <token>] [--allow-dev-auth]
       [--enable-web-test] [--upload-base-url <url>] [--upload-sink-dir <dir>]
       [--upload-insecure-http] [--tls-cert <cert>] [--tls-key <key>]

    关键行为： - --db默认为<output>/edge.sqlite3；协调现有 CLI 在启动时捆绑到索引中。 - --api-token 回退到 AV_EDGE_API_TOKEN （然后是 Docker 秘密文件 /run/secrets/edge_api_token）。 - 绑定验证：没有令牌且没有的非环回主机 --allow-dev-auth → 退出2。环回绑定从不需要令牌。 - TLS：--tls-cert/--tls-key（或AV_EDGE_TLS_CERT/AV_EDGE_TLS_KEY） 必须一起提供，文件必须存在，并且密钥不能是 组/其他可读；该对必须匹配。 - 如果没有 --config/--rule 则不会构建管道：历史记录/运行状况是 服务和inspection_ready=false。 - --enable-web-test 打开门控 /api/v1/dev/* 端点 （否则他们会在 auth 之前返回 404）。 - 运行 uvicorn 的块；出现配置/验证错误时退出 2。

    assemblyvision backup¶

    usage: assemblyvision backup --output <dir> [--db <file>]
       [--config <file>] [--rule <file>] --dest <out.tar.gz>
    • 如果输出根、数据库、任何受管理的 --config/--rule 则关闭失败 文件，或引用的模型清单丢失。
    • 获取一致的 SQLite 快照（在线备份 API），包括待处理的 媒体 + 他们的 inspection.json 记录（每个条目 SHA-256），并受管理 文件；丢失/更改的挂起文件会中止备份。
    • stderr 成功线： backup written to <path>: N governed files, N pending media, sha256=<hex>。
    • 退出：0成功，2失败。

    assemblyvision restore¶

    usage: assemblyvision restore --backup <bundle.tar.gz> --output <dir>
       [--db <file>] [--governed-dest <dir>]
    • 在应用任何内容之前验证每个捆绑包校验和；拒绝 DB 校验和不匹配；预检媒体目标（冲突文件 → 错误 活动数据库不变）；保留<db>.pre-restore；恢复受治理的 仅将文件放入--governed-dest；协调商店以便等待上传 任务得以生存。
    • stderr 成功线： restore from <path>: db=<db>, media=N, governed=N, reconciled=N。
    • 退出：0成功，2失败。

    python -m assemblyvision_edge.healthcheck¶

    python -m assemblyvision_edge.healthcheck <url>
    • GET 超时时间为 5 秒；在 2xx/3xx 时退出 0，在失败时退出 1，在误用时退出 2。
    • 由容器 HEALTHCHECK 使用。

    av-train（培训 CLI，仅限开发人员）¶

    usage: av-train [-h] [--version] {product,prepare-components,component} ...

    av-train product <dataset> --semver X.Y.Z¶

    旗帜 默认 意义
    --epochs 50 50训练纪元
    --imgsz 640 640模型输入尺寸
    --model-size n YOLO 规模 n/s/m/l
    --device cpu cpu/mps/cuda
    --seed 0 再现性种子
    --no-augment 关闭 禁用大量增强（对于小数据集稳定）
    --allow-missing-labels 关闭 旧版选择加入：接受没有标签文件的图像（记录在 data.yaml 中）
    --out-weights models/weights/product-yolo.pt 输出权重路径
    --out-manifest models/manifests/product-manifest.json 输出清单路径
    --rule — 用于打印建议版本冲突的可选规则 YAML

    av-train prepare-components <dataset> --product-manifest <file> --out-dir <dir>¶

    旗帜 默认 意义
    --margin-x / --margin-y 0.05 / 0.05 0.05 / 0.05投资回报率利润率
    --min-area 10000 最小 ROI 面积 (px)
    --min-retention 0.80 最小夹子保留率
    --conf / --iou 0.5 / 0.5 0.5 / 0.5产品检测阈值
    --device cpu 火炬装置
    --allow-missing-labels 关闭 旧版选择加入

    从校验和验证重新生成 ROI 裁剪的组件数据集 产品清单；零个/多个候选产品 → exclusions.json (NO_PRODUCT_OR_AMBIGUOUS)，永远不会是一个被猜到的盒子；登台+原子发布； 保留带有空标签的负投资回报率作物。

    av-train component <roi-dataset> --semver X.Y.Z¶

    与 product 相同的标志，除了 --imgsz 默认为 320 并且默认值 输出为 models/weights/component-yolo.pt / models/manifests/component-manifest.json。

    改进提示输出¶

    product/component训练后，av-train打印协调的 凹凸（使用 --rule product-rule.yaml 运行的组件的实际输出）：

    === Next steps: model improved ===
1. pipeline.yaml: set component_detection.model_version: 'component-yolo-0.2.0'
2. product-rule.yaml: add 'component-yolo-0.2.0' to compatible_component_model_versions
   suggested: rule_version 3 -> 4
   suggested compatible: ['component-yolo-0.1.0'] -> ['component-yolo-0.1.0', 'component-yolo-0.2.0']
3. re-run: assemblyvision verify <test> --config <pipeline.yaml> --rule <rule.yaml> --output out/
   see docs/runbooks/10-model-improvement.md

    对于 product 运行，步骤 2 是 prepare-components 再生 消息。

    serve读取的环境变量（全部在cli.py中）¶

    Auth/secrets：AV_EDGE_API_TOKEN、AV_EDGE_UPLOAD_TOKEN（单独上传 凭据，而不是查看者令牌）、AV_EDGE_TLS_CERT、AV_EDGE_TLS_KEY。

    上传工作线程（仅在 AV_EDGE_UPLOAD_BASE_URL 或 AV_EDGE_UPLOAD_SINK_DIR已设置）：

    变量 默认
    AV_EDGE_UPLOAD_BASE_URL / AV_EDGE_UPLOAD_SINK_DIR —（HTTPS 端点/本地开发接收器）
    AV_EDGE_UPLOAD_CONNECT_TIMEOUT_SECONDS 5.0
    AV_EDGE_UPLOAD_REQUEST_TIMEOUT_SECONDS 30.0
    AV_EDGE_UPLOAD_INTERVAL_SECONDS 1.0
    AV_EDGE_UPLOAD_BATCH_SIZE 4
    AV_EDGE_UPLOAD_LEASE_SECONDS 120
    AV_EDGE_UPLOAD_BASE_RETRY_SECONDS 2.0
    AV_EDGE_UPLOAD_MAXIMUM_RETRY_SECONDS 900.0
    AV_EDGE_UPLOAD_EXPONENT_CAP 8
    AV_EDGE_UPLOAD_MAXIMUM_BANDWIDTH_MBPS 无（禁用）
    AV_EDGE_UPLOAD_INSECURE_HTTP 假
    AV_EDGE_UPLOAD_CIRCUIT_FAILURE_THRESHOLD 5
    AV_EDGE_UPLOAD_CIRCUIT_OPEN_SECONDS 60.0
    AV_EDGE_UPLOAD_MEDIA_CHUNK_BYTES 8388608（保留）

    存储（设置任意值时有效）：AV_EDGE_STORAGE_WARNING_FREE_PERCENT (20.0), AV_EDGE_STORAGE_CRITICAL_FREE_PERCENT (10.0), AV_EDGE_STORAGE_STOP_FREE_PERCENT (5.0) — 严格排序。

    保留：AV_EDGE_RETENTION_ENABLED（False - 默认情况下关闭清理）， AV_EDGE_RETENTION_DURATIONS （类似于 {"KEY_FRAME": "30d"} 的 JSON；紧凑 持续时间s/m/h/d）。

    完整性扫描（设置任何一项时激活）： AV_EDGE_STORAGE_INTEGRITY_VERIFY_CHECKSUMS（正确）， AV_EDGE_STORAGE_INTEGRITY_SAMPLE_LIMIT, AV_EDGE_STORAGE_INTEGRITY_SAMPLE_MAX_BYTES。

    前端：VITE_API_MODE（mock开发/http生产），VITE_API_BASE_URL （省略时同源），VITE_CAMERA_INSTANCE_ID (line-1)， VITE_DEV_SERVER_URL（边缘桌面开发）。
