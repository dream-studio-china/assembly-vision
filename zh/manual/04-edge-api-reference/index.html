    04 — Edge API Reference¶

    边缘 API 如何真正被调用：基本 URL、身份验证流程、每个端点 具有真实请求/响应 JSON 和curl 示例、WebSocket 协议、错误 约定和代码清单。权威合同是 提交的 OpenAPI 文档 (apps/edge-service/openapi/edge-openapi.json, 使用 uv run python scripts/generate-edge-openapi.py 重新生成）。

    基本 URL 和约定¶

    • 服务器：uv run assemblyvision serve --output out/ --db out/edge.sqlite3 --config ... --rule ... --static apps/edge-web/dist --host 127.0.0.1 --port 8000。基本URL http://127.0.0.1:8000，下的所有路由 /api/v1。
    • JSON 无处不在； snake_case字段； ISO-8601 UTC 时间戳；通用唯一标识符 字符串。
    • 每个响应都带有安全标头（Content-Security-Policy、 X-Content-Type-Options: nosniff、Referrer-Policy: same-origin）。
    • /api/* 下的 GET 不是真正的路由，返回 JSON 404，而不是 仪表板 HTML。

    验证¶

    配置 API 令牌（--api-token 或 AV_EDGE_API_TOKEN）时， 除 GET /api/v1/health/live 之外的每条路线都需要凭据。 接受两种凭据：

    1. Authorization: Bearer <token> header（恒定时间比较）。
    2. av_edge_viewer_session HttpOnly cookie（由 POST /api/v1/auth/session）。

    如果没有配置令牌，服务将在开放的 M1 开发模式下运行（所有 未经验证的路线）。失败策略：凭证错误/丢失 → 401 code: "UNAUTHENTICATED"；每个客户端 IP 每分钟 5 次失败尝试后 → 429 code: "RATE_LIMITED" 与 Retry-After: 60。

    Bearer → 会话 cookie 流（仪表板登录的作用）¶

    # exchange the token for an HttpOnly session cookie (204, Set-Cookie: av_edge_viewer_session=...)
curl -i -X POST http://127.0.0.1:8000/api/v1/auth/session \
  -H "Authorization: Bearer $TOKEN"
    • 204 无内容； cookie Max-Age=28800（8 小时）、HttpOnly、SameSite=strict、 Secure 当使用 HTTPS 时；最多 500 个会话。
    • 错误的令牌 → 401；速率限制 → 429。

    WebSocket 票证流程¶

    浏览器套接字无法设置 Authorization 标头，因此仪表板 将其观众凭证交换为短期的一次性门票：

    TICKET=$(curl -X POST http://127.0.0.1:8000/api/v1/ws/runtime/ticket \
  -H "Authorization: Bearer $TOKEN" | python3 -c 'import sys,json;print(json.load(sys.stdin)["ticket"])')
# response: {"ticket": "<urlsafe-base64>", "expires_at": "ISO-8601", "channel": "runtime"}

    然后将票证作为协商的子协议连接：

    const ws = new WebSocket("ws://127.0.0.1:8000/api/v1/ws/runtime", [ticket]);

    Ticket TTL 30 秒，一次性使用，绝不出现在 URL 中；过期/重播的门票 → 关闭4401。

    错误约定 - application/problem+json¶

    所有非 2xx 错误都是 RFC 7807 问题：

    {
  "type": "https://assemblyvision.example/problems/task_not_retryable",
  "title": "Task Not Retryable",
  "status": 409,
  "detail": "upload task is SUCCEEDED and cannot be manually retried",
  "code": "TASK_NOT_RETRYABLE",
  "request_id": "<X-Request-ID or generated uuid4>",
  "errors": []
}
    • 422 验证失败使用 code: "VALIDATION_FAILED" 并填充 errors 与 {"field": "<loc>", "message": "<msg>"} 条目。
    • 未处理的异常 → 500 code: "INTERNAL_ERROR"。
    • 未知的 API 路由 → code: "HTTP_404"。

    端点¶

    健康¶

    GET /api/v1/health/live — 未经身份验证的活跃度。

    curl http://127.0.0.1:8000/api/v1/health/live

    {"status": "ok"}

    GET /api/v1/health/ready — 经过身份验证；返回完整的 DeviceStatus （见下文）或 503 code: "NOT_READY" 当管道 未加载或存储无法保证强制持久化（写入故障、 storage_mode == "STOP"，完整性错误，清理完整性错误）。

    curl http://127.0.0.1:8000/api/v1/health/ready -H "Authorization: Bearer $TOKEN"

    媒体¶

    GET /api/v1/media/{media_id}/content — 字节流，可选 Range：

    curl http://127.0.0.1:8000/api/v1/media/$MEDIA_ID/content \
  -H "Authorization: Bearer $TOKEN" -o media.bin
curl http://127.0.0.1:8000/api/v1/media/$MEDIA_ID/content \
  -H "Authorization: Bearer $TOKEN" -H "Range: bytes=0-1023" -o part.bin
    • Content-Type 源自种类允许列表（图像 → image/jpeg， 剪辑 → video/mp4），绝不来自持久的哑剧。
    • 206 和 Content-Range 用于范围； 416 code: "INVALID_RANGE" 对于 无法满足的范围； 404 MEDIA_NOT_FOUND; 410 code: "MEDIA_PURGED" 用于已清除的媒体（即使文件存在）。

    status = PENDING | IN_PROGRESS | RETRY_WAIT | SUCCEEDED | PERMANENT_FAILURE | CANCELLED; kind = INSPECTION | MEDIA | DEVICE_EVENT。

    POST /api/v1/uploads/{upload_task_id}/retry — 手动重试。仅 RETRY_WAIT 和 PERMANENT_FAILURE 任务符合条件。本体可选 （{"reason": "..."}，最多 200 个字符，或无正文）：

    curl -X POST http://127.0.0.1:8000/api/v1/uploads/$TASK_ID/retry \
  -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"reason": "conveyor jam cleared"}'
# legacy: no body at all
curl -X POST http://127.0.0.1:8000/api/v1/uploads/$TASK_ID/retry \
  -H "Authorization: Bearer $TOKEN"
    • 200 → 用 status: "PENDING" 和 attempt_count 刷新 UploadTask 增加； completed_at/next_attempt_at/last_error_code 已清除。
    • 404 code: "NOT_FOUND" 未知任务； 409 code: "TASK_NOT_RETRYABLE" 对于 SUCCEEDED/PENDING/IN_PROGRESS/CANCELLED 和第二次重试 （比较并设置）； 422 当原因太长时（无突变）。

      "min_area_pixels": 1000, "min_expanded_area_retained": 0.6,
      "normalize_perspective": false
    },
    "rule": {
      "rule_id": "model-a-presence", "rule_version": 3,
      "product_type": "model_a",
      "required_components": ["component_a", "component_b"]
    }
  },
  "local_overrides": {}
}

    revision 始终是 "local"； checksum_sha256 是 SHA-256 加载配置+规则字节；当管道不是时，子对象是 null 已加载。

    评论（边缘本地人工评论，ADR-016）¶

    GET /api/v1/reviews — 审核队列。查询参数：business_result (OK/NG)、internal_decision、reviewed（布尔值：true = 已审核， false = 打开）、cursor、limit（默认 50）。 400 INVALID_CURSOR 开启 光标格式错误/过滤器不匹配。

    curl "http://127.0.0.1:8000/api/v1/reviews?business_result=NG&reviewed=false&limit=25" \
  -H "Authorization: Bearer $TOKEN"

    {
  "items": [
    {
      "inspection_id": "uuid",
      "completed_at": "2026-08-10T09:30:01Z",
      "business_result": "NG",
      "internal_decision": "UNCERTAIN",
      "barcode": "SN-001234",
      "reason_summary": ["COMPONENT_MISSING:component_a"],
      "has_review": false,
      "latest_disposition": null
    }
  ],
  "next_cursor": "opaque-or-null"
}

    GET /api/v1/inspections/{inspection_id}/reviews — 仅附加历史记录 （最旧的在前），普通数组：

    [
  {
    "review_id": "uuid",
    "inspection_id": "uuid",
    "disposition": "CORRECTED_NG",
    "reason": "rework performed",
    "note": "operator confirmed",
    "reviewer": "operator-1",
    "created_at": "2026-08-10T10:00:00Z",
    "original_business_result": "OK",
    "original_internal_decision": "OK",
    "original_reason_codes": [],
    "component_corrections": [
      {"component_code": "component_a", "corrected_state": "MISSING", "note": "pad missing"}
    ],
    "supersedes_review_id": null
  }
]

    POST /api/v1/inspections/{inspection_id}/reviews — 附加一篇评论。 请求正文（extra="forbid"）：

    {
  "disposition": "CONFIRMED_NG",
  "reason": "defect visible",
  "note": "optional operator note",
  "reviewer": "operator-1",
  "supersedes_review_id": null,
  "component_corrections": [
    {"component_code": "component_a", "corrected_state": "PRESENT", "note": "optional"}
  ]
}

    约束：需要disposition； reason≤200； note≤2000； reviewer 需要 1-128 个字符； component_corrections ≤64，每个 component_code 1-64（剥离），corrected_state ∈ PRESENT|MISSING|UNCERTAIN，note ≤500； INCONCLUSIVE 需要 reason；重复的组件代码被拒绝。

    每台机器结果允许的配置（服务器强制执行）： UNCERTAIN→CONFIRMED_NG, CONFIRMED_OK, REINSPECT, INCONCLUSIVE； 业务NG→CONFIRMED_NG, CONFIRMED_OK, INCONCLUSIVE； OK → CONFIRMED_OK, CORRECTED_NG, INCONCLUSIVE。

    curl -X POST http://127.0.0.1:8000/api/v1/inspections/$INSPECTION_ID/reviews \
  -H "Authorization: Bearer $TOKEN" -H "Content-Type: application/json" \
  -d '{"disposition":"CONFIRMED_NG","reason":"defect visible","reviewer":"operator-1"}'

    响应：存储的ReviewRecord（原始机器字段快照， 从未重写）。错误：404 INSPECTION_NOT_FOUND； 409 REVIEW_CONFLICT （supersedes_review_id 针对不同的检查）； 422 REVIEW_DISPOSITION_INVALID（不允许处置）； 422 VALIDATION_FAILED（架构/模型验证）。

    统计和追溯（派生）¶

    GET /api/v1/statistics — 查询参数 from/to （时区感知 UTC）， line（总是被拒绝）：

    curl "http://127.0.0.1:8000/api/v1/statistics?from=2026-08-10T00:00:00%2B00:00&to=2026-08-10T23:59:59%2B00:00" \
  -H "Authorization: Bearer $TOKEN"

    {"total_inspections": 100, "pass_count": 82, "ng_count": 18, "pass_rate": 0.82}

    错误：400 UNSUPPORTED_FILTER (line)、400 INVALID_FILTER（天真的 时间戳），400 INVALID_RANGE（from在to之后）。

    获取/api/v1/traceability/{sn}：

    curl http://127.0.0.1:8000/api/v1/traceability/SN-001234 -H "Authorization: Bearer $TOKEN"

    {
  "sn": "SN-001234",
  "final_status": "PASS",
  "attempts": [
    {"attempt": 1, "inspection_id": "uuid", "timestamp": "2026-08-10T09:30:01Z",
     "result": "PASS", "reason": "COMPONENT_MISSING:component_a", "operator": "-"}
  ]
}

    未知 SN → 404 code: "SN_NOT_FOUND"。

    WebSocket 运行时通道¶

    GET /api/v1/ws/runtime/stats — 通道计数器：

    {
  "active_connections": 0,
  "published_total": 0,
  "published_by_type": {},
  "slow_consumer_disconnects": 0,
  "delivery_failures": 0
}

    WS /api/v1/ws/runtime — 服务器推送的信封 (v1)。握手 接受承载/会话 cookie 或单个票据作为 Sec-WebSocket-Protocol； 失败→关闭4401；缓慢的消费者使用关闭代码 1008 断开连接。

    {
  "event_id": "uuid",
  "type": "inspection.completed",
  "schema_version": 1,
  "occurred_at": "2026-08-10T09:30:01Z",
  "source_id": "<device_id>",
  "sequence": 1,
  "correlation_id": null,
  "data": {"inspection_id": "i-9"}
}

    事件类型：inspection.started、inspection.completed、 device.status_changed、upload.changed。序列是严格单调的 根据(source_id, channel)；差距意味着事件丢失 - 客户必须 重新获取 REST。事件是短暂的； REST 是权威的。

    开发测试工具（ADR-014；404 DEV_TOOLS_DISABLED，除非 serve --enable-web-test）¶
