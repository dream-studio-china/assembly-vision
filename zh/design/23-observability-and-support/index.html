    23. 可观察性和支持¶

    23.1 目的和范围¶

    可观察性必须解释检查行为、设备运行状况、同步状态和配置来源，而无需中央连接进行本地诊断。支持程序保留生产证据，并且决不会将不可用或不明确的检查变成OK。

    23.1.1 交付范围¶

    • MVP： 结构化本地日志、每阶段计时、决策 JSON、模型/规则版本和 CLI 运行状况输出。
    • 一个月目标：本地运行状况 API/仪表板、持久设备事件、队列/磁盘/摄像头指标、试点的中央上传/设备状态、相关标识符和有界诊断包。
    • 生产目标：警报路由、根据基线数据商定的服务目标、运行手册、时钟监控、受控远程诊断和版本分段质量仪表板。
    • 未来范围： OpenTelemetry 跨车队服务跟踪以及与客户监控平台的集成。

    23.2 可观察性原则¶

    1. 离线时本地检查可观察性仍然可用。
    2. 检查 ID 将框架、决策、媒体、上传任务、收据和人工审核关联起来。
    3. 日志和指标区分应用程序、模型、规则、产品、产品线和设备版本。
    4. 健康端点描述软件准备情况；它们不能取代相机取景、照明、焦点或线条行为的物理验证。
    5. 遥测是有界的并受到保留，因此它不能耗尽边缘磁盘。
    6. 根据政策最小化或编辑条形码、图像、凭证和客户标识符。

    23.3 结构化日志¶

    JSON 日志使用 UTC 时间戳和稳定的事件名称。推荐字段有：

    {
  "timestamp": "2026-08-04T10:15:31.412Z",
  "level": "warning",
  "event": "upload_retry_scheduled",
  "service": "edge-service",
  "device_id": "device-reference",
  "inspection_id": "inspection-reference",
  "correlation_id": "request-reference",
  "product_model_version": "product-model-reference",
  "component_model_version": "component-model-reference",
  "rule_version": "rule-reference",
  "attempt": 3,
  "error_code": "CENTRAL_TIMEOUT",
  "retry_at": "2026-08-04T10:16:04Z"
}

    不记录凭据、授权标头、完整图像字节或任意异常负载。仅在获得批准后才会记录完整的条形码值；否则存储屏蔽值或稳定的限制访问引用。回溯通过访问控制保留在本地并集中汇总。

    23.4 指标¶

    23.4.1 边缘健康状况和工作负载¶

    • 相机连接、帧龄、采集失败、曝光/配置偏差和重新连接计数。
    • 产品窗口打开/完成/中止以及不明确/多个产品计数。
    • 产品检测、ROI 失败、条形码读取/失败以及不可用的框架。
    • 由OK、NG、可选UNCERTAIN和原因代码做出的决定。
    • 阶段延迟和总持久决策延迟分布。
    • CPU/GPU 利用率、推理内存、可用温度、进程内存、磁盘空间/索引节点、数据库大小和文件描述符使用。
    • 上传队列深度/字节/最旧年龄、重试计数、终端故障和接收延迟。
    • 活动应用程序、模型、规则、产品配置版本及其校验和。

    23.4.2 中心指标和质量指标¶

    • 摄取请求结果、重复收据、校验和失败以及处理积压。
    • 设备上次查看、队列延迟、时钟偏移估计和版本合规性。
    • NG 召回率、假阴性估计、假阳性率以及存在审查的基本事实的审查纠正率。
    • 按产品、按组件、按模型和按规则细分。
    • 审核队列深度/年龄和审核者周转时间。
    • API 延迟/错误率、数据库饱和度、对象存储故障和工作人员积压。

    公制标签必须避免使用无界值，例如检验 ID 或条形码。这些属于日志/痕迹。

    23.5 健康模型¶

    /api/v1/health/live 报告进程是否可以应答。 /api/v1/health/ready 报告决策关键本地依赖项是否允许有效检查。经过身份验证的 /api/v1/device/status 报告摄像头、型号、规则、磁盘、数据库、时钟、网络、中央连接、inspection_ready 和 sync_ready 状态。

    当 edge-service 内的决策运行时无法持久记录决策、没有兼容的活动模型/规则或没有可用的相机时，它还没有准备好。仅靠中央连接并不意味着它尚未准备好。仪表板显示 healthy、degraded 和 unavailable 以及原因代码和时间戳，而不是单个绿色指示器。

    23.6 事件和可追溯性¶

    设备事件是摄像机转换、检查暂停/恢复、磁盘阈值、配置激活、模型/规则激活、上传失败、时钟异常、启动/关闭和恢复的持久记录。中央接收保留源事件时间和中央接收时间。

    每个检查轨迹都会回答：

    • 使用了哪个物理窗口和条形码/产品映射？
    • 哪些帧被接受或拒绝，为什么？
    • 哪些产品盒/投资回报率和组件证据导致了该决定？
    • 哪些应用程序、模型、规则和配置版本处于活动状态？
    • 证据是否已上传、审查、更正、保留或删除？
    • 哪个用户或服务更改了相关配置？

    23.7 仪表板和警报¶

    边缘仪表板优先考虑摄像头可用性、最新决策、活动版本、磁盘预留、队列寿命和中央连接。中央仪表板优先考虑陈旧设备、质量趋势、队列延迟、版本推出、审查积压和重复出现的组件/条形码故障。

    警报阈值是在基线测量后配置的。所需的警报条件包括相机不可用、预计生产时没有最新帧、磁盘关键、数据库写入失败、无活动兼容版本、重复工作器重新启动、队列年龄/大小增长、包签名失败、时钟漂移、中央摄取失败以及具有统计意义的质量回归。警报需要重复数据删除、严重性、所有者、操作手册链接和恢复通知。

    23.8 诊断包¶

    授权的支持操作可以导出包含清单/版本校验和、有效的非秘密配置、最近的结构化日志、健康历史、数据库完整性结果、队列摘要、选定的检查元数据和明确选择的证据的有界的、加密的包。 UI 预览包含敏感数据。创建和下载均经过审核；凭证和不相关的生产媒体被排除在外。

    远程 shell 访问不是默认支持机制。如果客户政策允许，访问必须有时间限制、可单独归属、批准并记录在应用程序外部以及审核日志中。

    23.9 支持严重性和升级¶

    严重性 示例 立即处理
    关键 潜在的漏检 NG 模式；决策无法持久保存 暂停/遏制受影响的操作，保留证据、页面质量和工程所有者
    高 相机不可用、反复崩溃、磁盘严重损坏 遵循本地恢复操作手册并及时升级
    中等 本地检查正常时上传积压的订单 监控容量、恢复连接、核对收据
    低 报告缺陷或外观仪表板问题 记录版本/证据并安排更正

    响应和解决时间是需要商定的合同值，而不是在此架构中发明的。

    23.10 操作手册¶

    23.10.1 潜在的漏检 NG¶

    1. 保存检查、相邻证据、有效版本、日志和审查记录。
    2. 确定受影响的产品/组件/版本/时间/设备范围。 3、根据客户流程增加审核或暂时暂停OK产品的自动发布。
    3. 重新评估保留的证据而不覆盖原来的决定。
    4. 纠正groundtruth，添加锁定的回归案例，并决定是否需要规则/配置回滚或模型修复。
    5. 记录遏制、根本原因、受影响的检查和发布验证。

    23.10.2 不断增长的上传队列¶

    1. 确认本地检查和持久队列健康状况。
    2. 检查网络、DNS、TLS、凭据、中央 API、对象存储和代理限制。
    3. 检查最旧的任务、待处理字节、重试/错误类别和本地可用空间。 4、恢复服务并允许限速引流；不要手动克隆任务。
    4. 核对幂等性收据和校验和；仅在修复其原因后重试终端任务。

    23.10.3 重复进程重启¶

    1. 使线路保持安全的不可用/降级状态并保留重启计数器。
    2. 检查退出代码、资源耗尽、驱动程序状态、数据库完整性和最后事件。
    3. 在配置的阈值之后禁用自动重启循环。
    4. 恢复失败的依赖项或回滚版本。
    5. 在恢复之前运行相机和已知样本检查。

    23.10.4 时钟漂移¶

    1. 将边缘墙时间与批准的时间源和中心接收时间进行比较。
    2. 保留单调序列和源时间戳；不要重写历史记录。
    3. 恢复时间同步，避免不安全的突变，平台支持逐步校正。
    4. 标记受影响的记录并验证产品窗口订购和上传核对。

    23.11 遥测数据保留¶

    日志按大小和寿命轮换，并为检查记录保留磁盘。指标使用有限的本地历史记录，然后在连接时集中聚合。审计记录具有经客户批准的更长保留期，并且不会通过普通日志清理默默删除。遥测清理遵循与媒体清理相同的保护措施：上传/协调所需的待决证据和记录受到保护。

    23.12 未解决的问题和需要验证¶

    • 客户监控平台、警报渠道、支持时间、严重性定义和升级联系人。
    • 需要生产计划信号来区分预期空闲时间和丢失帧。
    • 硬件和生产基线测量后的指标/警报阈值。
    • 本地和中央日志、指标、审计和诊断包保留期。
    • 条形码/图像数据分类、编辑规则以及导出诊断证据的许可。
    • 时间同步源和可接受的时钟偏移。
    • 是否允许远程支持以及哪些访问/审核控制是强制性的。
    • 摄像机、网络、主机和应用程序故障的合同响应目标和责任边界。
