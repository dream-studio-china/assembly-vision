    24. 人机交互操作¶

    24.1 目的和安全位置¶

    人工审核是一个受控的质量流程，旨在谨慎推出、模糊证据、NG 处理和持续改进。它不会隐藏模型限制或改变原始机器决策。 AssemblyVision 优先考虑高 NG 召回率：早期操作接受额外的错误 NG 决策，因为它们可以进行审查，而错误地发布为 OK 的真正 NG 是主要的质量风险。

    审核是可选且附加的 (ADR-016)：运行 检查，永远不会改变不可变的机器决策，并且永远不会改变 现有的检查终点或预测。任何检查 — OK 或 NG — 可以在边缘进行本地审查； NG 详细视图显示评论条目 OK 视图提供了可选的审核路径。

    24.2 阶段范围¶

    24.2.1 初始生产阶段¶

    • 使所有 NG 检查可供审查。
    • 路由内部决定为UNCERTAIN的业务NG案例作为独特的解释类别进行审查。
    • 审核 OK 检查的代表性样本。
    • 保留原始证据、模型/规则/配置版本和机器原因代码。
    • 将审阅者的更正和确认的错误分类存储到受管理的培训待办事项中。

    24.2.2 成熟生产目标¶

    • 按产品、组件、生产线、型号和规则版本分别调整审核路线。
    • 只有在有足够的生产证据和客户批准后才能减少人工审核。
    • 继续基于风险的 OK 抽样来估计漏报。
    • 优先考虑新颖、低质量、分歧和发布后的案例。

    24.2.3 未来范围¶

    • 审稿人辅助聚类和主动学习建议。
    • 对选定的关键缺陷类别进行双重审查或裁决。
    • 接口和职责达成一致后，MES配置集成。

    自动化再培训和自动化生产模式推广不在最初的范围之内。

    24.3 可审查的结果¶

    机器结果保持不变。评论添加了单独的人类性格：

    机器结果 审核目的 允许的人类处置
    NG 确认真缺陷或假NG 确认NG、确认OK、尚无定论
    业务NG，内部UNCERTAIN 解决证据不足/冲突的问题 确认 NG、确认 OK、重新捕获/重新检查、不确定
    采样 OK 估计遗漏的缺陷并检测漂移 确认OK，修正NG，无定论
    系统异常 确定可检查性和回收率 重新检查，操作故障，尚无定论

    NG 更正为 OK，采样 OK 确认共享 CONFIRMED_OK 处置；审查记录上的原始机器结果区分 他们。 “系统异常”行（包括操作故障处理） 超出边缘本地审查范围，并推迟到中央审查存在 （ADR-016）。

    修正不会重写边缘决策。它记录审查者、时间、原因、真实成分状态、使用的证据以及与原始检查的关系。

    24.4 查看队列策略¶

    路由策略是版本化且可审计的。优先因素包括：

    1. 缺失组件的潜在安全/质量影响。
    2. UNCERTAIN、无商品、条码不匹配或系统异常。
    3. 新的应用程序/模型/规则/产品配置推出。
    4. 证据余量低或跨框架不一致。
    5. 相机或图像质量下降。
    6. 产品/组件组合代表性不足。
    7. 物品的年龄和客户的生产流程。

    All-NG 审查是一项初始部署策略，而不是永久的架构要求。合格的审核样本必须通过记录的方法来选择，而不是为了审查者的方便。抽样分层应防止大批量产品类型隐藏小批量风险。

    24.5 手动审核顺序¶

    participant C as 中央服务器
    participant Q as 审核队列
    participant R as 审稿人
    participant T as 培训待办事项
    E->>C:上传决定、版本和证据
    C->>C:验证收据和证据校验和

    审核完成绝不会将临时阈值或模型更改直接推送到边缘设备。

    24.6 审阅者界面要求¶

    中央仪表板显示原始完整/关键帧、产品投资回报率、带注释的检测、保留时的每帧证据、条形码/产品映射、丢失和低置信度组件、图像质量原因以及应用程序/模型/规则/配置版本。审阅者可以缩放和切换叠加层，而无需修改源证据。

    提交需要进行处理、每个组件的更正（如果适用）、原因代码和可选注释。 Inconclusive 需要一个理由，例如证据不足、框架错误、遮挡或无法获得基本事实。 UI 可防止配置双重控制的自我批准并记录重新分配、重新开放和裁决。

    24.7 审查数据模型和可审计性¶

    审核记录包括：

    • 稳定的审查和检查标识符。
    • 队列策略/版本和分配历史记录。
    • 原始机器结果和原因代码。
    • 审阅者处置和组件级基本事实。
    • 审阅者身份、角色、时间戳和原因。
    • 显示证据标识符/校验和和版本。
    • 如果更正，则取代审查参考。
    • 需要时裁决国家和裁决者。
    • 培训积压资格和排除原因。

    审核记录仅供追加。更正是取代而不是覆盖。访问和导出均经过审核。

    24.8 人工审核的质量控制¶

    审核人员需要与客户商定的特定于产品的说明和示例。质量控制包括定期校准案例、盲法重叠审查、分歧分析以及授权产品专家的裁决。无法从保留的证据中确定的基本事实仍然是不确定的，并且不得被迫与机器输出相匹配。

    审阅者绩效数据用于改进说明并解决歧义，而不是替代代表性系统评估。

    24.9 反馈和模型改进¶

    已确认的错误会进入候选待办事项列表，并具有出处和数据使用权限。在培训使用之前，授权管理者会检查图像质量、产品标识、组件标签、泄漏分组、隐私和重复/相邻帧关系。数据集版本记录包含决策。

    更新周期为：

    1. 按产品、组件、现场条件和发布版本分析错误。
    2. 选择有代表性的、授权的示例并保留保留的验收数据。
    3. 在生产边缘运行时之外进行训练或调整。
    4. 针对锁定回归和独立验证集进行评估。
    5. 通过正常发布流程批准已签名的模型/规则发布。
    6. 如果测量到的行为出现退化，则进行暂存、监视和回滚。

    没有个人审查会导致在线学习或默默地改变生产决策政策。

    24.10 指标和审查减少¶

    跟踪审核率、队列年龄、审核者周转率、纠正率、误报率、OK 审核的估计误报率、不确定率、分歧率以及每个产品/每个组件/模型/规则结果。每个比率都包括其样本数量和抽样方法。

    仅当测量的生产证据支持更改时，才会减少手动审核。该决定考虑了 NG 召回、OK 审核结果、新颖性、审查纠正率、样本代表性、最近的相机/产品/配置更改以及客户风险承受能力。没有固定的日历日期或未经验证的数字触发器。

    24.11 操作异常¶

    • 如果中央服务器不可用，边缘检查将继续，并稍后同步审核项目。
    • 如果所需的证据丢失或损坏，则审查没有结论，并且会引发操作事件。
    • 如果队列增长超过人员配置能力，优先政策会保护最高风险的物品；它不会自动将 NG 转换为 OK。
    • 如果审核者发现潜在的漏检 NG 模式，请遵循 Observability and Support 中的遏制运行手册。
    • 如果产品配置发生变化，请在激活之前和之后维护单独的审核指标。

    24.12 未解决的问题和需要验证¶

    • 内部UNCERTAIN如何显示为独特的评论类别，同时保留业务结果NG。
    • 谁有权定义基本事实、裁决分歧并在审查后发布产品。
    • 审查人员配置、轮班、语言、响应期望和队列所有权。
    • 生产基线测量后初始和持续的 OK 审核抽样政策。
    • 按产品类型划分的组件重要性和审查优先级。
    • 完成延迟审查和质量审核所需的证据保留。
    • 审核结果是否与 PLC/MES 集成，还是在第一个版本中保持咨询性。
    • 在培训中使用经过审查的生产证据的客户许可和管理。

    24.14 边缘本地审查 (ADR-016)¶

    虽然成熟的设计通过中央服务器进行审查（部分 24.5），边缘存储仅附加的本地审查记录，因此该过程保留 在离线状态下工作（第 24.11 节）并且在中央服务器存在之前。 范围参见ADR-016 决定：可选的每次检查审查、处置兼容性、本地 审阅者身份、取代链接和网络审阅队列。
