    14. 数据模型和数据库¶

    14.1 目的和范围¶

    本文档定义了规范的 AssemblyVision 域模型以及单独的边缘和中央持久性模式。边缘数据库是一个针对不间断检查和上传恢复进行优化的操作存储。中央 PostgreSQL 数据库是用于车队配置、同步检查历史记录、审查和审计的记录系统。

    M1 实现边界。 在 M1 只读里程碑 (ADR-012) 中 边缘 SQLite 数据库是 CLI 的 可重建读取投影 inspection.json捆绑包，非权威运营商城描述 下面。它可以从同一个包中删除和重建，它不是 完成/发件箱存储，其模式尚未携带唯一的 约束、产品配置列或上传所需的租约 生产设计。权威商店与上传一起构建 调度程序；在此之前，该设计描述的是目标，而不是当前 实施（AUDIT-001）。

    相关文档：REST API and Events、Edge Dashboard、Central Admin Dashboard和Training and Evaluation。

    14.2 数据约定¶

    关注 大会
    标识符 应用程序生成的 UUID；新记录首选 UUIDv7。切勿重复使用数据库序列作为同步标识。
    时间 UTC、API 中的时区感知 ISO 8601； TIMESTAMPTZ 集中； SQLite 中的 UTC 文本或整数纪元。分别记录设备捕获时间和中心接收时间。
    坐标 像素空间 xyxy，原点位于左上角，右/下边界除外。包括源图像尺寸。
    信心 [0, 1]中的浮点数；没有证据就不是信心0。
    决定 内部OK、NG或UNCERTAIN； UNCERTAIN 始终映射到业务/物理 NG 路径。
    版本控制 模型、产品和规则版本是每次检查时捕获的不可变标识符。
    JSON 仅将 JSON 用于有界快照或不断变化的细节。查询关键值仍然是类型列。
    删除 配置使用存档/软删除。检查和审计删除是受控保留操作，而不是普通的 API 删除。

    14.3 规范 Pydantic 2 模型¶

    这些传输/域模型独立于 SQLAlchemy 持久性类。它们构成了 FastAPI 模式的真实来源。

    from __future__ import annotations

from datetime import datetime
from enum import StrEnum
from typing import Annotated, Literal
from uuid import UUID

from pydantic import BaseModel, ConfigDict, Field, model_validator

Confidence = Annotated[float, Field(ge=0.0, le=1.0)]
NonNegativeInt = Annotated[int, Field(ge=0)]


class APIModel(BaseModel):
    model_config = ConfigDict(extra="forbid", from_attributes=True)


class InternalDecision(StrEnum):
    OK = "OK"
    NG = "NG"
    UNCERTAIN = "UNCERTAIN"


class BusinessResult(StrEnum):
    OK = "OK"
    NG = "NG"


class InspectionLifecycle(StrEnum):
    OPEN = "OPEN"
    EVALUATING = "EVALUATING"
    COMPLETED = "COMPLETED"
    ABORTED = "ABORTED"


class UploadTaskState(StrEnum):
    PENDING = "PENDING"
    IN_PROGRESS = "IN_PROGRESS"
    RETRY_WAIT = "RETRY_WAIT"
    SUCCEEDED = "SUCCEEDED"
    PERMANENT_FAILURE = "PERMANENT_FAILURE"
    CANCELLED = "CANCELLED"


class DeviceOperationalState(StrEnum):
    STARTING = "STARTING"
    READY = "READY"
    INSPECTING = "INSPECTING"
    DEGRADED = "DEGRADED"
    PAUSED = "PAUSED"
    MAINTENANCE = "MAINTENANCE"
    FAULTED = "FAULTED"


class MediaLifecycle(StrEnum):
    PENDING = "PENDING"
    AVAILABLE = "AVAILABLE"
    FAILED = "FAILED"
    PURGED = "PURGED"


class BoundingBox(APIModel):
    x_min: Annotated[float, Field(ge=0)]
    y_min: Annotated[float, Field(ge=0)]
    x_max: Annotated[float, Field(gt=0)]
    y_max: Annotated[float, Field(gt=0)]
    image_width: Annotated[int, Field(gt=0)]
    image_height: Annotated[int, Field(gt=0)]

    @model_validator(mode="after")
    def validate_bounds(self) -> BoundingBox:
        if not (self.x_min < self.x_max <= self.image_width):
            raise ValueError("x bounds must be ordered and inside the image")
        if not (self.y_min < self.y_max <= self.image_height):
            raise ValueError("y bounds must be ordered and inside the image")
        return self


class Detection(APIModel):
    class_name: str = Field(min_length=1, max_length=100)
    confidence: Confidence
    bbox: BoundingBox
    frame_id: UUID
    track_id: str | None = Field(default=None, max_length=100)


class FrameQuality(APIModel):
    usable: bool
    blur_score: Annotated[float, Field(ge=0)]
    brightness_mean: Annotated[float, Field(ge=0, le=255)]
    saturation_fraction: Confidence
    occlusion_fraction: Confidence | None = None
    reason_codes: list[str] = Field(default_factory=list)


class ReasonCount(APIModel):
    reason_code: str
    count: NonNegativeInt


class FrameQualitySummary(APIModel):
    total_frame_count: NonNegativeInt
    usable_frame_count: NonNegativeInt
    rejected_frame_count: NonNegativeInt
    reasons: list[ReasonCount] = Field(default_factory=list)


class BarcodeResult(APIModel):
    status: Literal["READ", "NOT_READ", "CONFLICT", "NOT_REQUIRED"]
    value: str | None = Field(default=None, max_length=256)
    symbology: str | None = Field(default=None, max_length=64)


class ProductResolution(APIModel):
    status: Literal["RESOLVED", "UNKNOWN", "CONFLICT"]
    source: Literal["BARCODE", "MANUAL", "CONFIGURED_DEFAULT", "NONE"]
    product_code: str | None = None
    product_version_id: UUID | None = None


class MediaMetadata(APIModel):
    media_id: UUID
    kind: Literal["KEY_FRAME", "ANNOTATED_FRAME", "PRODUCT_ROI", "NG_CLIP", "ROLLING_VIDEO"]
    lifecycle: MediaLifecycle
    relative_path: str
    mime_type: str
    size_bytes: NonNegativeInt
    checksum_sha256: str = Field(pattern=r"^[0-9a-f]{64}$")


class ProductDetection(APIModel):
    frame_id: UUID
    product_class: str
    confidence: Confidence
    bbox: BoundingBox
    model_version_id: UUID
    quality: FrameQuality


class ROIResult(APIModel):
    frame_id: UUID
    product_bbox: BoundingBox
    roi_bbox: BoundingBox
    roi_width: Annotated[int, Field(gt=0)]
    roi_height: Annotated[int, Field(gt=0)]
    orientation_degrees: float | None = None
    transform_full_to_roi: tuple[float, float, float, float, float, float]
    media_id: UUID | None = None


class ComponentDetection(APIModel):
    frame_id: UUID
    component_code: str
    confidence: Confidence
    roi_bbox: BoundingBox
    full_frame_bbox: BoundingBox
    model_version_id: UUID


class AggregatedComponentEvidence(APIModel):
    component_code: str
    state: Literal["PRESENT", "MISSING", "UNCERTAIN"]
    best_confidence: Confidence | None = None
    usable_frame_count: NonNegativeInt
    detection_count: NonNegativeInt
    adjacent_detection_run: NonNegativeInt
    supporting_frame_ids: list[UUID]
    policy_reason_codes: list[str]


class InspectionDecision(APIModel):
    internal_decision: InternalDecision
    business_result: BusinessResult
    missing_components: list[str]
    low_confidence_components: list[str]
    reason_codes: list[str]
    decided_at: datetime


class InspectionRecord(APIModel):
    inspection_id: UUID
    device_id: UUID
    device_sequence: Annotated[int, Field(gt=0)]
    lifecycle_status: InspectionLifecycle
    started_at: datetime
    completed_at: datetime
    barcode_result: BarcodeResult
    product_resolution: ProductResolution
    product_detection: ProductDetection | None = None
    roi_result: ROIResult | None = None
    frame_quality_summary: FrameQualitySummary
    application_version: str
    product_model_version_id: UUID
    product_model_checksum_sha256: str = Field(pattern=r"^[0-9a-f]{64}$")
    component_model_version_id: UUID
    component_model_checksum_sha256: str = Field(pattern=r"^[0-9a-f]{64}$")
    rule_version_id: UUID
    aggregation_policy_version: str
    evidence: list[AggregatedComponentEvidence]
    media: list[MediaMetadata]
    decision: InspectionDecision
    synchronization_status: Literal["LOCAL_ONLY", "QUEUED", "PARTIAL", "SYNCED", "FAILED"]
    processing_ms: NonNegativeInt


class UploadTask(APIModel):
    upload_task_id: UUID
    device_id: UUID
    inspection_id: UUID | None = None
    kind: Literal["INSPECTION", "MEDIA", "DEVICE_EVENT"]
    object_id: UUID
    payload_hash: str = Field(pattern=r"^[0-9a-f]{64}$")
    status: UploadTaskState
    idempotency_key: str
    checksum_sha256: str | None = Field(default=None, pattern=r"^[0-9a-f]{64}$")
    attempt_count: NonNegativeInt = 0
    next_attempt_at: datetime | None = None
    last_error_code: str | None = None
    created_at: datetime
    updated_at: datetime
    completed_at: datetime | None = None
    lease_owner: str | None = None
    lease_expires_at: datetime | None = None


class DeviceStatus(APIModel):
    device_id: UUID
    observed_at: datetime
    operational_state: DeviceOperationalState
    inspection_ready: bool
    sync_ready: bool
    camera_connected: bool
    model_loaded: bool
    central_connected: bool
    disk_free_bytes: NonNegativeInt
    upload_pending_count: NonNegativeInt
    current_product_model_version_id: UUID | None = None
    current_component_model_version_id: UUID | None = None
    current_rule_version_id: UUID | None = None
    alerts: list[str] = Field(default_factory=list)


class ProductConfiguration(APIModel):
    product_version_id: UUID
    product_id: UUID
    product_code: str
    version: Annotated[int, Field(gt=0)]
    barcode_patterns: list[str]
    required_component_codes: list[str]
    active_from: datetime | None = None


class ComponentPolicy(APIModel):
    component_code: str
    high_confidence: Confidence
    medium_confidence: Confidence
    minimum_medium_detections: Annotated[int, Field(gt=0)]
    require_adjacent_frames: bool = False


class RuleConfiguration(APIModel):
    rule_version_id: UUID
    rule_id: UUID
    product_version_id: UUID
    version: Annotated[int, Field(gt=0)]
    component_policies: list[ComponentPolicy]
    minimum_usable_frames: Annotated[int, Field(gt=0)]
    uncertain_maps_to_ng: Literal[True] = True
    published_at: datetime | None = None


class Artifact(APIModel):
    name: str
    uri: str
    sha256: str = Field(pattern=r"^[0-9a-f]{64}$")
    size_bytes: NonNegativeInt


class DatasetReference(APIModel):
    dataset_version: str
    purpose: Literal["TRAIN", "VALIDATION", "TEST", "ACCEPTANCE"]
    manifest_uri: str


class ModelMetric(APIModel):
    name: str
    value: float
    scope: str


class ModelManifest(APIModel):
    model_version_id: UUID
    model_id: UUID
    semantic_version: str
    task: Literal["PRODUCT_DETECTION", "COMPONENT_DETECTION"]
    runtime: str
    input_width: Annotated[int, Field(gt=0)]
    input_height: Annotated[int, Field(gt=0)]
    class_names: list[str]
    artifacts: list[Artifact]
    datasets: list[DatasetReference]
    split_strategy: str
    source_revision: str
    training_config_revision: str
    metrics: list[ModelMetric]
    limitations: list[str]
    approved_by: str | None = None
    approved_at: datetime | None = None
    supersedes_model_version_id: UUID | None = None
    created_at: datetime


class ComponentCorrection(APIModel):
    component_code: str
    state: Literal["PRESENT", "MISSING", "UNCERTAIN"]


class ReviewRecord(APIModel):
    review_id: UUID
    inspection_id: UUID
    reviewer_user_id: UUID
    original_internal_decision: InternalDecision
    original_business_result: BusinessResult
    reviewed_disposition: Literal["CONFIRMED_OK", "CONFIRMED_NG", "REINSPECT", "INCONCLUSIVE"]
    component_corrections: list[ComponentCorrection]
    reason_code: str
    comment: str | None = Field(default=None, max_length=2000)
    reviewed_at: datetime
    revision: Annotated[int, Field(gt=0)]

    15 个必需的公共模型是 BoundingBox、Detection、FrameQuality、ProductDetection、ROIResult、ComponentDetection、AggregatedComponentEvidence、InspectionDecision、InspectionRecord、UploadTask、DeviceStatus、ProductConfiguration、RuleConfiguration、ModelManifest 和 ReviewRecord。条形码、分辨率、生命周期、媒体、数据集、指标和校正类型支持值对象，并且仍然是生成的 API 合约的一部分。

    14.4 匹配 TypeScript 类型¶

    这些界面显示了预期生成的形状。前端应该导入生成的类型，而不是手动维护此块。 UUID 和日期时间在应用程序边界仍然是品牌别名，因为 JSON 携带字符串。

    14.4.1 支持模式注册表的 API¶

    REST API and Events 中的每个命名模式都必须是类型化的 Pydantic OpenAPI 中的模型。最小注册表是：

    模式家族 所需型号
    错误和分页 Problem、ProblemFieldError、Page[T]、不透明游标元数据
    运行时 CameraState、InspectionRuntimeState、OperationAccepted、EffectiveConfiguration、ValidationResult
    检验查询 InspectionSummary、CentralInspectionDetail、MediaMetadata
    食入 UploadReceipt、MediaUploadInitiate、MediaUploadComplete、DeviceEventBatch、每件收据
    配置 ConfigurationCandidate、LocalOverrides、DesiredConfiguration、分配/验证/激活确认
    行政 输入站点、线路、设备、用户、仪表板、报告和审核请求/响应预测

    Problem 使用 API 合约中的 application/problem+json 字段。请求模型保留 extra="forbid"； WebSocket 事件负载消费者允许在同一事件负载中添加未知字段 架构版本。事件 sequence 对于 (source_id, channel) 是单调的，并且仅当 源身份变更。

    14.5 边缘模式¶

    SQLite 是 MVP 默认值。在检查吞吐量允许的情况下启用 WAL 模式、外键、busy_timeout 和 synchronous=FULL。每个最终框架或检查都保留一份短写交易；媒体字节保留在文件系统中。

    表 关键列和主要列 限制和目的
    local_inspections id PK UUID、device_id、device_sequence、生命周期、时间戳、条形码状态/值、产品解析、内部决策、业务结果、应用程序/产品模型/组件模型/规则版本和校验和、原因 JSON、延迟 UNIQUE(device_id, device_sequence)；耐用的产品级结果和同步单元。
    local_detection_frames id PK、inspection_id FK、frame_index、捕获时间、质量字段、产品 bbox JSON UNIQUE(inspection_id, frame_index)；可选的详细证据的保留时间较短。
    local_component_evidence id PK、inspection_id FK、组件代码、状态、置信度/计数字段、原因 JSON UNIQUE(inspection_id, component_code);最终每个组件的证据。
    local_media_files id PK、inspection_id FK 可为空、种类、相对路径、MIME 类型、字节、SHA-256、捕获时间、需要上传标志 路径必须相对于配置的媒体根； UNIQUE(relative_path) 和 UNIQUE(sha256, kind) ，其中重复数据删除是安全的。
    upload_tasks id PK、设备/检查/对象 ID、种类、有效负载哈希、校验和、幂等性密钥、规范状态、尝试、租约所有者/到期、下次尝试、时间戳、错误 UNIQUE(device_id, idempotency_key)；具有可恢复租约的持久发件箱。
    device_events id PK、发生时间、严重程度、事件代码、详情JSON、上传状态 仅附加操作事件流。
    local_configuration key PK、修订、值 JSON、来源、应用时间、校验和 原子有效配置快照；在历史或事件记录中保留先前的快照。
    model_installations model_version_id PK、清单 JSON、本地路径、SHA-256、状态、安装/激活时间 每个任务只有一个活动安装，以事务方式强制执行。
    rule_installations rule_version_id PK、产品版本 ID、文档 JSON、校验和、状态、安装/激活次数 激活验证兼容的模型类和产品版本。

    所需的边索引：

    CREATE INDEX ix_local_inspections_completed ON local_inspections(completed_at DESC);
CREATE INDEX ix_local_inspections_barcode ON local_inspections(barcode) WHERE barcode IS NOT NULL;
CREATE INDEX ix_local_inspections_result_time ON local_inspections(business_result, completed_at DESC);
CREATE INDEX ix_upload_tasks_due ON upload_tasks(state, next_attempt_at);
CREATE INDEX ix_media_inspection_kind ON local_media_files(inspection_id, kind);
CREATE INDEX ix_device_events_time ON device_events(occurred_at DESC);

    14.6 中心模式¶

    PostgreSQL 拥有租户隔离和全局历史记录。每个租户拥有的行都带有 organization_id；即使稍后启用行级安全性，存储库查询也必须对其进行范围限制。

    表 关键列和主要列 限制和目的
    organizations UUID PK、唯一的 slug、名称、状态 租户根；归档而不是删除。
    sites UUID PK、组织 FK、代码、名称、时区 UNIQUE(organization_id, code)。
    production_lines UUID PK、站点 FK、代码、名称 UNIQUE(site_id, code)。
    devices UUID PK、线路 FK、设备代码、证书身份、状态、上次查看 UNIQUE(organization_id, device_code)；证书身份单独唯一。
    users、roles、user_roles UUID 键、组织范围、身份主体、角色名称、连接行 身份提供者主体唯一；赋值具有复合唯一性。
    products、product_components 产品UUID/代码；组件代码/名称/活动状态 组件成员资格通过产品版本快照进行版本控制，不会在历史检查中被覆盖。
    product_versions UUID PK、产品FK、整数版本、不可变配置JSON、发布时间 UNIQUE(product_id, version)；发布后没有更新。
    rules、rule_versions 稳定的规则身份和不可变的版本文档，产品版本FK 草稿可编辑；发布的版本不可变且具有唯一编号。
    model_packages、model_versions 稳定的模型身份；任务、语义版本、清单、工件 URI/校验和、生命周期状态 UNIQUE(model_id, semantic_version)；发布后不可更改。
    inspections UUID PK 匹配边缘 ID、组织/设备 FK、设备序列、生命周期/时间、条形码/产品分辨率、内部决策、业务结果、应用程序/产品模型/组件模型/规则版本和校验和、延迟、接收时间 UNIQUE(device_id, device_sequence)；保留准确的运行时版本。
    inspection_components UUID PK、检查 FK、组件代码、状态、置信度/计数、原因 UNIQUE(inspection_id, component_code)。
    inspection_media UUID PK 匹配边缘对象 ID、检查 FK、种类、对象密钥、MIME、字节、SHA-256、捕获/接收时间 UNIQUE(device_id, source_media_id) 和验证后的不可变对象密钥。
    review_records UUID PK、检查/审阅者 FK、结果、更正、原因、修订、时间 UNIQUE(inspection_id, revision)；修订追加，切勿覆盖。
    device_events UUID PK 匹配源事件 ID、设备 FK、源/接收时间、严重性/代码/详细信息 幂等事件摄取。
    upload_receipts UUID PK、设备FK、幂等密钥、请求哈希、资源类型/ID、状态、响应代码/时间 UNIQUE(device_id, idempotency_key)；哈希不匹配是一种冲突。
    audit_logs UUID PK、组织/参与者、操作、资源类型/ID、JSON 之前/之后、请求/关联 ID、IP、时间 仅附加安全和配置审核。

    仅当测量的数量证明其合理性时，才对 inspections、device_events 和 audit_logs 使用每月范围分区。过早的分区会使外键和迁移变得复杂。

    14.8 键、索引和查询路径¶

    • 主键是持久化之前生成的UUID。因此，边缘可以离线创建记录。
    • 业务密钥是组织别名、站点/线路/设备代码、产品代码、组件代码、(device_id, device_sequence) 及其稳定父级中的版本号。
    • 使用 (organization_id, barcode, completed_at DESC) 索引中央条形码查询并使用排除空条形码的部分谓词。不要全局限制条形码的唯一性，因为可能会出现返工和重复读取。
    • 使用 (organization_id, completed_at DESC) 和 (device_id, completed_at DESC) 索引仪表板时间扫描。为产品/型号/规则/原因查询路径的 NG 队列和索引添加 (organization_id, business_result, completed_at DESC)。
    • 对业务结果为NG且审核状态为待审核的检查使用部分索引来索引待审核；内部 UNCERTAIN 仍然是可过滤的原因/状态。
    • 索引连接中使用的所有外键。在添加置信度/组件综合索引之前，使用类似生产的基数验证计划。
    • 使用键集分页 (completed_at, id) < (:cursor_time, :cursor_id) 来获取历史记录。偏移分页仅适用于小型配置列表。

    14.9 媒体元数据和完整性¶

    数据库存储媒体元数据，而不是大图像/视频 blob。 Edge 写入临时路径（在支持的情况下fsync），自动重命名、计算 SHA-256，然后提交元数据及其上传任务。集中上传使用暂存对象密钥； API 在标记媒体可用之前验证大小和校验和。在最终对象存在之前，数据库行不得声明 AVAILABLE。

    对象键是不透明的且具有租户范围，例如 org/{organization_id}/device/{device_id}/2026/08/04/{media_id}.jpg。 API 响应发出授权的短期 URL，而不是公开存储凭据。

    14.10 保留和安全清理¶

    保留值是部署配置，而不是硬编码的默认值。清理工人应用此命令：

    1. 切勿删除具有非终端所需上传任务的媒体文件。
    2. 在 NG 证据之前，优先删除滚动视频并上传 OK 媒体。
    3. 删除文件/对象，验证是否存在，然后用原因和时间戳标记元数据 PURGED。
    4. 保留检查元数据的时间长于大容量帧和媒体细节。
    5. 在任何保单之前应用法律保留和调查保留。
    6. 通过记录的保留作业删除中心对象和数据库详细信息；如果需要进行审计核对，请保留墓碑。

    建议的策略类别（待客户批准）包括滚动视频（小时/天）、帧详细信息（天）、OK 关键帧（短）、NG 证据（较长）、检查元数据（长）、操作日志（有界）和审核日志（安全/合规术语）。请参阅the source brief中的任务要求。

    14.11 审计和变更规则¶

    • 审核登录、角色分配、设备注册、配置草稿/发布/激活、模型生命周期更改、手动审核、导出、保留和打破玻璃操作。
    • 存储参与者类型（USER、DEVICE、SYSTEM）、参与者 ID、操作、目标、删除机密的前后值、UTC 时间、请求 ID 和原因（如果需要）。
    • 已发布的产品、模型和规则版本是不可变的。更正创建新版本。
    • 评论是仅附加的修订。 UI 会预测最新修订版本，而所有修订版本仍可查询。
    • 审核行仅附加到应用程序角色。行政变更需要单独记录的操作程序。
    • 根据客户政策，敏感条形码和身份数据必须在一般日志和导出中进行屏蔽。

    14.12 迁移和恢复¶

    Alembic 通过单独的迁移分支/配置拥有这两种模式。边缘升级进行数据库备份、停止新的检查窗口、应用前向迁移、验证架构修订并恢复。长 SQLite 重写需要磁盘空间预检。集中迁移使用扩展/迁移/收缩更改，因此可以在部署期间运行混合 API 版本。

    边缘恢复可协调媒体路径、过期的上传租约以及启动时不完整的检查窗口。中断的窗口以生命周期状态 ABORTED 持久化；如果需要业务结果，则为 NG，并且记录永远不能变为 OK。数据库备份不会取代介质备份策略。

    14.13 OpenAPI同步策略¶

    1. 共享Python域包中的Pydantic模型由FastAPI请求和响应声明直接引用。
    2. CI 启动/导入每个 API，并使用固定的 FastAPI/Pydantic 工具链发出确定性的 edge-openapi.json 和 central-openapi.json。
    3. CI 验证每个文档并检查提交/生成的工件是否存在偏差。
    4. openapi-typescript 或 Orval 生成 TypeScript 模式和客户端到 packages/typescript/api-client/generated 中；生成的文件不需手动编辑。
    5. 前端包装器添加了身份验证和错误映射等传输问题，而无需重新定义有效负载。
    6. 合约测试反序列化代表性服务器响应并运行 TypeScript 类型检查。重大架构更改需要版本化端点或协调发布。
    7. 在需要时在前端边界添加日期时间和 UUID 运行时验证；单独生成的 TypeScript 类型并不能验证 JSON。

    OpenAPI 涵盖按名称引用的 REST 快照和 WebSocket 事件负载模式。由于 OpenAPI 没有完全描述 WebSocket 通道，因此事件信封从相同的 Pydantic 类导出为 JSON 模式，并针对前端验证器进行测试。

    14.14 未解决的问题和需要验证¶

    • 确认每个设备的预期检查、帧、事件和媒体量以及保留级别。
    • 确认本地 SQLite 是否足够，或者较大的边缘安装是否需要 PostgreSQL。
    • 确认条形码格式、灵敏度分类以及条形码搜索是否需要标准化变体。
    • 与客户就中央和边缘保留期、合法保留、删除证据和审计保留达成一致。
    • 确认租户隔离要求以及 PostgreSQL 行级安全性是否是强制性的。
    • 确认客户时钟同步能力和可接受的时钟漂移处理。
    • 验证所选 Python 和 PostgreSQL 版本中的 UUIDv7 库/工具支持。
    • 定义内部 UNCERTAIN 状态是否作为解释性细节在外部可见；其业务和物理路径仍然是NG。
