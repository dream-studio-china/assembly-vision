    16. 边缘仪表板¶

    16.1 目的和用户¶

    边缘仪表板是由本地边缘服务提供服务的 Vue 3 和 TypeScript Web 应用程序。它支持生产线操作员和维护人员，而无需参与检查决策路径。当浏览器关闭、仪表板崩溃或无法访问中央服务器时，检查会继续进行。

    仪表板使用 REST API and Events 中的边缘合约以及从 Data Model and Database 生成的类型。 Monorepo 放置在 Monorepo and Code Organization 中定义。

    16.2 设计原则¶

    1. 最新安全相关结果一目了然；不要在导航背后隐藏 NG 原因。
    2. 区分检查准备情况和中央连接。中心服务器离线并不意味着检查失败。
    3. 切勿仅从 WebSocket 事件推断​​系统状态；重新连接或序列间隙后从 REST 进行协调。
    4. 在与中央服务断开连接时保留可用的本地历史记录和控制。
    5. 需要明确确认以及暂停、恢复、重新连接、重试或配置更改的原因。
    6. 结合使用文字、图像和颜色。仅红/绿是不够的。
    7. 避免将高置信度检测显示为整体正常的证明；最终的决定性决定具有权威性。

    16.3 信息架构¶

    路线 主要目的 角色 数据来源
    / 现场检查和当前运行状态 观察者、操作者 状态 REST 快照和运行时 WebSocket
    /inspections 搜索最近的本地记录 观众 本地检查REST API
    /inspections/:id 审查证据、覆盖图、版本和媒体 观众 检查/媒体 REST API
    /uploads 队列状态、失败和手动重试 观众；操作员重试 上传 REST API 和事件
    /health 相机、模型、磁盘、网络、数据库、服务健康度 观众 设备/相机/健康 API
    /configuration 有效的配置和允许的本地覆盖边缘管理员 配置 API
    /logs 有界本地结构化日志 边缘管理员 日志API

    顶部栏始终显示设备代码、线路标签（如果已配置）、检查状态、本地时钟、中央连接、磁盘警告和经过身份验证的用户。如果预览流不可用，应用程序必须保持可导航。

    16.4 现场检查屏幕¶

    16.4.1 布局¶

    桌面使用主摄像头/证据窗格和固定宽度的决策窗格。在 1280 像素及以上，两者均可见，无需垂直滚动。平板电脑/移动设备堆栈首先是决策，然后是证据，最后是诊断；暂停/恢复仍然可以访问，但不是可以意外触发的浮动控件。

    屏幕包括：

    • 相机预览包含缩放、源分辨率、捕获时间戳和陈旧帧标记。
    • 从源坐标映射的可选产品和组件边界框，从不预先缩放服务器坐标。
    • 最终的 OK、NG 或 UNCERTAIN 面板，包含检查 ID、条形码、产品类型、处理延迟和完成时间。
    • 所需组件矩阵：存在、缺失、不确定、最佳置信度、支持框架计数和政策原因。
    • 相机、模型、规则、本地数据库、磁盘和检查引擎的就绪条。
    • 连接条分隔本地 API、网络接口、DNS/中央可达性和上传积压。
    • 最近的结果栏至少显示最近十次检查，并带有可通过键盘访问的详细信息链接。

    16.4.2 结果呈现¶

    OK 可以使用绿色，但包含单词“OK”和复选图标。 NG 使用红色、“NG”一词、警报图标以及缺失/不确定的组件名称。 UNCERTAIN 使用琥珀色并说明物理处理路径是否将其视为 NG。新结果使用简短的非阻塞转换；动画必须尊重简化动作偏好。

    条形码故障、未知产品、不可用框架、型号故障和缺少组件是单独的原因代码。 UI 不得将所有 NG 结果折叠为“组件缺失”。

    16.4.3 预览传输¶

    仅当延迟要求合理时才使用带宽受限的 JPEG/MJPEG 或 WebRTC 预览。不要通过 JSON WebSocket 消息发送完整的生产帧。覆盖事件携带源维度和框； UI 会丢弃帧 ID 与显示的预览帧不匹配的叠加。预览丢失永远不会改变检查引擎的状态。

    16.5 检查历史和详细信息¶

    历史记录默认为最新的优先，并支持业务结果、内部决策、条形码、产品和有界日期过滤器。搜索已去抖且在服务器端进行；游标分页会阻止加载完整的本地数据库。一行显示完成时间、业务结果、内部决策详细信息、条形码、产品、原因摘要、延迟、上传状态和模型/规则版本。

    详细信息页面包含：

    • 不可变的身份和捕获时间戳。
    • 决策原因代码和每个组件的汇总证据。
    • 产品和组件检测叠加，带有切换开关和可访问的组件列表。
    • 仅当媒体存在时，关键帧、产品 ROI、带注释的图像和剪辑选项卡。
    • 帧质量指标和源/全帧坐标元数据。
    • 模型、规则和产品配置版本标识符。
    • 上传任务状态和上次失败，而不暴露凭据或堆栈跟踪。

    清除的媒体显示元数据和清除原因，而不是损坏的图像。视频使用范围请求并提供静态后备关键帧。

    16.6 上传队列¶

    队列页面组 PENDING、IN_PROGRESS、RETRY_WAIT、PERMANENT_FAILURE、CANCELLED 和 SUCCEEDED 计数。默认行显示未完成的任务、下一次尝试、尝试计数、对象类型、检查链接、字节和已清理的错误代码。仪表板解释说，在页面未打开的情况下会继续重试。

    手动重试仅针对重试/死信任务启用，需要确认和原因，并发送幂等密钥。它不会创建第二个任务。批量重试被推迟，直到操作证据表明有必要；无限制的批量重试可能会在中断后使中央服务器过载。

    16.7 健康状况和警报¶

    状况 用户界面状态 所需的操作员指导
    相机已断开连接 严重，检查尚未准备好 检查电缆/电源；管理员可能会请求重新连接
    模型或规则不可用/不兼容 严重，没有新窗口 显示活动/所需版本和升级说明
    磁盘低于警告阈值 警告 在没有发明剩余时间的情况下显示可用字节、保留活动和估计风险
    盘面低于停止阈值 关键 说明捕获是否暂停；永远不要默默地丢弃所需的证据
    中央无法到达 降级，而非检查失败 显示离线持续时间和持久队列计数
    队列死信存在 警告 显示任务/错误和重试/升级路径
    检测到时钟漂移 警告或严重阈值 显示测量的漂移和时间源检查
    检查暂停 突出的中立/琥珀状态 如有可能，请显示演员、原因和时间

    警报具有稳定的代码、严重性、第一个/最后一个观察到的时间戳以及活动/清除状态。浏览器 toast 通知是补充，但绝不会取代持久状态。

    16.8 本地配置¶

    该页面将集中管理值、本地覆盖值和有效值分开。托管字段是只读的。可编辑 MVP 字段应仅限于明确批准的操作设置，例如预览首选项或允许的本地存储阈值；检测器阈值和决策规则通常应集中版本化。

    配置工作流程：

    1. 加载有效配置和修订。
    2. 编辑包含字段级单位、范围和说明的草稿。 3.通过API验证，无需激活。
    3. 显示语义差异和需要重新启动或检查暂停的影响。
    4. 需要管理员确认并说明理由。
    5. 使用If-Match提交；如果发生冲突，请故意重新加载并重新应用。
    6. 显示激活结果和审核/事件标识符。

    切勿在生产中向操作员提供任意 JSON 编辑。

    16.9 暂停和恢复安全¶

    暂停意味着停止打开新产品窗口。 API 拥有活动窗口的行为：安全完成或根据配置的策略标记为中止。确认确定了结果并捕获了原因。在相机、模型、规则、数据库和磁盘先决条件通过之前，恢复将保持禁用状态。 UI 显示 API 拒绝详细信息，并且在确认之前不得乐观地显示 READY。

    紧急机器停止是工厂安全控制问题，不得以网络按钮表示，除非与经过验证的机械控制集成。仪表板暂停是应用程序级检查控制，而不是紧急停止。

    16.10 状态和数据流¶

    • Vue Router 控制路由授权和深度链接。
    • Pinia 仅存储会话、有效权限、运行时快照、警报状态和轻量级 UI 首选项。
    • 历史查询仍然是页面本地/服务器驱动的；不要将检查数据库镜像到 Pinia 中。
    • 生成的 OpenAPI 客户端处理键入的 REST。单个 WebSocket 服务验证信封并调度资源失效。
    • 启动时：获取会话、权限、状态和当前检查；然后连接WebSocket。
    • 重新连接或序列间隙时：将数据标记为过时，重新获取快照，然后清除过时状态。
    • 使用带有抖动和上限的指数重新连接退避。浏览器重新连接行为不得影响边缘上传重试。

    16.11 失败、加载和空状态¶

    每个窗格都定义加载、无数据、陈旧数据、授权拒绝和服务错误状态。最后已知的状态可能会通过明确的“最后更新”时间戳保持可见；它看起来一定不是最新的。失败的命令保留表单输入和请求 ID。缺少预览不会使结果面板变为空白。 Service Worker 不得缓存经过身份验证的 API 响应；静态资产可以通过版本安全更新进行缓存，以实现本地恢复。

    16.12 可访问性、性能和安全性¶

    • 键盘操作、焦点、对比度、标签、对话框、表格和非颜色状态指示器符合 WCAG 2.1 AA。
    • 仅虚拟化已证明较大的表；光标分页是第一个控件。
    • 延迟加载视频和高级查看器代码。保持初始实时屏幕资源对于目标边缘硬件而言足够小。
    • 清理文件名和日志文本，禁止原始 HTML，并使用限制性内容安全策略。
    • 在使用会话的地方使用安全、仅限 HTTP、同站点 cookie；保护突变免受 CSRF 的影响。
    • 不要在分析中放置令牌、条形码或媒体 URL。本地仪表板不应依赖于第三方 CDN。

    16.13 测试与验收¶

    Vitest 涵盖存储、原因代码渲染、坐标转换、权限和重新连接协调。组件测试涵盖所有结果/健康状态和键盘行为。 Playwright 练习实时结果到达、过时连接恢复、历史记录/详细信息、清除媒体、队列重试、配置冲突、暂停/恢复拒绝和离线中心操作。视觉测试使用代表性的 4:3 图像和长组件/条形码字符串。

    验收检查包括：

    • 在仪表板关闭且中央断开的情况下，检查仍处于活动状态。
    • 在不丢失最新结果的情况下协调 WebSocket 间隙。
    • 不打开模态即可看到 NG 原因和缺少的组件。
    • 边界框在调整大小和全屏模式下保持对齐。
    • 未授权控件不可用，服务器授权仍拒绝直接调用。
    • 实时视图在商定的工业显示分辨率和狭窄的维护设备上仍然可用。

    16.14 MVP 及后续范围¶

    MVP 包括实时状态/最新结果、最近历史记录/详细信息、运行状况、队列可见性/手动重试以及暂停/恢复（如果操作获得批准）。本地覆盖编辑和日志可能是仅限管理员的后期 MVP 功能。后续添加的内容可能包括 WebRTC 预览、信息亭打包/Tauri、警报确认工作流程、引导相机校准和更丰富的多帧证据回放。静态训练和检查 MVP 不需要任何操作。

    16.15 未决问题和需要验证¶

    • 确认生产线上的显示尺寸、浏览器、信息亭模式、触摸/键盘使用、语言和辅助功能需求。
    • 确认是否允许应用程序暂停/恢复以及如何处理活动产品。
    • 确认边缘计算机上可接受的预览帧速率、延迟和带宽。
    • 确认哪些配置字段可以在本地被覆盖以及哪些角色可以这样做。
    • 验证警告/停止磁盘阈​​值和操作员恢复指令。
    • 确认离线时本地身份验证是否必须与客户身份系统集成。
