    28. 边缘验收报告¶

    28.1 目的和证据原则¶

    Edge 验收报告是单一的基于证据的记录，用于声明已定义域（站点、设备、相机设置、产品组合和软件/模型/规则/配置版本）的 Edge 版本已接受、有条件接受或拒绝。它整合了已执行的测试矩阵、测量的指标、弹性证据、锁定的工件以及验收（设计 26）所基于的残余风险决策。

    该报告从未声称具有普遍性或未经验证的数字保证，也从未声称 100% 准确。每个测量数据都与测试的领域和版本相关联；未测量的字段被记录为NOT_MEASURED并且永远不会被伪造。具有 NOT_MEASURED 指标的报告可以记录准备就绪情况，但它本身不能声明生产验收。

    28.2 何时需要报告以及何时可以发布报告¶

    在 Edge 版本被宣布接受或有条件接受用于生产之前，以及每当重大更改后重新验证需要新的验收声明时，都需要提供 Edge 验收报告（设计 26.10）。

    该报告分两个阶段制作：

    • E6-prep 草稿： 在 E6-prep 期间可以在没有真实环境的情况下起草报告。它记录环境和先决条件、候选版本、锁定的工件、验收协议参考和计划的测试矩阵。指标和弹性证据默认为 NOT_MEASURED。准备稿是准备记录，而不是接受。
    • 现场验收运行： 正式验收需要针对真实环境和看不见的客户数据执行现场证据。准备草案由执行的测试矩阵、测量指标、弹性证据、浸泡证据、偏差和签核完成。

    在没有真实环境输入的情况下起草的报告必须明确说明缺失的输入（例如，硬件、相机/SDK、未见过的数据或见证人可用性）并标记每个受影响的字段 NOT_MEASURED。在代表性恢复成功之前，备份不被视为可操作（设计 20.10），因此报告只能在记录执行的恢复时将备份/恢复视为证据。仅准备的报告永远不会触发生产验收的签字。

    28.3 报告结构¶

    该报告遵循此逐节模板。未测量或不适用的字段标记为 NOT_MEASURED 或 NOT_EXECUTED，绝不会默默省略。

    28.3.1 封面¶

    • 候选版本：应用程序、产品/组件模型和校验和、规则、产品配置和审核策略，每个版本都有版本和校验和。
    • 设备/硬件标识符和硬件描述。
    • 站点和线路。
    • 报告日期：起草日期、执行开始/结束和签署日期。
    • 状态：DRAFT (E6-prep)、COMPLETE-PENDING-SIGN-OFF、ACCEPTED、CONDITIONALLY-ACCEPTED 或 REJECTED。

    28.3.2 环境和先决条件¶

    • 硬件：边缘计算机、CPU、GPU、内存、存储和 UPS（如果适用）。
    • GPU 型号和驱动程序/SDK 版本。
    • 相机供应商、型号、SDK/驱动程序和触发接口。
    • 条码扫描仪模型和解码器/SDK。
    • PLC/触发器集成和信号定义在范围内。
    • Docker/OS：操作系统、Docker 引擎和运行时版本。
    • 网络：拓扑、DNS、防火墙和声明的连接假设。

    每个先决条件都记录为 PRESENT、ABSENT 或 NOT_MEASURED。如果不满足先决条件，则需要说明影响并在解决之前阻止现场验收。

    28.3.3 锁定工件和校验和¶

    • 应用程序映像/包摘要和版本。
    • 产品/组件模型工件和校验和。
    • 规则工件和校验和。
    • 产品配置和校验和。
    • 检查策略和校验和。
    • 验收清单和校验和（设计 26.4）。

    锁定的工件集是在验收运行期间执行的集。任何验收证据都不能引用锁定组之外的工件。

    28.3.4 接受协议参考¶

    • 商定的验收协议及其版本/日期的链接。
    • 基线评估后与客户商定的指标目标。
    • 统计报告方法和不确定的基本事实的处理。
    • 停止条件和补救/重新测试政策。

    本文档中从未发明过目标；它们来自共同完成的方案（设计 26.3）。

    28.3.5 执行的测试矩阵¶

    身份证 场景 分类 结果 证据链接 笔记
    T-01 产品类型 必填 PASS/FAIL/SKIP/NOT_EXECUTED 链接/ID ...

    每行记录场景（来自设计 26.5 中的所需矩阵和 22.8 中的弹性案例）、分类（必需/可选）、结果、证据链接和注释。 SKIP 需要说明理由； NOT_EXECUTED 在计划场景但未运行时记录，并被视为未测量的证据。

    28.3.6 指标表¶

    公制 测量值 目标 置信区间 样本计数 状态
    不良召回 价值 协议 CI 计数 MEASURED/NOT_MEASURED

    指标列表和定义见第 28.5 节。目标仅根据基线后商定的协议来填充。

    28.3.7 弹性证据¶

    故障 注射方式 所需行为 结果 证据
    离线 中央端点/DNS 被阻止 地方决定继续进行；队列持续存在 ... ...

    设计 22.8 中的每个弹性案例（离线、网络抖动、重新启动、断电、磁盘压力、GPU 故障、数据库损坏、备份/恢复、容器重新启动、时钟漂移、校验和失败）都会记录注入方法、针对所需行为观察到的行为、结果和证据。仅当代表性恢复成功时，备份/恢复案例才算数。

    28.3.8 长期运行和浸泡证据¶

    • 持续时间、工作量概况、工作周期和商定的目标。
    • 资源趋势：CPU、GPU、内存、温度、磁盘 I/O、文件描述符和队列增长。
    • 浸泡窗口内的延迟稳定性。
    • 任何降级或数据丢失事件。

    28.3.9 偏差和未清项目¶

    • 与商定的协议、矩阵或目标集的偏差，每个偏差都有理由和所有者。
    • 未结清的项目不会阻碍规定的结果，并附有所有者和截止日期。

    28.3.10 风险和剩余风险签核¶

    • 适用于本版本和域的风险登记册（设计 27）中的剩余风险。
    • 接受的剩余风险、所有者和补偿控制。
    • 明确声明授权客户代表接受剩余风险。

    28.3.11 排除的操作域¶

    • 产品类型、摄像机角度/位置、照明方式、组件、PLC/MES 行为以及验证范围之外的吞吐量范围（设计 26.2.4）。
    • 明确声明排除的域不包含在此接受声明中。

    28.3.12 签核块¶

    • 供应商：角色、姓名、日期、签名。
    • 客户：角色、姓名、日期、签名。
    • 适用时，证人和事实真相裁决者。
    • 结果：接受、有条件接受（有限制）或拒绝。
    • 限制批准条件：补偿人工审核、范围限制、所有者和所需的补救措施。
    • 到期/审查条件和下次审查日期。

    28.4 证据和可追溯性要求¶

    每个执行的测试都会保留（镜像设计 26.6）：

    • 检查结果和原因代码。
    • 原始和选定的图像证据，以及配置的注释/ROI 证据。
    • 事实真相和裁决来源。
    • 应用程序、模型、规则、产品配置和审查策略版本。
    • 源和接收时间戳和设备标识符。
    • 条形码/产品映射结果。
    • 相关结构化日志、运行状况事件和阶段时间安排。
    • 上传任务和中央收据/校验和，其中同步在范围内。
    • 审阅者结果，其中人工验证是程序的一部分。

    证据是不可变的或受校验和保护，并通过检查标识符和报告的证据链接进行链接。可追溯性必须足够完整，以重建哪些锁定的工件、在哪个设备上、在哪个时间戳产生每个结果（设计 22.11 门 7）。

    28.5 度量定义¶

    每个指标报告定义、分子/分母、排除/不确定计数、有意义的置信区间以及按发布版本进行的细分。任何未执行测量的字段默认为NOT_MEASURED；没有捏造数值。基线评估后，根据客户协议商定目标（设计 26.3、22.7）。

    公制 定义 分子/分母 默认
    不良召回 真正的NG产品被归类为NG或路由至采用的不确定/手动路径 NG路由到NG/手动路径/真正的NG产品 NOT_MEASURED
    假阴性率 真正的NG产品被归类为OK 真正 NG 分类 OK/真正 NG 产品 NOT_MEASURED
    假阳性率 真正的 OK 产品被归类为 NG 真正的OK分类NG/真正的OK产品 NOT_MEASURED
    每个组件的召回 回忆一下每个缺少必需组件的场景 组件布线不良/组件缺失案例 NOT_MEASURED
    按产品召回 按产品类型细分的不良召回 按产品 NG 路由/按产品真实 NG NOT_MEASURED
    产品检测成功 产品可检查时产生的可用产品投资回报率 成功的产品检测/可检验产品 NOT_MEASURED
    投资回报率生成的成功 产品检测中有效、正确映射的 ROI 有效的投资回报率/产品检测 NOT_MEASURED
    条码读取成功 正确解析可读目标条形码中的条形码 正确读取/可读目标 NOT_MEASURED
    延迟（平均和 P95） 捕获/触发持久决策 阶段时间/检查总和（分布中的 P95） NOT_MEASURED
    吞吐量 每次在经过验证的生产线概况下完成产品决策 已完成的决定/已用时间 NOT_MEASURED
    上传延迟 中央持久收据的决策时间，按连接性分段 接收时间减去决策时间 NOT_MEASURED
    评论率 按决策/版本划分的手动审核率 审查检查/全面检查 NOT_MEASURED
    修正率 按决定/版本进行更正 更正的决定/审查的决定 NOT_MEASURED

    整体准确性本身并不能作为验收指标；该报告按产品、组件、模型和规则版本对结果进行细分，并披露覆盖范围差距以及阶段性缺陷与自然发生的缺陷（设计 26.7）。

    28.6 验收结果和变更控制¶

    结果镜像设计26.10：

    • 已接受： 执行的证据符合已定义域和发布的商定协议目标。
    • 有条件接受： 列出限制、补偿人工审核、过期/审核条件、所有者和所需的补救措施。人工审核可能不会仅仅因为日历周期过去而减少。
    • 拒绝/重新测试： 释放阻塞问题保留了运行；修复会创建新的候选版本并进行受控重新运行。历史故障不会被覆盖（设计 26.8）。

    接受是特定于版本和域的。任何重大的相机移动/角度变化、照明变化、产品/组件变化、条形码映射变化、规则/模型更新、推理运行时变化或材料硬件/吞吐量变化都会触发影响评估和比例重新验证（设计26.10）。接近 45 度的摄像机角度变化被视为有意义的领域变化，需要明确的模型测试、可能的新数据、需要时的微调以及完整的系统重新验证。重新验证在新的或更新的报告中记录触发因素、范围和结果。

    28.7 未解决的问题和需要验证¶

    • 基线评估后准确的客户接受阈值、置信度方法和不确定案例的规则。
    • 未见过的客户数据、自然发生的 NG 样本以及分阶段的缺失组件/手动场景的可用性和授权。
    • 硬件包络：边缘计算机、GPU/驱动程序、相机/SDK、触发器/PLC，以及允许的位置、焦点、曝光和照明范围。
    • 条形码标准和预期的不可读/未知代码处理。
    • 客户见证人、事实真相裁决者、签名者和重新测试责任。
    • 备份/恢复频率和客户同意的接受索赔的 RPO/RTO。
    • 长时间运行的测试持续时间、生产工作周期以及浸泡证据的预期停机持续时间。
