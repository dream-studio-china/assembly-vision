    ADR-014: Web Dev Test Harness (File-Based, Not Production Acquisition)¶

    1. Status¶

    已接受

    2. 背景¶

    在没有生产硬件的情况下在真实图像上测试检查管道 慢：开发人员必须将图像或视频复制到边缘主机，运行 CLI，然后 然后检查仪表板。浏览器已经有摄像头（包括手机 手机（通过操作系统相机 UI），因此面向开发人员的 Web 工具可以拍照， 上传图片，或上传短视频并获取检查结果 立即。

    这必须保留为 测试工具：边缘 API 在 M1 (ADR-012) 中是只读的， 生产实时采集使用原生app/RTSP/摄像头 来源（设计 07）。网络绝不能将连续视频流式传输到 管道，并且不应暗示新的生产摄入表面。

    3. Decision¶

    1. 默认情况下禁用 /api/v1/dev/ 下的门控开发端点，并且 返回 404 DEV_TOOLS_DISABLED 除非 serve 开头为 --enable-web-test。身份验证重用现有的查看器承载 令牌/会话（共享凭证，而不是每个参与者的授权，确切地说 如M1开发模式）。
    2. 仅基于文件的请求/响应：
    3. POST /api/v1/dev/inspect-frame：原始图像字节→实例 pipeline的单帧检查→返回InspectionRecord。写 默认情况下的证据包（因此结果显示在仪表板历史记录中） 除非persist=false。
    4. POST /api/v1/dev/inspect-video：原始视频字节（流式传输到 临时文件） → 使用共享 VideoFrameSource 解码 → 最多 检查 30 个采样帧而不保留 → 返回每帧 摘要 (VideoInspectResult)。没有视频被传输。
    5. 限制：图像≤ 20 MB；视频 < 100 MB 且分析帧数≤ 30 （step 采样）。这些限制了边缘主机上的 CPU 和磁盘成本。
    6. 前端：/dev 页面组开发人员工具（测试和日志选项卡；更多 工具可能会跟随）。 “测试”选项卡提供照片/图像/视频输入和绘图 产品边界框覆盖返回记录中的客户端。
    7. 边界：此线束不是生产获取路径。生产 检查停留在本机应用程序/RTSP/相机源上；网络开发人员 工具永远不会提供连续的流，并且永远不会在默认情况下启用 serve 运行。

    4. 后果¶

    4.1 正面¶

    • 通过任何浏览器进行快速、无硬件测试，包括移动照片/视频 通过操作系统摄像头 UI 捕获（无 getUserMedia 安全上下文依赖性）。
    • 结果在持久化时是可追踪的：图像测试写入出现的包 在仪表板历史记录中，并通过调节来获取。
    • 保留只读 M1 边界 (ADR-012)：端点 404，除非 开发人员明确启用它们。

    4.2 负面和权衡¶

    • 开发端点是突变（它们写入包/消耗 CPU），所以它们 决不能在生产主机上启用；该标志是开发人员选择加入的。
    • 视频分析按帧进行，且受 CPU 限制； 30帧上限防止失控 成本但限制了长视频测试。
    • 共享观看者令牌不是每个演员的授权；开发模式是 明确不是生产认证（与 ADR-012 一致）。

    5. 开放式问题和需要验证¶

    • 未来的开发工具（相机预览、配置/数据库检查）是否加入 相同的 /api/v1/dev/ 命名空间。
    • 是否支持生产级媒体上传（分段、可恢复、预签名） 曾经需要数据收集；如果是这样，它是一个单独的功能，而不是这个 马具。
