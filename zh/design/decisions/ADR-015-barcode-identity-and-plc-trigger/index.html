    ADR-015：条码标识和 PLC 触发关联¶

    1. 现状¶

    已接受

    2. 背景¶

    为期一个月的演示需要产品标识来做出检查决定，但是 客户没有固定的条形码前缀标准，也没有单一经过验证的 PLC 模型。 Design 07 将 PLC/光电眼边界排在第一位，条码事件排在第二位； 设计 04 需要条形码输出，包含原始值、符号系统、时间戳、来源、 质量/状态，以及版本化解析器。当前运行时只接受 仅开发 mock 触发并写入 BarcodeResult(NOT_REQUIRED)，因此 真实的流程永远无法满足条形码所需的规则。

    缺乏经过验证的 PLC 模型意味着 Modbus 适配器必须定义一个 PLC 必须满足的合同而不是猜测寄存器语义。缺席 固定条形码前缀意味着每个实例的产品分辨率必须准确 映射，切勿从条形码内容推断前缀或模式。

    3. 决定¶

    1. 条形码标识是一种选择加入、精确映射的边缘功能。 identity.barcode 配置启用视觉解码（ZXing-cpp） 捕获单帧和/或明确模拟的键盘输入 发展。配置的映射文件将完整的条形码值映射到 产品代码；禁止前缀/模式匹配。一个解析值 不可读、冲突、符号系统不受支持、未知或映射到 除活动规则产品类型之外的产品未经验证并记录 NG 启用身份收集时的结果。
    2. 规则引擎仍然是唯一的决策机构。 条码解析 只提供 product_identity_verified 和持久化的 barcode_result/product_resolution字段；它从不绕过规则并且 当规则没有经过验证、兼容的身份时，永远不会返回 OK 需要条形码。
    3. barcode_required 规则需要启用，需要身份配置 加载时间。 声明条形码所需规则的配置，无需 匹配的身份配置是ConfigError，因此配置错误 永远不能默默地允许未经验证的OK。
    4. 模拟键盘输入被明确标记为仅开发。 它是 仅通过 ADR-014 开发工具暴露，报告为 SIMULATED_KEYBOARD_INPUT，并且绝不能作为扫描仪硬件出现 可用性。
    5. PLC/光电眼触发器使用 FIFO/快照 Modbus 合约，通过以下方式禁用 默认值。 Modbus 适配器对 PLC 提供的 ENTRY/EXIT/ABORT 事件进行建模 递增序列、产品令牌、心跳和溢出状态读取 通过一致的快照。普通线圈轮询被拒绝，因为 无法证明瞬态光电眼脉冲未被遗漏。一场直播 传输需要经过现场验证的注册配置文件；适配器合约是 现已交付，集成仍受部署限制。
    6. 条形码身份通过临时检查被拒绝，直到窗口化 存在相关性。 时间窗口不能真实地保留单个 每帧读取的条形码结果，没有源时序和冲突 语义。初创公司拒绝该组合而不是发出误导性信息 NOT_REQUIRED证据。

    4. 后果¶

    4.1 正面¶

    • 需要条形码的规则现在具有真实的、经过验证的路径，而不是永久的路径 NOT_REQUIRED 死胡同。
    • 动态实例条形码与精确的每个实例映射配合使用，匹配 混合标准的客户要求。
    • 错误配置在加载时无法关闭（合同 03 §5）。
    • Modbus 合约是诚实的：没有占位符寄存器地址声明 支持未经验证的 PLC。

    4.2 负面和权衡¶

    • 必须为每个产品实例维护精确的映射；没有 基于条形码的产品类型推断。
    • 视觉解码取决于条形码质量、位置、运动模糊和 照明；必须在生产样品上进行验证。
    • 模拟键盘输入只是为了开发方便，而不是 生产获取路径。
    • Modbus TCP 实时集成在选定的 PLC 型号上仍然被阻止，并且 注册个人资料。

    5. 开放式问题和需要验证¶

    • 确认实际的符号系统、标签尺寸/位置和读取率目标 样品。
    • 选择 PLC 型号/寄存器映射并验证 ENTRY/EXIT 时序、FIFO 深度、 心跳节奏，并重新连接现场行为。
    • 决定仅条形码身份是否可以作为经过验证的生产边界 对于特定的生产线或仅保留工作台/开发。
