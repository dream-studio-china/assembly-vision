    21. 安全性和源代码分发¶

    21.1 目的和安全地位¶

    AssemblyVision 可以保护生产证据、配置完整性、凭证和管理操作，同时保留离线边缘检查。安全控制是基于风险的； Docker 和 Python 字节码都没有被表示为强大的源代码安全边界。

    21.1.1 范围区别¶

    • 静态训练和检查 MVP： 不需要身份验证，而训练和检查 CLI 仅在具有非生产数据的隔离开发环境中使用。训练代码、数据集、笔记本和实验配置仅供开发人员使用，不包含在运行时发行版中。模型加密和仅限 .pyc 的打包被推迟。
    • 一个月目标： 本地访问控制、中央身份验证、TLS、设备凭证、审核日志、非根容器和受控工件分发。
    • 生产目标： 实用的客户集成身份、基于角色的授权、证书生命周期管理、签名模型/配置包、漏洞管理、备份加密和事件响应。
    • 未来范围： 硬件支持的密钥、远程证明、更强大的本机编译/混淆或仅在合同威胁分析证明合理的情况下进行许可控制。

    21.2 资产和信托边界¶

    受保护的资产包括检查决策、图像和剪辑、条形码、产品配置、规则、模型包、凭证、审核日志、源/构建工件以及用户帐户中的个人信息。相机/边缘硬件、本地浏览器/边缘 API、边缘/中央网络、中央 API/工作线程、对象存储、管理员和构建/注册环境之间存在信任边界。

    客户对边缘硬件的控制意味着拥有足够特权的客户管理员可以检查容器、卷、内存和流量。该架构可防止随意浏览和未经授权的应用程序级访问；它不能保证抵抗有决心的特权逆向工程师。

    21.3 身份和授权¶

    中央用户通过客户身份联合（如果可用）或安全管理的本地身份提供商进行身份验证。在浏览器架构允许的情况下，会话使用短期令牌和安全的、仅限 HTTP 的 cookie。服务到服务和边缘到中心的访问使用唯一的每设备身份；凭据是可撤销的，并且不得跨设备共享。

    推荐角色有：

    角色 允许的行为
    操作员 查看当前状态、确认警报、启动授权重试/暂停/恢复
    审稿人 查看证据并记录审查结果
    产品工程师 产品和规则配置草案
    发布审批人 批准并部署已签名的规则/模型/应用程序版本
    网站管理员 管理设备和站点范围内的用户
    审计员 阅读检查、评论、发布历史记录和审核日志

    授权默认拒绝，并按组织/站点/线路/设备划分范围。在人员配备允许的情况下，起草和批准安全相关配置应分开。所有权限、配置、规则、模型、保留和审查更改均通过参与者、时间、旧/新值或校验和、原因和相关标识符进行审核。

    本地仪表板访问必须反映站点限制。仅环回信息亭可以减少暴露，但不能取代其他用户可以访问主机的身份验证。本地可紧急暂停；配置更改需要更强的授权。

    21.4 网络和API安全¶

    • 对边缘到中心和浏览器到中心的流量使用 TLS；验证主机名和信任链。
    • 首选仅出站边缘连接，因此工厂防火墙无需集中公开边缘 API。
    • 对每个上传进行身份验证并将其绑定到已注册的设备。
    • 应用请求大小限制、模式验证、速率限制和安全媒体内容处理。
    • 使用幂等密钥而不将其视为身份验证。
    • 将数据库、Redis 和对象存储接口保留在专用网络上。
    • 限制本​​地API监听地址和跨域策略。
    • 不要在客户端响应中放置机密、原始 SQL 错误、文件系统路径或堆栈跟踪。
    • 将上传的文件名和元数据视为不可信；在服务器端生成存储密钥。

    WebSocket 连接使用与 REST 相同的身份验证和授权规则，随会话一起过期，并携带状态通知而不是权威状态转换。

    21.5 数据保护¶

    检查证据可能会揭示产品标识符和工厂运营情况。收集最小化到配置的上传策略：OK 记录的代表性证据和 NG 或异常的更丰富的证据。保留是按媒体类别明确的。对图像、剪辑、条形码值和导出的访问都会被记录并限制在站点范围内。

    静态加密应在边缘使用平台或卷加密，并在集中使用数据库/对象存储加密。密钥所有权和备份密钥处理必须与客户达成一致。当不需要完整值时，日志必须避免凭据并编辑敏感条形码内容。浏览器缓存不得保留超出预期会话的敏感媒体。

    21.6 配置、模型和供应链完整性¶

    每个可部署的工件都有一个版本、加密校验和、兼容性元数据、出处和批准状态。签署生产包；边缘客户端在安装前验证校验和、签名、设备/产品兼容性、最低应用程序版本以及所需的规则/模型配对。激活发生在检查窗口之间，并保留最后的已知良好组。

    构建控制包括固定依赖项、审查的锁定文件更改、软件材料清单、容器和依赖项扫描、受限注册表发布、受保护的发布凭据和可重现的构建记录。模型和数据集作为受控工件进行处理：生产图像、训练数据、笔记本和实验凭证被排除在运行时图像之外。

    21.7 源分发方法¶

    客户收到可运行的边缘工件，而不是 Git 存储库。分配管道应：

    1. 在私有构建阶段构建 Python 轮子或应用程序树。
    2. 将项目 Python 模块编译为检查哈希 .pyc 文件。
    3. 删除导入和诊断仍然可靠的原始项目 .py 文件。
    4. 仅将运行时依赖项和工件复制到最终映像中。
    5. 构建 Vue 应用程序并仅部署生成的静态资产。
    6. 排除.git、测试、运行时不需要的文档、除非操作批准的源映射、训练数据集、模型训练代码、笔记本和内部实验配置。
    7. 在可行的情况下，在具有只读根文件系统的非 root 用户下运行。
    8. 将模型、规则、数据库、日志、媒体和临时文件以最小权限显式挂载。
    9. 在部署时注入短期或可轮换的秘密；永远不要将长期秘密烘焙到图像中。

    第三方 Python 源代码仍可能包含在依赖项打包中，并且必须遵循其许可证。许可通知和所需的归属必须保持可用。必须有意控制调试符号和前端源映射；删除它们会使支持变得更加困难，并且不会阻止客户行为的重建。

    21.8 源分发注意事项¶

    • .pyc 可以直接使用可用工具进行分析，并且不是强大的反逆向工程保护。
    • Docker 打包文件和进程，但不是针对主机管理员的源代码安全边界。
    • 构建的前端 JavaScript 必须传递到浏览器并可以进行检查。
    • 即使没有 Python 源代码，模型文件和规则定义也可以揭示系统行为。
    • 删除源可能会降低诊断质量，使回溯分析复杂化，并产生为某些第三方许可证提供相应源的义务。
    • 当授权机器在没有额外可信硬件的情况下主动执行代码时，图像加密无法保护代码。

    MVP 接受此级别是因为直接要求是避免直接随意的源浏览，而不是保证免受高级逆向工程的影响。如果没有具体的商业和运营要求，则不会故意引入许可服务器、激进的混淆、自定义加壳程序和硬件绑定激活。

    21.9 秘密管理¶

    秘密被分类、清点并分配所有者和轮换方法。本地机密应只能由服务帐户读取，并通过客户批准的操作系统机密存储、Docker 机密挂载或受保护的文件提供。仅当了解流程和支持工具暴露时，环境变量才是可接受的。前端构建时变量是公共的，绝不能包含秘密。

    轮换必须支持重叠，以便排队上传能够在凭证替换后幸存下来。撤销一台设备不得使其他设备失效。日志显示凭证标识符，而不是凭证值。

    21.10 安全操作¶

    21.10.1 疑似设备凭证泄露¶

    1. 集中撤销设备凭证并禁用其包/配置访问。
    2. 保留审核日志、上传收据和设备诊断。
    3. 如果安全，继续本地检查，但隔离出站同步，直到重新注册。
    4. 根据客户事件策略重新映像或检查边缘主机。 5、只有在主机信任恢复后才颁发新的唯一凭证；通过检查 ID 和校验和协调排队记录。

    21.10.2 未经授权的配置更改¶

    1. 停止进一步激活并保留当前证据和审计跟踪。
    2. 识别参与者、范围、旧/新校验和、受影响的设备和检查时间范围。
    3. 自动恢复最后批准的配置。
    4. 使用保留的模型/规则版本和证据重新审查可能受影响的检查。
    5. 在服务正常化之前更正权限或凭证暴露。

    21.10.3 易受攻击的运行时依赖项¶

    1. 确定部署的镜像中是否存在易受攻击的组件和代码路径。
    2. 在需要时应用补偿网络或功能控制。
    3. 从修补的固定依赖项重建、扫描、测试、签名和阶段部署。
    4. 保留发布来源并根据严重性和合同通知客户。

    21.11 验证¶

    安全验证包括授权矩阵测试、租户/站点隔离测试、设备吊销、畸形上传处理、依赖项/容器扫描、秘密扫描、包签名失败、回滚安全、审核日志完整性、备份恢复以及合同要求的广泛部署之前的外部渗透测试。

    21.12 未解决的问题和需要验证¶

    • 客户身份提供商、MFA 政策、帐户生命周期和角色分离可行性。
    • 边缘用户、物理访问控制、本地网络可达性和信息亭/浏览器模型。
    • 证书颁发机构、设备注册、撤销、轮换和离线续订流程。
    • 条形码、图像、视频、日志和导出的数据分类。
    • 边缘、中央和备份的静态加密要求和密钥所有权。
    • 所需的保留、合法保留、删除和审核日志保留期限。
    • 合同源交付、托管、开源许可、支持或混淆义务。
    • 所需的漏洞响应时间和批准的注册/扫描产品。
