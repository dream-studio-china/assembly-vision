    10. 时间聚合¶

    10.1 Purpose¶

    时间聚合器将 component detection 的帧级观察结果转换为 rule engine 的产品级证据。 YOLO 仍然处理单个帧。聚合通过组合观察结果来提高系统的鲁棒性；它不会提高模型的单帧精度。

    10.2 范围¶

    静态训练和检查 MVP 不包括时间聚合。生产目标在一个有限的实物产品窗口内汇总证据。未来的跟踪可能支持更复杂的重叠场景，但证据隔离仍然是强制性的。

    10.3 核心不变量¶

    1. 证据按 inspection_id、所需组件密钥和固定模型/配置版本进行分区。
    2. 各个所需组件独立聚合；禁止整体产品多数投票。
    3. 被拒绝的、陈旧的、重复的或错误的窗口框架不会做出贡献。
    4. 一个高置信度观察或多个中等置信度观察只能根据该组件的配置策略来建立存在。
    5. 不确定、矛盾或不充分的证据不能成为OK。
    6. 关闭窗口是最终决定；迟到的帧会被记录为丢弃，并且不会改变其决定。

    10.4 组件状态模型¶

    每个必需的组件均以以下证据状态之一结尾：

    状态 意义 规则引擎后果
    PRESENT 满足配置的积极证据政策 有资格满足该组件
    MISSING 存在足够的有效机会，但没有可接受的积极证据 NG
    UNCERTAIN 存在一些证据，但质量、一致性或数量不足 NG
    UNVERIFIABLE 管道/窗口无法提供有效的检查机会 NG

    即使外部业务接口仅公开 OK 和 NG，UNCERTAIN 和 UNVERIFIABLE 也会以诊断方式保留。

    10.6 默认策略¶

    实用的初始策略接受不同相邻有效帧中的一个高置信度观察或至少两个中等置信度观察。它还需要足够的有效检查机会和可选的可见性约束。

    def resolve(evidence, policy):
    valid = deduplicate(e for e in evidence if e.frame_quality.accepted)
    if len(valid.opportunities) < policy.minimum_valid_frames:
        return UNVERIFIABLE
    if any(e.confidence >= policy.high_confidence for e in valid.detections):
        return PRESENT
    medium = [e for e in valid.detections if e.confidence >= policy.medium_confidence]
    if has_adjacent_distinct_frames(medium, policy.max_frame_gap) and len(medium) >= policy.medium_hits:
        return PRESENT
    if medium or valid.low_confidence_detections:
        return UNCERTAIN
    return MISSING

    帧邻接使用捕获序列和最大经过时间限制。除非规则明确基于计数，否则一帧中的多个框将计为一次临时命中。

    10.7 Configuration¶

    temporal:
  window_strategy: identity   # identity (validated correlation) or time (dev fallback)
  minimum_valid_frames: 3
  maximum_window_ms: 2500
  reject_duplicate_frame_ids: true
  components:
    manual:
      high_confidence: 0.85
      medium_confidence: 0.65
      medium_hits: 2
      require_adjacent_hits: true
      max_frame_gap: 1
    component_a:
      high_confidence: 0.90
      medium_confidence: 0.70
      medium_hits: 2
      require_adjacent_hits: true
      max_frame_gap: 1

    策略按型号和产品类型进行版本控制和验证。配置的阈值必须遵循严格不等式的observation_threshold <= medium_confidence < high_confidence，并且启用的时间配置必须为每个规则所需的组件声明一个策略。 medium_confidence 以下的检测永远不会满足计数或空间规则。

    10.7.1 实施状态（ADR-010，产品窗口里程碑）¶

    每个组件的时间聚合器和边缘产品窗口管理器是 为实时摄像机路径实现。每个声明一个实例 其管道配置中的 temporal: 块运行一个产品窗口：frames 分组直到帧间间隙或配置的 maximum_window_ms 关闭窗口，聚合器解析每个组件的一个证据集 规则引擎只计算一次。因关机而关闭的窗口是 记录为中断 NG，未从未记录的日志中重建证据 记忆（10.8）。对于基于计数的规则，detection_count 是最大数量 在单个有效帧中观察到的实例数；实例跨帧分割 不满足没有共现的精确expected_count。

    审查修复强制执行的窗口分组、质量和策略行为 (PR-015 F1-F7)：

    • 捕获时间分组：窗口成员资格和持续时间使用帧的 获取单调时间戳（CapturedFrame.monotonic_ts_ns），从不 推理后处理时间，因此队列积压或推理缓慢无法 改变产品边界。无序时间戳被删除并计为 陈旧（10.8）。空闲到期后，管理器保留捕获时间 边界，因此排队的到期前帧无法重新打开最终产品 窗口。
    • 空闲到期：运行时将活动窗口最终确定为 GAP 空闲时间过去了，因此决定了流结束时的最终产品 通常，而不是等待稍后的帧或关闭（10.8）。
    • 窗口策略：window_strategy: identity需要经过验证 每帧产品标识（跟踪器、触发器或条形码关联）和 将每个窗口密封到一种产品。缺失的身份，窗口中的身份 过渡，或已确认的多产品框架（包括 ProductDetector MULTIPLE_PRODUCTS 结果）关闭窗口 完整性违规 (PRODUCT_IDENTITY_MISSING, PRODUCT_IDENTITY_TRANSITION, MULTIPLE_PRODUCTS) 永远无法释放 OK。 window_strategy: time 仍然是一个明确的开发后备方案；它 并不能证明相邻产品不能重叠，所以生产时间上 检查必须使用 identity 或其他经过验证的关联机制。 配置拒绝带有时间策略的inspection.enabled: true。
    • 最大持续时间：当身份密封窗口达到时 maximum_window_ms 当该身份保持连续时，它会关闭为 NG 与 WINDOW_MAX_DURATION_EXCEEDED。身份被隔离 无法开始另一个窗口，直到不同的经过验证的身份证明 产品转型。
    • 框架质量：产品检测质量门报告的框架 不可用不会造成任何检测，也没有有效的机会；它的质量 原因被保留为帧诊断。
    • 决定原因：每帧拒绝原因仅用于诊断，并且 不能否决一个其汇总证据满足所有规则的窗口。仅 窗口完整性违规（中断、身份混合、身份丢失、 规则评估失败）独立强制NG。
    • 故障关闭策略：启用的临时配置必须提供 对于每个规则所需的组件只有一个策略（在 规则加载）；缺失的策略防御性地解析为 UNVERIFIABLE COMPONENT_POLICY_MISSING。 medium_confidence 必须严格小于 high_confidence。
    • 策略身份：每个临时记录都保留完整的 SHA-256 aggregation_policy_version 中的规范政策文件。该文件 包括聚合格式、窗口策略、窗口参数等 每个组件阈值/命中规则，因此历史决策仍然存在 配置更改后可重现。
    • 计数证据：detection_count、方框区域和中心摘要包括 仅检测到等于或高于计数证据阈值（策略 medium_confidence 至少），因此低置信度误报不能 膨胀一个精确的 expected_count。

    10.8 窗口完整性和故障处理¶

    • 触发超时将窗口视为不完整而关闭；未解析的组件变为 UNVERIFIABLE。
    • 重复的帧 ID 将被忽略并进行计数。
    • 过时的无序捕获时间戳被忽略并计数；他们从不 改变窗口。
    • 空闲窗口在捕获时间后由运行时最终确定为 GAP 间隙过去了，无需等待后面的帧。
    • 身份密封窗口在丢失身份、中间窗口身份时中止 过渡或已确认的多产品框架；他们的框架从不混合 另一种产品的证据。
    • 超过maximum_window_ms的身份被关闭 WINDOW_MAX_DURATION_EXCEEDED 并被隔离，直到经过不同的验证 身份到达；它不能被分割成独立可释放的窗口。
    • 窗外的框架或检查 ID 不匹配的框架将与证据隔离。
    • 多个产品或身份切换使窗口无效，除非经过验证的跟踪器证明连续性。
    • Worker 重新启动会关闭恢复的打开窗口作为中断NG；它不会从部分记忆中重建证据，除非所有状态都被持久地记录下来。
    • 队列丢失或推理错误会减少有效机会，并且只能将证据移向UNCERTAIN或UNVERIFIABLE。
    • 默认情况下禁用早期OK最终确定，因为后面的帧可能会显示歧义；可选的提前完成需要生产验证，并且仍然必须满足每个组件的要求。

    10.9 持久性和可观察性¶

    保留帧机会、接受/拒绝状态、观察、重复数据删除决策、最终组件状态、阈值、命中帧 ID、置信度摘要和关闭原因。指标包括窗口打开/关闭/超时、帧混合尝试、每个组件状态计数、每个窗口的有效帧以及聚合延迟。

    10.10 验证¶

    • 表测试阈值相等、一次高命中、重复同一帧命中、相邻/不相邻中等命中、无命中以及仅低置信度证据。
    • 属性测试添加无效证据不能将组件更改为PRESENT。
    • 属性测试，证明组件 A 的证据不能改变组件 B。
    • 测试延迟帧、重复 ID、超时、重启、版本更改和混合检查 ID。
    • 重放记录的生产窗口并确定性地比较每个组件的结果。
    • 使用产品级 NG 召回和每个组件召回来验证策略，而不仅仅是帧级准确性。

    10.11 未解决的问题和需要验证¶

    • 选择权威的产品窗口机制并证明框架与产品的隔离。
    • 测量典型和最坏情况下的有效帧计数和帧间时序。
    • 校准特定于组件的高/中阈值和邻接要求。
    • 确定任何组件是否需要计数、可见性或空间一致性聚合。
    • 根据窗口持续时间和断电风险来确定持久的窗口中日志记录是否合理。
