    15.REST API 和事件¶

    15.1 契约原则¶

    AssemblyVision 公开独立的 /api/v1 边缘和中央 API。 REST 处理命令、持久资源、历史查询和重新连接快照。 WebSocket 承载低延迟瞬时通知；检查执行或持久同步不需要它。

    模式在 Data Model and Database 中定义。 UI 消费者在 Edge Dashboard 和 Central Admin Dashboard 中描述。

    所有 JSON 均使用 UTF-8、snake_case 字段、ISO 8601 UTC 时间戳、UUID 字符串和 application/problem+json 错误。问题响应包括type、title、status、detail、code、request_id和可选字段errors。

    15.2 常见行为¶

    15.2.1 认证和授权¶

    • Edge UI 请求源自本地管理网络。 MVP 可以使用本地操作员会话，但改变路由需要 operator 或 edge_admin；只读健康状况被故意限制。不要将 localhost 视为身份验证。
    • 设备到中心的调用使用相互验证的 TLS 或绑定到 device_id 的短期设备凭据。
    • 中央用户通过 OIDC 授权码和 PKCE 进行身份验证。 API 授权使用组织范围的角色：viewer、reviewer、config_manager、fleet_admin 和 org_admin。
    • 在发布短期下载 URL 之前检查媒体授权。

    15.2.2 幂等性和并发性¶

    PUT 和 DELETE 自然是幂等的。可重试的中央 POST 摄取请求需要 Idempotency-Key。服务器存储(device_id, key, request_hash, response)；相同的密钥/相同的散列重播结果，而相同的密钥/不同的散列返回409 IDEMPOTENCY_CONFLICT。管理更新将 If-Match 与 ETag/revision 结合使用，并在过时写入时返回 412 REVISION_MISMATCH。

    15.2.3 分页和过滤¶

    历史记录端点使用带有 limit （默认 50，最大 200）和不透明 cursor 的键集分页。响应为{items, next_cursor}。过滤器是显式查询参数；游标绑定标准化过滤器集，如果与不同的过滤器重用，则游标会被拒绝。小型配置列表可以使用相同的信封而不带光标。

    15.5 REST 和 WebSocket 边界¶

    REST 对于检查详细信息、队列状态、配置、命令、上传、审查和报告具有权威性。 WebSocket 传达某些内容发生了变化。重新连接的客户端总是刷新 REST 状态；它不能假设 WebSocket 流是完整的。

    频道 活动 传递语义 客户行动
    边缘 WS /api/v1/ws/runtime device.status_changed、inspection.started、inspection.updated、inspection.completed、upload.changed、alert.raised、alert.cleared 尽最大努力，按连接排序，有界缓冲区；缓慢的客户端断开连接 应用暂时预览更新；在序列间隙重新获取资源
    中环 WS /api/v1/ws/organization device.changed、inspection.received、review.changed、job.changed、configuration.assignment_changed 授权过滤后尽力而为； MVP 中没有持久的重播 无效/重新获取受影响的 REST 查询

    WebSocket 身份验证使用现有的安全会话 cookie 或通过 REST 获取的短期、单一用途票证。令牌不得出现在 URL 查询日志中。

    15.6 事件包络和演化¶

    {
  "event_id": "01989...",
  "type": "inspection.completed",
  "schema_version": 1,
  "occurred_at": "2026-08-04T10:12:31.442Z",
  "source_id": "01988...",
  "sequence": 1842,
  "correlation_id": "01989...",
  "data": {"inspection_id": "01989...", "business_result": "NG", "internal_decision": "UNCERTAIN"}
}

    事件有效负载故意较小。模式版本中允许添加字段；删除，意味着更改或类型更改需要新版本。事件使用者允许未知的附加有效负载字段，而请求主体保持严格。 sequence 与 (source_id, channel) 相比是单调的；客户端在间隙时重新获取 REST 状态。未知的事件类型将被忽略并记录。心跳 ping/pong 是传输级别的； DeviceStatus 快照仍然是 REST 资源。

    15.7 故障处理和限制¶

    • 返回 429 和 Retry-After 进行速率限制，并返回 503 和针对临时依赖失败的有限重试指导。
    • 限制请求主体、事件批次、媒体大小、过滤器范围和 WebSocket 消息/缓冲区大小。
    • 集中摄取202意味着接受异步验证，不完全持久，仅当响应明确包含接收状态时。正常检查元数据摄取应在 201 之前提交。
    • 切勿在没有幂等密钥的情况下自动重试非幂等调用。
    • 传播X-Request-ID；边缘上传尝试还携带检查和任务关联 ID。
    • 对大型媒体使用预签名对象上传；除非存储限制需要，否则不要通过 API Worker 代理视频。
