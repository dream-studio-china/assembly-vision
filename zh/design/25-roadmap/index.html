    25. 实施路线图¶

    25.1 目的和规划原则¶

    该路线图按技术依赖性和风险对 AssemblyVision 实施进行排序。日期是计划目标，而不是保证。相机/SDK 访问、生产数据、客户决策和硬件可用性可能会改变时间。质量证据优先于名义特征完成。

    25.2 范围边界¶

    • 静态训练和检查 MVP： X-AnyLabeling YOLO 通过产品/组件训练、静态两阶段检查、规则决策、可追踪输出和保留验证进行标签。
    • 一个月目标： 第一个适合受控客户现场评估的集成边缘和中央功能，而不是不受限制的生产自主权。
    • 生产目标： 强化离线操作、受控发布、安全性、可观察性、验收证据和支持准备情况。
    • 未来范围： Kubernetes集中、Tauri包装器、PLC/MES集成、先进的车队管理、自动化再训练和多角度优化。

    25.3 前提条件¶

    在实施之前，获取代表性静态图像、YOLO 格式的 X-AnyLabeling 产品和组件盒标签、草案产品/组件规则、类映射、允许的开发数据、文件名为 OK 或 NG 基本事实的单独保留固定装置集，并访问具有 16 GB 内存的开发人员 Apple Silicon Mac。地面实况、相机机械、网络/安全和验收的名称所有者。未知数被显式跟踪，而不是编码为默认值。

    25.4 静态训练和检查 MVP¶

    25.4.1 基础和数据集准备¶

    1. 使用 edge-service 建立一个根 uv 工作区，这是一个仅供开发人员使用的 training 发行版，并共享 domain 和 vision-core 包；推迟 TypeScript 工作区设置。
    2. 验证 X-AnyLabeling YOLO 导出布局、类顺序、图像/标签基本名称配对、标准化边界和泄漏安全训练/验证分组。
    3. 实现文件夹图像输入、确定性输出命名、模型清单生成以及针对图像错误、ROI 裁剪、坐标映射和序列化的重点测试。
    4. 在开发人员硬件上训练小型全框架产品检测器并记录模型元数据、类映射、工件校验和和训练配置。
    5. 为组件训练图像生成产品 ROI，裁剪它们，将组件框映射到 ROI 坐标，并验证往返和 ROI 外处理。

    25.4.2 训练、检查和验证¶

    1. 在准备好的 ROI 图像上训练组件检测器并生成版本化的校验和清单。
    2. 用真正的 Ultralytics 产品和组件适配器替换静态检测器存根；保留确定性的单产品选择、ROI 映射和故障原因代码。
    3. 定义列出所需组件的最小版本化产品规则，确定性地评估存在性，并生成 OK 或 NG 以及原因。
    4. 保存带注释的完整图像、带注释的有用 ROI、组件证据、模型/规则版本和 JSON 结果。
    5. 提供产品训练、组件数据集准备、组件训练的av-train命令；为一个图像/文件夹提供 assemblyvision inspect，为机器可读的保留报告提供 assemblyvision verify。
    6. 运行保留的静态夹具套件并报告 NG 召回、漏报、误报、每个组件的支持以及记录的限制。

    25.4.3 显式排除¶

    相机 SDK、实时视频、时间聚合、条形码实现、本地服务/仪表板、中央服务器、身份验证、生产部署、PLC/MES 集成、自动再训练、模型加密和仅限 .pyc 的运行时打包不属于此 MVP 的一部分。训练代码仅供开发人员使用，不包含在任何运行时分发中。

    25.4.4 退出证据¶

    训练和检查流程可从锁定的标记数据集重复；失败是明确的；全帧到 ROI 转换经过测试；输出标识数据集、模型和规则版本；并保留验证报告决策指标。这证明了静态的培训到检查流程，而不是生产精度、时间安排或操作准备情况。

    25.5 一个月受控集成演示器¶

    对于已经拥有相机、模型、数据和站点访问权限的小团队来说，这是一个多流目标 可用。这不是生产验收的承诺。范围有意限制为一个 产品系列、一台摄像头、一个窗口机制、一个条形码路径和一个中央摄取路径。

    25.5.1 第 1 周：检查核心和基线¶

    • 稳定标记的训练和检查基线：数据集验证、产品训练、ROI 组件数据集准备、组件训练、真实检测器适配器、确定性规则、模式、CLI 和保留验证。
    • 建立泄漏安全数据集清单、锁定回归集和可重现的模型清单。
    • 在开发者 Apple Silicon 硬件上进行配置文件训练和推理（如果有）。

    依赖性：代表性图像、初始产品/组件定义、候选模型。风险：NG示例和模型拟合不足。

    25.5.2 第 2 周：边缘获取和持续¶

    • 集成所选的相机适配器和触发器/窗口原型。的 FrameSource 抽象 (ADR-013) 首先附带模拟源 （文件夹、视频、OpenCV 本地/虚拟设备、RTSP、HTTP 图像） 采集路径的开发和测试无需相机硬件；供应商 SDK 适配器然后实现相同的协议。
    • 将条形码读取作为单独的功能和产品类型解决方案来实施。
    • 添加 SQLite 架构/迁移、原子媒体存储、恢复状态和保留保护措施。
    • 添加本地 FastAPI 和基本的 Vue 仪表板，用于摄像头、最新结果、运行状况和最近历史记录。
    • 添加最低限度的试点安全性：唯一的设备凭据、TLS、一个经过身份验证的管理员角色、 受保护的检查/媒体访问以及突变审核。

    依赖项：相机/SDK/硬件、条码样本/标准、运行环境。风险：驱动程序/容器兼容性、暴露、触发歧义。

    25.5.3 第 3 周：视频鲁棒性和同步¶

    • 实施产品窗口管理和帧质量过滤。
    • 添加每个组件的时间聚合和显式的模糊窗口处理。
    • 实现持久幂等上传队列、重试/退避、校验和和收据。
    • 添加一个中央摄取 API、PostgreSQL 模式、选定媒体存储、基本检查历史记录、 和一个最小的评论捕获视图。推迟通用产品/规则管理和分析。

    依赖性：稳定的相机时间戳/窗口信号、网络路径、身份方法。风险：混框、重复检查、队列压力。

    25.5.4 第 4 周：部署、弹性和站点评估¶

    • 构建非根多阶段 Docker 映像、Compose 配置文件、Nginx 配置、卷、运行状况检查和发布清单。
    • 测试关键试点子集：离线操作、重启恢复、重试/幂等性、重复 上传和受保护证据清理。保留完全断电、磁盘已满和浸泡矩阵 生产门。
    • 添加结构化日志、边缘运行状况、中央上传状态和有限审计跟踪。
    • 当访问和真实情况存在时，使用未见过的示例执行受控的客户现场基线 可用；这不是最终客户接受。
    • 提供试点路径所需的操作手册；在生产前扩展完整的操作手册集。

    依赖性：站点访问、客户网络/安全决策、验收案例和事实真相。风险：域转移晚和测试持续时间不足。

    25.6 一个月目标后的生产强化¶

    以下工作是由基线调查结果驱动的，而不是压缩到第一个月：

    1. 通过失败的产品/组件层扩展实际生产数据并重新验证模型。
    2. 与客户最终确定接受阈值和信心处理。
    3. 将试点身份验证扩展到完全基于角色的访问、需要时的外部身份、 凭证轮换、签名包、漏洞响应、备份和审计保留。
    4. 证明在生产等效硬件上的长期运行稳定性和恢复能力。
    5. 验证相机安装/曝光控制和变化检测程序。
    6. 建立发布环、回滚练习、支持所有权和质量监控。
    7. 只有在生产证据支持的情况下才减少人工审核。

    25.7 依赖性和关键路径¶

    Labeled static data and product rules
  -> dataset validation and baseline models
  -> static train-and-inspect pipeline
  -> camera/barcode integration
  -> product-window identity
  -> temporal aggregation
  -> durable local decision
  -> delayed synchronization
  -> site resilience tests
  -> independent customer acceptance
  -> controlled production rollout

    摄像头/窗口身份路径和代表性 NG 数据是主要的关键路径风险。中央仪表板可以并行进行，但无法弥补尚未解决的边缘决策完整性。

    25.8 交货门¶

    门 需要证据
    静态训练和检查完成 经过验证的 YOLO 标签、可重现的产品/组件工件、确定性夹具、原因代码、版本可追溯性、保留的验证报告
    边缘集成就绪 相机/条形码一致性、持久决策、重启恢复、健康状态
    联网试点就绪 幂等同步、中央历史记录/审查、离线测试、访问控制
    录取候选人 锁定的工件、看不见的客户数据集、完整的证据、操作手册
    生产推出 客户批准的目标/结果、回滚、监控、支持和安全准备

    没有门使用发明的准确性、延迟或可用性数字。在代表性基线测量和客户同意后添加数字标准。

    25.9 未来的选择¶

    • PLC/传送带传感器集成可增强窗口边界。
    • 用于产品识别和处置的 MES 集成。
    • 当浏览器信息亭管理不足时，Tauri 包装器。
    • 当服务规模证明操作复杂性合理时，进行中央 Kubernetes 部署。
    • 领域评估后的多角度或附加线模型自适应。
    • 手动数据集/发布治理成熟后，受控的再培训自动化。

    25.10 未解决的问题和需要验证¶

    • 相机供应商/SDK、边缘操作系统/GPU、硬件交付日期和容器访问方法。
    • 传送带速度、触发/窗口源、产品间距和预期的多产品行为。
    • 条码标准、扫描仪/解码器选择以及权威的产品映射源。
    • 产品类型、所需组件、样品可用性和真实所有权。
    • 客户站点/网络可用性、中心位置、安全审查和部署窗口。
    • 验收阈值设定研讨会、样品设计和允许上演的 NG 案例。
    • 团队规模/技能以及摄像头、前端、MLOps 和现场工作是否可以并行进行。
    • PLC/MES 要求以及它们是否改变第一个生产版本。
