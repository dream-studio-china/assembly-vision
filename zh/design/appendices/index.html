    AssemblyVision 架构附录¶

    1. 术语¶

    术语 规范意义
    装配视觉 完整的边缘客户端和中央服务器检查平台。
    实物产品 一件真实物品穿过检查区域；业务决策的单位。
    框架 来自相机或静态图像源的一张带有时间戳的图像。
    检查窗 归属于一个物理产品的一组有限的身份事件和框架。
    检验 一个物理产品窗口的可追溯的处理记录和决策。
    产品检测 对全框架进行第一阶段推理以定位/分类完整产品。
    产品投资回报率 从检测到的产品盒生成的裁剪，具有边距、剪裁和坐标映射。
    元件检测 对产品投资回报率进行第二阶段推断以查找配置的组件类。
    所需组件 版本化规则需要解析产品类型的组件。
    条码解码 使用解码器/SDK读取条码数据； YOLO 可以定位条形码区域，但不是解码器。
    产品类型解析 从条形码和其他批准的证据中确定性地选择产品配置。
    镜框品质 描述框架是否可用、模糊、剪裁、曝光不充分或其他无效的打印证据。
    时间聚合 为每个所需组件独立组合有效的帧级证据。它不会改变单帧模型的精度。
    规则引擎 版本化的确定性逻辑，将汇总的证据和产品需求转化为决策。
    内部决定 来自规则评估的 OK、NG 或 UNCERTAIN。
    经营成果 OK或NG；内部 UNCERTAIN 始终映射到 NG。
    假阴性 有缺陷或不完整的真实产品被错误地分类为 OK。
    假阳性/假NG 分类为NG的完整产品。
    不良召回 真正有缺陷/不完整的产品分类为NG的比例；主要验收指标。
    关键帧 保留/上传选定的框架作为代表性检查证据。
    带注释的图像 渲染检测/结果的派生图像；原始证据仍然可以单独识别。
    边缘客户端/设备 做出本地决策的工厂工业计算机和软件。
    中央服务器 非实时管理、摄取、历史记录、审查和报告系统。
    型号版本 模型工件和清单的不可变身份；产品和组件检测器是分开标识的。
    规则版本 确定性决策和聚合策略的不可变身份。
    产品配置版本 产品身份映射和所需组件集的不可变身份。
    上传任务 用于同步元数据或媒体的耐用边缘工作项。
    耐用收据 中央确认指定内容已被持续接受。
    审查结果 人工评估与原始自动化结果相关联，但不会取代原始自动化结果。
    验收数据集 客户生产数据排除在培训之外并用于商定的验证。

    2. 决策一致性检查表¶

    将此清单用于每个架构、API、模式、UI 和操作变更。强制 docs/contracts 下的工程合同强制执行最关键的 CI 和运行时中的这些规则；如果清单项目与合同冲突，则以合同为准 优先。

    • [ ] 生产关键决策在边缘仍然完全可执行。
    • [ ] 网络或中央故障无法将不完整的证据转化为OK或阻止其他健康的本地检查。
    • [ ] 业务输出仍为OK/NG；任何 UNCERTAIN 状态都是显式的和保守的。
    • [ ] 产品检测使用全帧并创建最终产品ROI；没有假设完美的产品定位。
    • [ ] 组件检测在生成的 ROI 上运行并检测当前所需的类，而不是抽象的全局缺失类。
    • [ ] 条码解码与 YOLO 检测/分类保持分离。
    • [ ] 时间聚合是根据所需的组件进行的，排除了不可用的证据，并且没有被描述为提高单帧精度。
    • [ ] 确定性规则引擎保持独立于模型实现。
    • [ ] 每个检查引脚不可变的产品检测器、组件检测器、规则和产品配置版本。
    • [ ] 身份、坐标空间、时间戳、证据谱系和原因代码保持可追溯。
    • [ ] 边缘记录/媒体/上传任务在重新启动后仍然有效，并保护待处理的证据免遭清理。
    • [ ] 同步至少一次，具有稳定的幂等性和内容/校验和冲突检测。
    • [ ] 服务器永远不会用审核结果覆盖原始边缘决策。
    • [ ] 确定上传保持选择性；默认情况下不集中发送所有帧。
    • [ ] 阈值、时间、保留、硬件、托管和验收声明已测量或标记为未解决。
    • [ ] 两天 MVP、一个月目标、生产目标和未来范围不混为一谈。
    • [ ] Docker Compose 对于边缘和初始中央部署来说仍然足够； Edge 不依赖 Kubernetes。
    • [ ] 可选的 Redis、代理、边缘 PostgreSQL、Kubernetes 和桌面包装在采用之前有具体的理由。
    • [ ] 源打包并不代表强大的逆向工程保护。
    • [ ] 训练数据、生产媒体/数据、笔记本、机密和运行时工件保留在 Git/客户端映像之外（如果适用）。
    • [ ]新的要求和决策有踪迹联系和客观验证证据。

    4. 原因代码术语表¶

    原因代码是稳定的机器可读标识符。一条记录可能包含多个代码； primary_reason_code 选择主要解释。消息文本已本地化/演示，不得替换代码。新代码需要架构文档、测试、严重性/默认映射和向后兼容的中央显示。

    由规则引擎实现的规范的机器可读代码集和 管道位于 packages/python/domain/src/assemblyvision_domain/reason_codes.py 并在 Rule Engine §11.5 中枚举。 下表是将这些代码映射到其对应的故障状态分类法 默认内部状态和操作响应；它是描述性的，而 Python 模块是可执行的事实来源 (AUDIT-001)。

    代码 意义 默认内部状态 典型动作
    OK_ALL_REQUIRED_PRESENT 使用有效证据，所有必需的组件都满足固定规则。 OK 记录并应用正常的 OK 上传策略
    NG_COMPONENT_MISSING 根据规则，所需组件具有足够的有效证据。 NG 审查组件证据
    UNCERTAIN_COMPONENT_LOW_CONFIDENCE 所需组件有证据低于其已验证的存在标准。 UNCERTAIN 商业NG；审查和评估阈值/模型
    UNCERTAIN_INSUFFICIENT_VALID_FRAMES 可用于聚合策略的可用帧太少。 UNCERTAIN 商业NG；检查采购/质量
    UNCERTAIN_PRODUCT_NOT_DETECTED 没有有效的产品检测支持 ROI 生成。 UNCERTAIN 商业NG；检查框架和产品型号
    UNCERTAIN_MULTIPLE_PRODUCTS 不止一种候选产品会使归因变得模糊。 UNCERTAIN 商业NG；检查窗口/间距
    NG_PRODUCT_IDENTITY_MISSING 到达时，框架没有产品标识，而身份密封的窗口却打开了。 NG 商业NG；检查跟踪器/触发器相关性
    NG_PRODUCT_IDENTITY_TRANSITION 密封到一种产品的窗户收到了具有不同产品标识的框架。 NG 商业NG；检查产品间距/过渡
    NG_WINDOW_MAX_DURATION_EXCEEDED 经过验证的身份在一个检查窗口中的保留时间超出了其最大持续时间。 NG 商业NG；在下一个产品之前检查触发/窗口时序
    NG_COMPONENT_POLICY_MISSING 时间聚合没有针对所需组件的经过验证的策略。 NG 商业NG；修复配置，保留之前版本
    UNCERTAIN_ROI_INVALID 产品 ROI 几何形状为空、过度剪切或以其他方式无效。 UNCERTAIN 商业NG；检查产品检测/投资回报率配置
    UNCERTAIN_BARCODE_NOT_READ 所需的条形码解码未产生可接受的值。 UNCERTAIN 商业NG；检查阅读器/图像
    UNCERTAIN_BARCODE_CONFLICT 多个身份观察发生冲突。 UNCERTAIN 商业NG；回顾身份事件
    UNCERTAIN_PRODUCT_TYPE_UNKNOWN 身份无法映射到已安装的产品配置。 UNCERTAIN 商业NG；正确的映射/包
    UNCERTAIN_FRAME_QUALITY 帧未通过模糊、曝光、可见度或其他经过验证的质量门。 UNCERTAIN 商业NG；检查环境/相机
    UNCERTAIN_WINDOW_TIMEOUT 在没有完整证据的情况下，检查窗口因超时而结束。 UNCERTAIN 商业NG；检查触发器/时序
    ERROR_CAMERA_UNAVAILABLE 相机已断开连接或无法提供有效帧。 故障 安全地停止决策路径；重新连接/修复
    ERROR_CAPTURE_FAILED 窗口内的帧获取失败。 错误或 UNCERTAIN 保留异常；恢复适配器
    ERROR_MODEL_LOAD_FAILED 所需的模型无法加载或通过运行状况检查。 故障 保留/恢复最后一个已知良好的包
    ERROR_MODEL_RULE_INCOMPATIBLE 活动模型类/清单与规则/配置不兼容。 故障 拒绝激活；回滚
    ERROR_INFERENCE_FAILED 所需的推理操作失败。 UNCERTAIN 或故障 商业NG；日志有界诊断
    ERROR_PERSISTENCE_FAILED 无法提交强制检查元数据。 故障 请勿举报不合理的OK；恢复存储
    ERROR_MEDIA_COMMIT_FAILED 强制证据媒体无法最终确定。 故障或UNCERTAIN 应用批准的最低证据政策
    ERROR_DISK_CRITICAL 可用空间越过关键水印或强制写入是不安全的。 故障 安全清理；操作员干预
    ERROR_CONFIGURATION_INVALID 安装或请求的配置未通过架构/不变检查。 故障 拒绝包裹；保留已知良好的版本
    INFO_NETWORK_OFFLINE 中央网络路径不可用，而本地检查仍然可行。 降级 缓冲上传并重试
    INFO_CENTRAL_UNAVAILABLE 中央端点不可用。 降级 继续本地检查并重试
    WARN_UPLOAD_RETRYING 暂时同步失败计划重试。 降级 观察队列年龄/尝试
    ERROR_UPLOAD_PERMANENT 上传验证/身份验证失败或超出批准的处理政策。 降级 操作员/支持解决方案；保留证据

    | ERROR_UPLOAD_CONFLICT | Central 检测到具有不同内容的相同身份/幂等密钥。 |降级|检疫任务及诚信调查| | WARN_CLOCK_DRIFT |设备挂钟的差异超出了经过验证的容差。 |降级|正确的时钟；使用接收/单调证据 | | CANCELLED_OPERATOR_REQUEST |授权操作员根据批准的政策取消了主动检查。 | UNCERTAIN |商业NG；审计主体及原因|

    捕获/媒体故障的故障与不确定行为取决于当前窗口内的恢复是否得到验证。它必须显式配置，并且永远不能默认为 OK。

    5. 可追溯性约定¶

    5.1 标识符命名空间¶

    前缀 神器 示例
    BR- 业务需求 BR-003
    EDGE- 边缘功能需求 EDGE-009
    CENTRAL- 中心功能需求 CENTRAL-001
    QA- 质量属性要求 QA-005
    OQ- 开放问题 OQ-016
    ADR- 架构决策记录 ADR-001
    TC- 测试案例 TC-EDGE-009-01
    EV- 评估/验收证据 EV-MODEL-2026-001

    ID 发布后绝不会重复使用。更改后的含义会收到新的 ID 或显式的取代链接。

    5.2 检验关联性¶

    使用全局唯一的不透明device_id和边缘生成的inspection_id。 frame_id、media_id 和 upload_task_id 是唯一的并引用检查。每个帧/证据项记录捕获序列/时间和坐标空间（FULL_FRAME、PRODUCT_ROI或派生空间）以及叠加所需的变换。

    在窗口启动时，固定并保留：

    • 产品检测器型号 ID/版本/校验和。
    • 组件检测器型号 ID/版本/校验和。
    • 规则 ID/版本。
    • 产品配置 ID/版本。
    • 聚合和帧质量策略版本（如果规则版本未完全包含）。
    • 应用程序/构建版本和相关适配器/配置版本。

    挂钟时间戳使用 RFC 3339 UTC。保留原始设备时间、单调序列/持续时间（如果可用）、时区/时钟运行状况元数据以及中央接收时间；永远不要默默地重写边缘时间戳。

    5.3 需求证据矩阵¶

    每个实施拉取请求或发布记录都应标识受影响的需求 ID。测试在元数据或文档字符串中命名需求，并发布证据将需求链接到代码/模块、测试用例、结果、环境、相关数据集版本以及批准角色。

    要求 设计业主 验证神器 公布证据
    BR-003 规则和失败语义 保守路径黄金测试 测试报告以及经过审查的异常样本
    EDGE-009 每个组件聚合器 单元/序列测试 按组件划分的评估报告
    EDGE-012 上传调度程序/摄取 重试、冲突、中断测试 弹性运行日志和收据
    CENTRAL-005 审查/审计领域 API 和并发测试 验收运行中的审计导出
    QA-005 储存/保留 磁盘水印/全面测试 恢复和无数据丢失报告

    该表是说明性的，不能替代完整生成的迹线矩阵。

    5.4 模型和数据集谱系¶

    模型清单链接工件校验和、架构/运行时要求、类映射、训练数据集版本、拆分策略、代码/配置修订、评估数据集、产品/组件指标、限制、批准和取代版本。数据集按批次、捕获会话/日期和物理产品进行分组，因此相邻帧不会在训练集和验证集上泄漏。

    起始数据目标是主要产品类别的大约 300-800 个真实图像以及每个组件类别的大约 300-500 个标记实例，包括实际的有意丢失的场景（在可行的情况下，最初每个丢失场景大约 100 个图像）。这些只是计划的开始，而不是保证；测量的验证决定额外的收集。

    5.5 回顾血统¶

    审核记录引用不可变的检查、原始业务/内部结果、选定的证据、审核者身份、审核结果、原因、时间戳和修订/并发令牌。更正的案例通过引用进入培训待办事项列表。数据集包含需要单独批准的标记操作；审核不会自动重新训练或重新标记历史模型指标。

    6. 范围-语言约定¶

    • 两天 MVP 指静态图像垂直切片，不包括相机/视频/中央/UI/身份验证/集成。
    • 一个月目标是指受硬件、数据和站点依赖性影响的实施目标；一个月后它不会自动投入生产。
    • 生产目标是指经过测量验证、验收、安全/操作强化和运行手册批准后所需的行为。
    • 未来表示可选范围，当前没有交付承诺。

    7. 开放式问题和需要验证¶

    尚未解决的权威决策列于Section 3中。文档所有者必须在那里添加新的未知数，链接受影响的需求/决策，在项目跟踪器中分配所有者和到期期限，并记录用于关闭它们的证据。结束一个悬而未决的问题可能需要更新原因代码默认值、图表、测试和验收证据；没有记录理由和验证的会议决定是不够的。
