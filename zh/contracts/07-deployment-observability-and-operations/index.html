    07. 部署、可观察性和操作¶

    1. 容器要求¶

    • 以非 root 用户身份运行。
    • 使用显式持久卷。
    • 定义健康检查。
    • 定义重启策略。
    • 使用结构化日志。
    • 不包含 Git 存储库。
    • 不包括训练数据集。
    • 不包括笔记本。
    • 不包含开发秘密。
    • 使用多阶段构建。
    • 将运行时数据保留在图像之外。

    2. 健康端点¶

    边缘应用程序应至少公开：

    /api/v1/health/live
/api/v1/health/ready
/api/v1/device/status

    定义：

    • /api/v1/health/live：进程处于活动状态；它没有暴露任何内部细节。
    • /api/v1/health/ready：决策关键配置、相机、模型和持久性许可 有效的检查。
    • /api/v1/device/status：经过身份验证的详细相机/模型/存储/上传运行状况，包括 单独的 inspection_ready 和 sync_ready 标志。

    示例：

    model unavailable:
/api/v1/health/live = healthy
/api/v1/health/ready = unhealthy

    3. 启动顺序¶

    1. Load configuration
2. Validate configuration
3. Initialize database
4. Validate storage directories
5. Load models
6. Initialize camera
7. Recover upload tasks
8. Enable inspection

    在准备检查通过之前，服务部门不得接受生产检查工作。

    4. 结构化日志记录¶

    {
  "event": "inspection_completed",
  "inspection_id": "...",
  "device_id": "...",
  "business_result": "NG",
  "internal_decision": "UNCERTAIN",
  "latency_ms": 134,
  "product_model_version": "product-v1.0.0",
  "component_model_version": "component-v1.2.0"
}

    5. 禁止日志内容¶

    不记录：

    • 密码
    • 代币
    • 授权标头
    • 数据库密码
    • 原始二进制图像有效负载
    • 敏感的客户数据

    6. 所需的运营指标¶

    • 每分钟检查次数
    • OK 和 NG 计数
    • 平均推理延迟
    • P95 推理延迟
    • 相机断开连接计数
    • 条码失败率
    • 投资回报失败率
    • 磁盘利用率
    • 上传队列长度
    • 最早等待上传的年龄
    • 模型加载状态
    • 数据库错误计数
    • 边缘到中心的连接状态

    7. 所需的操作手册¶

    维护操作手册：

    • 相机断线
    • 模型加载失败
    • 磁盘空间不足
    • 上传待办事项
    • 数据库恢复
    • 容器反复重启
    • 网络恢复后同步
    • 模型回滚
    • 规则回滚

    索引 Runbook 集位于 docs/runbooks 下。
